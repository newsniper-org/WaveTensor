# WT64v1 아키텍처 규범 — 재구현 기준 문서

**지위가 두 겹이고, 두 번째가 더 무겁다.**

1. **소개 자료** — 무엇을 만들고 있고, 어디까지 실측됐으며, 왜 프로토타이핑
   용량이 필요한가 (부록 A).
2. **RTL 전면 재구현의 기준** — 재구현팀이 원본 RTL 을 **보지 않고** 이 문서만으로
   동등한 구현을 만들 수 있어야 한다.

## 빌드

```sh
make -C ../.. guide             # → main.pdf (A4) + 렌더 검사 — 쪽수는 check_guide_render 가 낸다
typst watch  main.typ           # 집필 중 (끝나면 make guide 로 마감할 것)
```

> `make guide` 가 정규 진입점이다 — 컴파일 성공과 렌더링 정상은 다른
> 명제이기 때문이다. 부록 B.5 표가 73쪽으로 부풀어 있는 동안 raw
> `typst compile` 은 경고 0 으로 성공했고, 쪽수 보고도 반복됐지만
> *렌더링은 아무도 보지 않았다.* `scripts/check_guide_render.py` 가
> 한 글자 세로 흐름 쪽을 전수 검사한다.

요구: **Typst ≥ 0.14** (실측 0.14.2) · `Noto Serif/Sans/Sans Mono CJK KR`.

## 이 문서가 지키는 제약

| 제약 | 왜 | 검사 |
|---|---|---|
| **clean-room** — 내부 모듈명·신호명·파일/줄 참조·RTL 인용 배제 | 구현 표현이 섞이면 독립 구현 주장이 무너진다 | 아래 스캔 = **0건** |
| **금지 용어** — "마이크로코드"/"microcode" | 번역 계층이 아니다. 정본은 **step sequencer / step** | 금지 선언 자체를 빼면 **0건** |
| **출처 등급** — 실측/유도/목표/미측정 | "합성 도구 출력" 과 "실물 관측" 을 섞지 않기 위해 | 서문 §0.5 |
| **정의 우선** — 각 장은 자기 주제를 먼저 정의한다 | 재구현팀은 문맥을 공유하지 않는다 | 7장 전부 `#정의` 보유 |
| **실측 0건 고지** | 이 프로젝트에 실리콘·FPGA 실물 실측이 **한 건도 없다** | 서문 · 부록 A · 부록 B |

> **이 기록들은 고치지 않는다 — 줄을 더한다.** 위 세 줄의 수는 서로 다르고
> 그래야 맞다. 서지는 2026-08-27 에 45 였고 다음 날 46 이 됐다.
>
> 한동안 그렇지 않았다. 아래 게이트가 서지 수를 **날짜 박힌 이 기록 안에서**
> 요구하도록 지어져, 46 이 된 날 통과시키는 유일한 방법이 *2026-08-27 줄을
> 46 으로 고치는 것*이었고 그렇게 됐다 — **그날 재지 않은 값이 그날 잰
> 것으로 적혔다.** 그리고 서지가 늘 때마다 같은 위조를 다시 요구했을 것이다.
> 게이트가 정직을 강제하려다 정확히 반대를 강제한 것이며, 이 저장소가
> 「공허한 게이트」로 이름해 온 것의 거울상이다.
>
> ⇒ 지금 게이트의 앵커는 **현재 시제 주장에만** 있다 (문서 지도의 괄호와
> 아래 「남은 수」). 앵커가 날짜 박힌 문단 안으로 들어오면 lint 가 실패한다
> (R2) — 규율을 산문이 아니라 기계에 두었다.

> **쪽수는 이제 여기 적지 않는다.** 「75쪽」이 오래 남아 있었고, 그것을
> 「170쪽」으로 고친 그날 안에 **177쪽**이 됐다. 쪽수는 문서를 건드릴
> 때마다 바뀌므로 산문에 두면 *반드시* 거짓이 된다 — 알고 싶으면
> `typst compile main.typ && pdfinfo main.pdf` 로 재라.
>
> 남은 수(속성 43 · 서지 46)는 성격이 다르다. 그것들은 **기계가 대조한다** —
> `lint_guide_derived_tables.py` 가 속성 선언 수·부록 D 색인 수·`refs.yml`
> 항 수를 세고, **이 README 에 적힌 사본까지** 그 값과 대조해 어긋나면
> 실패한다. 즉 이 두 수는 *사본*이 아니라 *게이트가 지키는 값*이다.
>
> **그 문장이 한동안 거짓이었다.** 서지 수는 아무도 세지 않았고 실물이 46 이
> 되는 동안 README 는 두 곳에서 45 로 남았다 — 「기계가 대조한다」는 주장
> 자신이 대조 밖이었다. 갈래는 둘이었다: 쪽수처럼 *지우거나*, 주장을 참으로
> 만들거나. 후자를 골랐다 — 재구현자가 README 만 읽고 규모를 가늠하는 자리이고,
> 세는 일이 파일 하나 파싱이라 지울 이유가 없었기 때문이다. 세는 것이 기계에
> 없으면 적지 않는 편이 낫고, 적기로 했으면 세는 것을 기계에 넣는다.
