## 0. 확장의 형태 — 확정 요약

`C` 는 성격이 다른 두 뭉치다 — **분할은 확정됐다** (사용자 판정 2026-08-31.
§8 미결 1 닫힘). 아래 두 행은 이제 **각자의 전건과 각자의 승격 시점을**
갖는다: **`Cperm` 은 base 전건 0 · 결정 전건 0** 이고, **`Ccrypto` 는
전건 여덟**이다.

| 뭉치 | 확정 형태 | 신규 인코딩 |
|---|---|---|
| **Cperm** — PEXT/PDEP | PE 상주 이항 연산 **`0x057`·`0x058`** (§3) | opcode 2 |
| **Ccrypto** — AES·LEA·CRC·SHA-3 | **별도 다이(chiplet) + MMIO 페이지 2장** (CCTL 제어 · CSTRM 스트리밍) — 신규 opcode **0** (§2) | opcode 0 |

신규 EH **0** · 신규 dtype **0**. ISA 축의 헤드라인 「opcode 2 외 0」은
참이다 — 그러나 실계약 질량은 그것이 아니다: **페이지 2장(로스터 ≥17워드 +
창·크레딧) · base 전제 일곱(§5) · 결속·소거 프로토콜(§2.4) · 페이지
특권·사상 규범(§2.3 — 반드시 사야 하는 계약) · 신설 예약-오프셋 정책**이
이 확장의 실제 크기다 (§7 셈).

## 1. 인터페이스 갈래 판정 — 계획 §2.3 셋의 처분

1. **(a) `OPREF.src_kind=3` — 기각 (문면 사망).** 정본 §1.4.3 이 `src_kind
   ≥ 3` 을 예약으로 두고 「사용은 malformation, 판정은 디코드 경계」로
   처분한다 (`01-isa-asm.typ:797` — `src_kind` 표의 `[≥3]` 행).
   계획 배너가 이미 기록한 충돌 그대로다.
2. **(b) opcode 군 `0x060..0x06F` — 기각 (이중 사망).** ⑴ 문면: `0x060` =
   `SIMD_ADD_WIDE_SCALAR` 이고 그 범위의 빈칸은 `{0x066,0x067,0x06C–0x06F}`
   여섯뿐이다 (JSON 전수 실측). ⑵ 구조 — 이것이 본질이다: in-fabric opcode
   군은 다중 사이클 암호 상태를 파브릭 안에 두고, 그 **busy 관측 축**이
   SEC-4 (속성 — 격리, `05-security.typ:499-505`)의 관측면 넷
   (규범 「관측 가능한 출력은 열거한다」 `:377-397`, 열거는 `:385-391`) 에
   곧장 걸린다. **12b 확장으로 opcode 공간이 열려도 (b)는
   부활하지 않는다 — 죽인 것은 공간이 아니라 관측·격리 축이다.**
3. **(c) Hybrid → (c′) 확정.** 계획의 1차 권장 (c) 에서 **제어 opcode 를
   제거**한 순수 MMIO 형태다 — `0x060 CRYPTO_CTL` 은 문면 사망(위 ⑴)이지만
   그것은 손실이 아니다: 다이 상태 전이는 발화가 아니고, 발화의 유일한
   원천은 호스트 명령 큐다 (규범, `02-fabric-alu.typ:162-167` — 그 위에 선
   것 다섯 `:169-187`). 제어가 MMIO 인 것이 이 기계의 어법이다.

## 2. `Ccrypto` — 별도 다이 + 페이지 2장

분리 동기 5건(워크로드 격리 · trust boundary · SCA/fault 격리 · process
node 자유도 · 인증 부담 분리 — 계획 §2.1)은 전부 유지된다. 알고리즘 후보
(AES-128/192/256+GCM · LEA · CRC-32/32C · SHA3/SHAKE — 계획 §2.2)의 초판
집합은 미결 2 다.

### 2.1 다이행 판정 — 산술이 정한다

파도 캡처 상한 실측: `FRAG_MAX = 16` = **1,024b** (`0x07A` desc — "16-fragment
SINGLE wave (1,024b), FRAG_MAX=16 exactly consumed", 조각 64b).

- SHA-3: rate 1088b = **17조각** · Keccak 상태 1600b = **25조각** — 둘 다
  상한 밖. **현행 FRAG_MAX 실측에서 in-fabric SHA-3 는 죽는다.** 정확한
  문면 (검증 F6 수리): **단일 블록** SHA3-256(입력 17조각 · 출력 4조각)은
  캡처 확장 16→25 갈래가 열리면 파도 형태가 산다 — 그 갈래는 공짜가 아니고
  원장 7 이다. **다중 블록**은 발화 사이 상태(absorb state)라 캡처 폭과
  무관하게 영구 기각이다 (발화 원천 규범 — §1-3).
- AES: 블록 128b 는 파도에 들어가지만 라운드 키 스케줄·GCM 상태가 발화
  사이 상태다 — 다이행.
- ⇒ **암호 명령군 전체가 다이로 간다. in-fabric 갈래는 이 확장에 없다.**

> **두 다리의 지위를 갈라 적는다 (2026-08-30).** 이 판정은 두 다리로 서는데
> **둘 다 base authority 가 없다.**
>
> 1. **`FRAG_MAX = 16` 은 계약이 아니다.** 그 수는 `0x07A` desc(이관 전 계보
>    산출물)에만 살고 재구현 트리 전량에 `FRAG_MAX` 는 **0건**이다. base 는
>    폭을 **명시로 미룬다** — E.10 4항이 「구체 비트 폭은 이 문서가 정하지
>    않는다」로 적고 하한 8b 만 준다. 즉 **재구현이 25 를 고르는 것이 오늘
>    적법하다.** ⇒ 단일 블록 SHA-3 의 사망은 *계약이 아니라 오늘의 형상*이다
>    (원장 7 이 그렇게 적는다 — 정직하다).
> 2. **다중 블록의 「영구」 기각은 *관행* 위에 서 있다.** 「발화 사이 상태
>    금지」는 정본 규범이 아니다 — §5 전제 8. 관행은 영구 기각을 지탱하지
>    못한다.
>
> ⇒ **다이행 판정 자체는 §2 머리의 분리 동기 다섯**(워크로드 격리 · trust
> boundary · SCA/fault 격리 · process node 자유도 · 인증 부담 분리) **위로
> 옮겨 세울 것을 권고한다** — 그 다섯은 이 확장 자신의 근거라 base 착지를
> 기다리지 않는다.

### 2.2 페이지 2장 — 표면 로스터

MMIO 페이지 규율은 E.1 의 4규칙 (`appendix/e-defined.typ:128-144` — 특히
규칙 2 `:135-137`)을 승계하고, 미배정 오프셋은 「예약 — 쓰기 거절 + loud」
로 신설한다 (§5.7 「예약된 필드는 반드시 0」의 페이지 판).

> **대면 미이행 (2026-08-30 적발).** base 는 **오프셋 축에 정반대 정책**을
> 명시로 세워 두었다 — §3.7 규범 「예약 정책」이 「표에 없는 오프셋은
> *예약*이다 — 쓰기는 무시하고 읽기는 0을 반환한다」로 적고, 그 관대함의
> 근거를 「이 정책 덕분에 레지스터 추가는 하위 호환 형태가 된다」로 든다.
> 곁 함정이 축까지 못박는다 — 「「예약」은 이 문서에서 정반대의 두 정책을
> 이름한다」: **오프셋은 관대(하위 호환), 필드는 엄격(은닉 채널 차단)**.
> 이 절은 **필드 정책(§5.7)을 오프셋 축으로 이식**하면서 base 의 관대 근거를
> 명시로 기각하지 않았다 — base 가 경고한 바로 그 혼동형이다.
>
> **결론은 바꾸지 않아도 된다** — 암호 페이지에서 엄격이 옳다는 논증은 설 수
> 있다(키·논스 워드에 인접한 미배정 오프셋 기입은 하위 호환 이득보다 오적재
> 위험이 크다). 그러나 **대면 문단 없이는 「모르고 어긴 것」으로 읽힌다.**
> 그 문단은 §5 전제 3(페이지 층위의 예약 정책)의 입력이다. base 함정이 요구한
> 「오프셋인가 필드인가」 병기는 이 절이 이미 충족한다 — 「오프셋」이라 적었다.

| 페이지 | 워드 (작업명) | 역할 |
|---|---|---|
| **CCTL** (제어) | `CBIND` · `CABORT` · `CSCRUB` · `CSTATUS` · `CALG` · `CKEY[0..7]` (256b) · **`CNONCE[0..k]` — 폭 미정 (원장 9)** · 세션 식별 | 결속·중단·소거·상태·키/논스 적재 |
| **CSTRM** (스트리밍) | `DIN` 창 · `DOUT` 창 · 점유/크레딧 워드 | 데이터 이동 — 본체 파브릭을 지나지 않는다 |

- 동사 선례: `MASK_REKEY`(`e-defined.typ:344-345`) · `FP_BIND`(`:434-435`)
  · `ABORT_FIRE`(`:421-422`) — 기입 동사·완료 관측·「한 워드씩」 규율
  (`:1177`) 전부 승계. 파티션 필드 검증의 loud 거절 선례는 `:351-368`.
- **CNONCE 폭은 단수 워드로 적지 않는다** (검증 F7) — GCM 96b = 3워드 ·
  XChaCha 형 192b = 6워드로 알고리즘 집합(미결 2)에 걸려 있다.
- **기존 `0xE80` 마스크 키·논스 구역 재사용은 기각이다** — §6 기각 대안.

### 2.3 규범 — 페이지 특권·사상 (검증 F1 수리, 신설 계약)

이 절이 없으면 (b)를 죽인 바로 그 축(busy 관측)이 (c′) 자신의 `CSTATUS`
에서 재현된다 — 배타 결속은 **사용** 축만 닫고 **관측·제어** 축은 페이지
사상 규범이 닫는다.

1. **CCTL 은 호스트(신뢰 경계) 전용이다.** 테넌트 파티션에 사상되지
   않는다 — `CBIND`/`CABORT`/`CSCRUB` 의 기입 권한이 미명시면 문면상
   테넌트가 남의 세션을 중단·재결속할 수 있다.
2. **CSTRM 은 결속된 파티션에만 사상된다** (또는 호스트 중개). 비결속
   파티션의 접근 = **거절 + loud**.
3. **`CSTATUS.busy` 는 SEC-4 관측면의 「상태 표면」이다**
   (`05-security.typ:464-465`) — SEC-4 는 네 부류 전부에 걸므로 (`:500`)
   비결속 파티션에 **비가시**여야 한다. 반례 기록: 파티션 B 가 A 결속 중
   busy 를 폴링하면 A 의 암호 활동이 타이밍으로 샌다.
4. 관측면의 **전수 열거**는 다이 재구현 몫으로 남는다 — 그러나 페이지
   사상은 명세 몫이고, 그것이 이 절이다.

### 2.4 규범 — 결속·소거 프로토콜

- **결속은 배타다**: 한 시점에 한 파티션(또는 호스트 세션)만 `CBIND` 로
  결속된다. 재결속 전이의 **전건 = `CSCRUB` 완주**.
- **`CSCRUB` 의 소거 정의역** (검증 F2 수리): 키·세션 상태 **+ CSTRM
  DIN/DOUT 창 · 내부 FIFO · 점유/크레딧 워드 전부**. 좁은 정의역(키·세션
  상태만)은 반례가 실재한다 — A 세션 종료 후 B 재결속 시 B 가 A 의
  암문/평문 잔여를 DOUT 창에서 읽는다 (값 관측면 직격).
- 소거 완주는 `CSTATUS` 로 관측 가능해야 한다 (loud-fault 어법 승계).

### 2.5 규범 — 드레인과 다이 (검증 F3 수리)

base 3.7 드레인 정의역 여섯 항 + E.11 (`e-defined.typ:1546-1560`)은
fabric/HIU 점유만 센다 — **crypto 다이 세션은 어느 항에도 들지 않는다.**
따라서:

> **`DRAIN_ALLZERO = 1` 은 다이의 비행 없음을 증거하지 않는다.** 다이
> 세션의 정지 증거는 `CSTATUS`(비행 0 · 크레딧 원상)이고, 재키잉·리셋·이주
> 전에 그것을 확인하는 것은 **호스트 ABI 의무다.**

base 가 드레인 정의역에 다이를 편입하는 개정 갈래는 전제 7 (§5)로 남긴다 —
어느 쪽이든 문면 없이 두는 갈래는 없다 (믿고 자르는 호스트가 반례다).

### 2.6 엔트로피 원천 — 결정하지 않았다 (검증 F4 수리 · 미결 8)

다이의 마스킹 난수 원천은 **미결이다**:

| 갈래 | 사는 것 | 대가 |
|---|---|---|
| (i) 본체 TRNG 사이드밴드 | 엔트로피 설비 단일화 — 본체 4단계 파이프라인 (§5.4 규범 「네 단계」, `05-security.typ:328-335`) 재사용, 사이드밴드 대응 계약 선례 (`e-defined.typ:1441-1443`) | **전제 5 (chiplet 엔트로피 채널 신설)** + 인증 경계가 본체 TRNG 4단계 전체를 문다 — 분리 동기 5(인증 격리)의 부분 자해 |
| (ii) 다이 자체 TRNG | 전제 5 소멸 · 인증 격리 동기와 정합 | SEC-5 루프 승인·건강성 검사(`:221`)의 다이 판 이중화 |

어느 쪽도 재지 않았다 — 면적·인증 표면 실측이 결정의 전건이다 (원장 8).

### 2.7 conformance 표면 — **두 항으로 가른다 (2026-08-30)**

종전 문면은 성질이 다른 둘을 한 항에 담았다. 정본 B.5 「conformance 표면의
거처」 행이 그 둘을 명시로 갈랐으므로 이 절도 가른다 — **하나는 승격 가능,
하나는 미결이다.**

**⑴ fault 표면 — 승격 가능.** 이 확장의 *fault* 표면에 대해 `FAULT_STATUS[31:20]`
의 새 비트 승격 갈래 (`[19]` 는 3.10 v1.0 묶음이 비소유 프레임 접근에 배정했다 — 2026-10-09). `[31:20]` 은 RO 예약 = 0 (`e-defined.typ:526`)
· sticky 선례 `[17]` (`:522`) · 발화 우선 선례 `0xF84`(`:497`). 좌표·
근거 모두 유효 — **base 미결을 기다리지 않는다.**

**⑵ conformance 로스터 — 거처 미결.** sub-conformance flag 로스터는 계획 §4
를 승계한다 (`WT64v1-C/AES-128` · `/LEA-128` · `/SHA3-256` · `/CRC32C` ·
`/PEXT-PDEP`). 거처는 B.5 행이 진다 (*미결 — 정본 자답 가능*).

- **`FAULT_STATUS` 는 이 항의 후보에서 빠진다.** 정본이 근거를 적었다 —
  conformance 는 오류가 아니고, E.1.2 가 능력 부재를 `0xF8C` 로 따로 뽑은
  근거(오류가 아닌 것을 오류 비트맵에 접지 않는다)가 그대로 걸린다.
- 자연스러운 거처 후보는 `0xF8C CAP_STATUS` 계열도 아니다 — 능력 부재는
  sticky 재시도 축이고 conformance 는 *정적 선언* 축이라 성질이 또 다르다.
- **여기서 자리를 고르지 않는다.** B.5 행이 「이 행이 자리를 고르지는
  않는다」고 스스로 적었고 그 선을 앞지르지 않는다.

## 3. `Cperm` — PEXT / PDEP

| 항목 | 확정 |
|---|---|
| opcode | **`0x057` PEXT · `0x058` PDEP** (계획 §3.4 자리 승계, 12b 표기) |
| 의미 | PEXT: mask 1-비트 자리의 값을 하위로 압축 · PDEP: 하위 비트를 mask 1-비트 자리에 분산 (계획 §3.1) |
| legality | **`0x014 AND` 미러** (실측): `{required:[port], forbidden:[mem,subscript], allow_imm_xor_opref:true}` + `rtl_alu_binary` — **B(마스크) = IMM64 XOR OPREF** |
| EH 사슬 최악 | BH(1) + CH(1) + PORT(1) + IMM64(3) = **6워드 · EH 2슬롯** — 상한 4슬롯 / 14워드 안. 환산의 authority 는 `01-isa-asm.typ:320-334` 「사슬의 워드 수는 기본 헤더 1워드」 규범이다 (2026-08-30 재조준 — 종전에는 「최대 길이」 규범을 가리켰다). 이 문서는 **CH 를 포함해 센 쪽**이라 그 환산과 정합한다. 실측: 같은 형상의 `bh_len` = 6 · EH 2개 |
| 출력 | 64b 단일 beat — **ISA-9 ②** (규범 「토큰 비증식」, `:617-631`) |
| 구현 | PE 내부 barrel 네트워크 **6단 = log₂64** — 상수 시간, §5.3 동일 상태열 무충돌 |

- **truth table 비대칭 (실측)**: 근거 표는 **`truth_table_encwave.json`**
  이다 — domain_version 4 · 5,934 벡터 · 도메인 69 opcode 균등(각 86점) ·
  키 표기 `0x0##` 3자리. **`0x057` 은 미배정인 채 86 벡터가 캡처돼 있고
  `0x058`·`0x059` 는 0건이다** (재캡처본에서 재확인). ⇒ `0x057` claim 은
  **differential recapture 를 강제**하고 (pre-stable 정규 이벤트), `0x058`
  은 공짜다. 이 비대칭을 모르면 재캡처 누락이 조용히 통과한다.
  - ⚠️ **재캡처 대상은 `encwave` 이지 `premigration` 이 아니다.** 후자는
    인코딩 개정 파도 이후 「이관 전 계보 전용 블랙박스 오라클」로 좁아진
    **동결** 산출물이다 (그 항의 2자리 표기 `0x00`–`0x6F` 도 동결의 일부 —
    지위 배너의 예외 하나). 동결 표를 재캡처하려 드는 커밋은 상주
    동결 단언에서 즉사한다.
- **비용 산정은 계약이 아니다** (원장 3): 계획 §3.3 의 산정은 **자체 산술
  모순을 품고 있다** — 「PE당 +1000 LUT · Pod 16-PE → 32K」인데 500×2×16 =
  **16K ≠ 32K**, 2배 어긋난다 (검증 적발). 재실측 사유에 이 모순이 든다.
  도입 트리거(워크로드 프로파일 — 계획 §3.5)는 미결 6.
- **Cperm 의 base 전건은 이제 0 이다** (2026-08-30 재확인 — 종전 문면은
  「12b 파도 반영뿐」이었고 **그 하나가 착지했다**). 전제 1·2 가 둘 다
  `01-isa-asm.typ:190-203` 규범 「opcode 는 12비트다 — 개정됨」으로 섰다:
  12b 값 공간 + 「*미배정 opcode 는 malformation 이다.*」. 페이지·엔트로피·
  드레인 전제는 전부 Ccrypto 몫이다 — **분할(미결 1)의 실측 근거가
  「1 대 6」에서 「0 대 7」로 벌어졌고, 그 분할이 2026-08-31 확정됐다.**

### 영역 선택의 근거 (2026-08-30 신설 — base §1.3.1 이 요구한 것)

base §1.3.1 규범 「영역 구획 — 배정 절차의 규범이다」가 배정마다 영역 선택의
근거를 요구한다 — `01-isa-asm.typ:218-225` 「그 영역에 자리가 남았다」는
근거가 아니다. 이 문서는 「계획 §3.4 자리 승계」라고만 적었으므로 여기서
이행한다. **`0x0##`(기존 계보 — base 와 그 파생 확장) 에서 받는다.**

- **근거**: PEXT/PDEP 는 **PE 상주 이항 논리 연산**이고 legality 가
  `0x014 AND` 를 축자 미러한다(위 표) — 「기존 계보의 확대」의 정의에 곧장
  든다. 대조로 `-ctrl.md` 가 `0x4##` 를 고른 것은 그 확장이 *발화 제어* 축이라
  계보가 다르기 때문이다.
- **재검토 조건을 함께 적는다**: 판별 기준 자체는 base 미결이다
  (`b-gaps.typ:1846-1867` 「opcode 영역의 판별 기준」). 그 행이 이 문서 §3 의
  실측을 **대가의 증거로** 인용한다 — 이미 캡처된 코드점을 claim 하면 재캡처가
  강제되고 인접한 빈 자리는 공짜라, 영역이 아니라 *캡처 상태*가 배정을
  끌어당긴다. ⇒ **기준이 닫히면 이 근거는 재검토된다.** 기준 없이 세운 근거를
  기준인 척 두지 않는다.

## 5. 전제 — base 개정 (일곱 → **재편: `Cperm` 0 · `Ccrypto` 여덟**)

> **전수 재확인 (2026-08-30).** 정본 환류가 이 일곱을 전수 감사했고 성질이
> 바뀌었다. **둘은 착지했고, 하나는 「이미 있는 답을 다시 산다」로 판정됐고,
> 하나는 사정권 절반이 다른 축이었고, 하나는 「선행」이 아니라 「동반」이고,
> 그리고 여덟째가 새로 생겼다.** 전건은 **`Cperm` 0 · `Ccrypto` 여덟**으로
> 갈린다 — 미결 1(분할)의 실측 근거가 이 표이고, **그 분할은 2026-08-31
> 사용자 확정으로 닫혔다** (§8).

1. **opcode 12b 확장 파도 반영** — **착지 완료.** base §1.3.1 규범 「opcode
   는 12비트다 — 개정됨」. `0x057` 재캡처는 실장 몫으로 남는다 (원장 10).
2. **미지 opcode 전역 malformation 규범** — **착지 완료.** 같은 규범이
   `01-isa-asm.typ:190-203` 「미배정 opcode 는 malformation 이다」로 적고,
   근거까지 이 문서가 청한 대로다 — 「미지 EH 종류의 처분(1.3.2)과 같은
   결이다 — 능력 부재가 아니다」. 검증 수리로 갈아끼운 근거를 base 가 축자로
   받았다.
   > ⇒ **1·2 의 착지로 `Cperm` 의 base 전건이 0 이 됐다** (§3).
3. **~~페이지 배정 절차~~ → 재정의: 페이지 *층위*의 배정 절차 — 재정의가
   사용자 확정됐다 (2026-08-31).** 종전 청구
   (「신설 MMIO 페이지가 E.1 4규칙을 승계함을 base 가 문면화」)는 **이미 있는
   답을 다시 산다** — E.1.1 규범 둘째 문장이 승계를 이미 못박는다
   (`e-defined.typ:129-130` 「확장은 표를 흉내 내는 것이 아니라 아래 넷을 다시 적용해서 만든다」).
   정본이 B.5 「페이지 *층위*의 배정 절차 — E.1 의 네 규칙은 한 페이지 *안*을
   정한다」 행으로 **일곱 항 어디에도 없던 것**을 따로 이름했다: **페이지
   층위의 예약 정책**(§2.2 신설분) · **새 페이지를 언제 여는가** · **페이지끼리의
   배치**. ⇒ 이 항을 그 셋으로 갈아 적는다. (종전의 좌표 `b-gaps.typ:1335` 는
   낡았다 — 「확장 절차의 거처」 행은 오늘 `b-gaps.typ:1645-1691` 이고 1335 는
   「재조립 문맥 풀 고갈」 행 안이다. 인용 규약대로 **행 이름을 authority 로**
   적는다.)
4. **conformance 표면의 거처** — **B.5 행으로 등재됐고 거처는 미결이다**
   (「conformance 표면의 거처」, *미결 — 정본 자답 가능*). **그 행이 §2.7 을
   둘로 갈랐다**: fault 표면과 로스터는 성질이 다르고, **로스터에서
   `FAULT_STATUS` 는 후보에서 빠진다** — conformance 는 오류가 아니므로 오류
   비트맵에 접지 않는다(E.1.2 가 능력 부재를 `0xF8C` 로 따로 뽑은 근거가 그대로
   걸린다). ⇒ §2.7 의 두 항 중 fault 표면 쪽만 이 전제를 안 기다린다.
5. **chiplet 엔트로피 채널 신설** — **표가 받지 않았다.** 미결 8 의 (i)
   갈래에서만 서는 조건부라 「전건이 정해지기 전에는 받을 것이 없다」. (ii)
   채택 시 소멸한다 — 종전 서술 그대로 유효.
6. **SEC-4 정합 절 — 사정권을 좁힌다.** 유지분 = 「§5.8 관측면 넷의 *상태
   표면* 부류가 확장 다이의 표면을 덮는다」 한 문장. 이것은 **다섯째 부류
   신설이 아니라 넷째 부류의 해석 확장**이라 값이 싸다 (§5.8 은 「부류는 이
   넷으로 *닫힌다*」를 적고 다섯째 추가에 정본 개정을 요구한다). **이관분** =
   「새 페이지의 특권·사상을 누가 정하는가」 → **전제 3 으로 보낸다.** 두
   청구가 한 항에 살면 싼 쪽이 통과하면서 비싼 쪽이 함께 통과한 것처럼 읽힌다.
7. **드레인 정의역과 다이의 관계 — 「선행 개정」이 아니라 「동반 착지」다.**
   B.5 가 이 행을 **[*조건부* — 정의역 밖 실행 주체를 두는 확장의 도입이
   전건]** 으로 등재했고 **그 전건이 바로 이 확장의 도입**이다. 지금 문면을
   넣으면 대상 없는 규범이 되고, 이 확장 없이 두면 첫 도입에서 아무도 묻지
   않는다. ⇒ **일곱 항 중 유일하게 이 성질이다.** base 쪽 편집은 한 문단이면
   족하다 — 여섯 항은 fabric/HIU 점유만 세고, 정의역 밖 실행 주체를 두는
   확장은 자기 정지 증거를 자기 표면에 두고 확인을 호스트 ABI 의무로 돌린다.
   (검증 F3 — 이 항이 없으면 `DRAIN_ALLZERO` 를 믿는 호스트가 세션을 자른다.)
8. **🆕 「발화 사이 상태 금지」의 규범 승격 — 가장 무거운 전건.** 정본이 B.5
   「「발화 사이 상태 금지」 — 이름 없이 쓰이는 어법」 행을 세우며 축자로
   판정했다: 정본 전량에 「아키텍처 상태」도 「발화 사이」도 **0건**이고, 가장
   가까운 문면인 §2.3 「발화의 유일한 원천은 호스트 명령 큐다」로는 **유도되지
   않는다** — 원천이 호스트뿐이어도 발화 A 가 세우고 발화 B 가 읽는 상태는 서
   있을 수 있다. 확장이 인용하는 것은 규범의 귀결이 아니라 **이름 없는
   관행**이며, 그 행이 **이 문서 §2.1 을 영구 기각의 사례로 직접 지목한다.**
   - **이 확장의 구조 결정 *둘*이 여기 매달렸다** — 다중 블록 해시의 **영구**
     기각과 AES 전체의 다이행. **관행은 영구 기각을 지탱하지 못한다.**
   - 갈래 둘: ⓐ 어법을 §2.3 곁에 규범으로 승격 ⓑ 승격하지 않고 「관행이지
     계약이 아니다」를 명기. **ⓑ 가 채택되면 §2.1 의 「영구」는 그 자리에서
     죽고 다이행 판정 전체를 다시 논증해야 한다.**
   - 대가는 B.5 행이 스스로 적었다 — 승격하면 오늘 정본이 지는 상태들(재조립
     문맥 · 마스크 키 · step 프로그램 저장)의 정의역 밖 표시를 함께 사야 한다.

  아니라 관측·격리다 — 12b 로 부활하지 않는다.
- **기존 `0xE80` 마스크 키·논스 구역 재사용** — ⑴ 검증 주체가 다르다 (그
  구역의 계약은 본체 마스킹 몫 — E.9 「마스크 키와 논스」,
  `e-defined.typ:1398-1417`) ⑵ 용량: **CCTL 로스터 실물 ≥17워드 > 구역
  잔여 15워드** (0xE80 구역 17/32워드 사용 실측; 파티션 ≥2 키·논스 세트면
  28 > 15) — 검증 F5 수리 문면: base 구조는 **키 전역 1벌 + 논스만
  파티션별**(`e-defined.typ:114, 338-343`)이라 「파티션당 키 8」은 base
  미러도 아니다 ⑶ 인증 격리 — 인증 경계가 본체 구역을 문다. ⑴·⑶ 만으로
  기각이 서고 ⑵ 는 부수다.
- **마스킹 구역 공유** (본체 E.9 설비를 다이가 직접 사용) — 신뢰 경계를
  가로지르는 상시 채널이 된다 — 분리 동기 2·3 자해.
- **DVMA 경유 데이터 이동** — 본체 파브릭·메모리 경로에 암호 트래픽을
  실어 SEC-4 공유자원 축(`05-security.typ:502-503` — SEC-4 속성
  `:425-431` 안의 「공유 자원에 남긴 잔여물」 문면)을 연다 — CSTRM 분리가
  그 축의 답이다.
- **in-fabric SHA-3** — §2.1. 단일 블록의 부활 갈래(캡처 16→25)만 원장 7
  로 남는다.

## 7. 신설 계약 수 셈 — 정직하게

「신규 opcode 2 · EH 0 · dtype 0」은 참이나, 이 확장의 실계약 질량:

① 페이지 2장 (CCTL 로스터 ≥17워드 + CSTRM 창·크레딧) · ② base 전제 일곱
(§5 — Cperm 몫은 1 하나) · ③ 결속·소거 프로토콜 (§2.4) · ④ **페이지
특권·사상 규범 (§2.3)** — 검증 E 의 지적대로 초안이 계상하지 않은 채
반드시 사야 하는 계약이라 명시적으로 올린다 · ⑤ 신설 예약-오프셋 정책
(§2.2) · ⑥ drain-다이 문면 (§2.5).

더 싼 길은 없다 — 대안 전수(§6)의 기각 근거가 전부 실측으로 섰다.

## 8. 미결 — **닫힌 것 · 유보 · 열린 채** (2026-08-31 판정 반영)

> **분할이 확정되면서 이 절이 두 문서 몫으로 갈렸다.** 아래 표의 「소속」
> 열이 그것이다 — **미결 2·3·5·6·7·8 은 전부 `Ccrypto` 몫**이고, 분할 이후

|---|---|---|---|
| 1 | **`Cperm` / `Ccrypto` 분할** | — | ✅ **닫힘 — 분할한다** (사용자 확정 2026-08-31). 실측 근거: 전건이 다르다 (Cperm = **0** · Ccrypto = 페이지·엔트로피·드레인 전제 묶음, §3·§5). ⇒ **`Cperm` 은 `Ccrypto` 의 미결에 인질로 잡히지 않는다** |

**`Cperm` 의 남은 결정 전건 = 0 (2026-08-31).** 분할(미결 1)이 확정됐고,
승격 절차 축도 확정됐다 — **승격은 열려 있고 「배정 번호의 최종 확정」만이
base B.5 「확장 절차의 거처」 미결에 매달린다** (그 미결이 열린 채 승격한
선례가 `Ctrl-min`, 커밋 `7d6139d`). **제출 문턱은 규범화하지 않는다.**
⇒ `Cperm` 은 오늘 base 착지도 사용자 결정도 기다리지 않는다.

**`Ccrypto` 는 승격 불가 — 무변경.** 전제 8(「발화 사이 상태 금지」의 규범
승격)이 서기 전에 승격하면 §2.1 의 **「영구 기각」 둘이 base 근거 없이
계약이 된다.**
