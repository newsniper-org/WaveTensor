# opcode 12비트 확장 — 제안과 실측 평가

> ### 📌 지위 — 사용자 제안(2026-08-28) + 실측 평가. **채택됨 (2026-08-28).**
>
> opcode 12b 확장과 영역 구획은 **사용자가 채택했다.** 확장 니블은 `[11:8]`
> (§4 권고 — 사용자가 「[15:12] 가 여전히 비어 있다」를 전제로 후속 제안을
> 냈으므로 배치도 수용된 것으로 확인). 정본 반영은 확장 파이프라인
> (#22 이후)의 정본 개정 전제 목록에 실린다.
>
> 정본은 `docs/wt64v1-architecture-guide/` 하나이고 이 문서의 어떤 문장도
> 계약이 아니다.

## 1. 제안 원문 (2026-08-28)

> opcode 의 자릿수를 늘릴 필요가 있어 보이는데, **#22 까지의 opcode 들은 앞에
> 0x0 을 하나 붙이는 걸로 일괄 처리**(즉, `0x60` → `0x060`)하고, **맨 앞
> 니블에 따라 영역을 나누는** 건 어떨까? `0x0##`~`0x3##` 영역은 기존 opcode
> 공간의 크기를 단순히 키운 것으로 간주하고, `0x4##`~`0x7##` 영역은 #24
> (신규 확장)를 위한 opcode 공간으로 활용하며, 나머지 영역은 예비용으로
> 남겨두는 식으로.

제안 시점의 상정: **공짜로 붙이기는 어려울 것** — 즉 재인코딩 비용을 각오했다.

## 2. 실측 — 바이너리 층에서는 공짜다. 그리고 그것은 우연이 아니다

기본 헤더 32b 실측 (`01-isa-asm.typ` §1.3.1 표):

```
[31:24] opcode 8b · [23:20] next_hdr 4b · [19:16] flags 4b
[15:8]  reserved 8b — **반드시 0. 0 이 아니면 malformation**
[7:0]   bh_len 8b
```

세 층이 전부 실물로 확인됐다:

- **어셈블러**가 `[15:8]` 에 0 을 방출한다 (`wavetensor_asm.py:2041` —
  `(opcode & 0xFF) << 24`, 예약 자리는 조립식에 아예 없어 0).
- **재구현 RTL** 이 비0 을 판정한다 (`DecodeWalk.scala:223,262` —
  `resvFld = iInstr(0)(15 downto 8)`, `resvBad = resvFld =/= 0` → malformed).
- **방출면**이 그 비트를 0 으로 지워 내보낸다 (`:285` — SEC-7 (ii)).

⇒ **기존의 모든 적법 바이너리는 이미 확장 니블 자리에 0 을 갖고 있다.**
`0x060 == 0x60` 은 수치로도 동일하다 — 재인코딩할 것이 **한 비트도 없다.**
`truth_table_premigration.json` 벡터들도 재캡처 불요다(예약 비트가 이미 0).

**이것이 공짜인 이유는 §5.7 엄격 규율의 배당금이다.** 정본이 명령 인코딩
예약을 「비0 = malformation」으로 못박은 목적이 정확히 이것 — *나중에 그
자리를 claim 할 때 쓰레기를 재해석하지 않기 위해서*다. MMIO 식 관대 예약
(쓰기 무시·읽기 0)이었다면 옛 바이너리에 아무 값이나 있을 수 있어 이 확장은
공짜가 아니었다. **상정("공짜는 어렵다")은 관대 예약 세계에서는 옳았다.**

## 3. 공짜가 아닌 곳 — 검증층. 전수 목록

바이너리는 안 움직이지만 **그 비트를 보는 모든 검사가 움직인다**:

| # | 자리 | 무엇이 바뀌나 |
|---|---|---|
| 1 | 정본 §1.3.1 표 | `[15:8] reserved 8b` → `[15:12] reserved 4b` + `[11:8] opcode_ext 4b` (배치는 §4). opcode 표기 전반 `0x##` → `0x0##` |
| 2 | `DecodeWalk.scala` | `resvFld` 폭 8→4 · `masked` 범위 · opcode 결선 `{ext, [31:24]}` 12b |
| 3 | **GUARD-MAP 4건** — `Decode.resv_judged / resv_not_indexed / resv_not_timed / resv_not_echoed` | 문면의 `[15:8]` 이 전부 좁아진다. TLA cfg ~10 run (`Decode_del_resv_*` 3형상 × 3가드 + pair) · SVA 하네스(`DecodeWalk_props.sv:203` 등) · **증거 재측정** (sby 해당 태스크 — 「모듈 태스크만 돌리면 합성 증명이 조용히 깨진다」 함정의 사정권) |
| 4 | **SEC-7 (ii) 논증 재유도** | `resv_not_echoed` 의 「`oInstr_0[15:8] == 0` 상시」가 깨진다 — **`[11:8]` 은 이제 opcode 라 방출되어야 한다.** 마스킹은 `[15:12]` 로 좁아지고, 「같은 판정을 받은 두 명령은 방출면에서 구별 불가능」 논증에서 opcode_ext 는 (opcode 가 이미 그렇듯) 구별 인자로 *정당하게* 남는다 |
| 5 | ⚠️ **fp ROM 게이트 — 공허 PASS 함정** | `in_fp_block = (opcode[7:4] == 0x7)` 이 **ext 니블 == 0x0 을 함께 봐야 한다.** 안 보면 `0x47B`·`0x87B` 가 `0x07B` 의 ROM 행에 얹힌다 — Di 확정안이 `0x80` 에서 문서화한 것과 같은 결이다 |
| 6 | 어셈블러 | opcode 인자 12b 수용 · legality 의 예약 검사 협소화 · ISA JSON `code` 는 수치 그대로(>0xFF 는 신규만) |
| 7 | **미지 opcode·영역 처분 규범 신설** | 현행 정본에 「미지 *opcode*」의 일반 처분 문면이 그립다(미지 EH 는 malformation 명문). 4096 칸이 열리면 이것이 필수가 된다 — 영역별: 미배정 값 = malformation · 예비 영역(`0x8##`+) 전체 = malformation (claim 전까지) |

**전부 유한하고 열거 가능하다.** pre-stable 이므로 recapture 는 정규
이벤트(`prestable_compat_policy`)이고, 지금이 이 확장이 가장 싼 시점이다 —
stable 후에는 §5.7 동결이 이것을 사실상 막는다.

## 4. 배치 권고 — 확장 니블은 `[11:8]`

두 후보 중 `[11:8]` 을 권고한다:

- `[11:8]` = opcode_ext ⇒ **남는 예약 `[15:12]` 가 flags `[19:16]` 에 인접** —
  미래에 플래그가 자라면 연속 구간으로 자란다.
- `[15:12]` = opcode_ext 면 남는 예약이 flags 와 opcode_ext 사이에 끼인다.

opcode 가 `[31:24]`+`[11:8]` 로 물리적으로 갈라지는 것은 디코드에서 결선
하나다. INV-T2 의 「고정 니블 분할 금지」는 *목적지 명명에 arity 를 싣는 것*의
금지이지 필드의 물리 연속성 요구가 아니다.

## 5. 영역 구획 평가

| 영역 | 용도 (제안) | 평가 |
|---|---|---|
| `0x0##`–`0x3##` | 기존 공간의 단순 확대 (base + Di/Lf/C 계보) | 1024칸. base 256 + Di(`0x07B`·`0x080`) + C 재배정 + Lf 가 넉넉히 든다 |
| `0x4##`–`0x7##` | #24 신규 확장 (Txtsmp · Ctrl 등) | 1024칸. **이종 PE 도달 경로와 자연 정합** — B.5 미결 「유닛 도달 경로의 규범 부재」(술어가 측정 트랙에만)의 답 후보: 영역 니블 → 유닛 *부류* 술어. 단 **분류이지 라우팅이 아니다** — 배달은 여전히 LNID 사상표가 한다 (「라우터를 짓지 말 것」) |
| `0x8##`–`0xF##` | 예비 | 2048칸. claim 전까지 전역 malformation (§5.7 엄격의 opcode 판) |

주의 하나: 영역 경계는 **관례이지 하드웨어 판정이면 안 되는 축이 있다** —
「`0x4##` 는 신규 확장」이라는 사실 자체를 디코더가 알 필요는 없다(미배정 =
malformation 으로 족하다). 하드웨어가 아는 것은 배정된 opcode 뿐이고, 영역은
*배정 절차의 규범*(어느 확장이 어디서 번호를 받는가)이다. 이 구분을 명세에
적지 않으면 영역 니블이 슬그머니 dispatch 비트가 된다.

## 6. 파이프라인 영향

- **Di 명세(#22, 진행 중)**: 표기만 `0x7B`→`0x07B`, `0x80`→`0x080`. 수치
  동일이므로 커밋 때 일괄 갱신으로 족하다.
- **C 재배정(#23)**: 8b 공간의 「빈칸 여섯」 제약이 풀린다 — `0x0##` 안에서
  깨끗한 연속 블록을 받을 수 있다.
- **#24**: `0x4##`–`0x7##` 가 처음부터 열린 채 시작한다.

## 8. 후속 제안 — `[15:12]` 를 기본 헤더 CRC-4 로 (2026-08-28, 평가)

> **제안**: 남은 예약 `[15:12]` 를 기본 헤더의 나머지 28비트
> (`[31:16]` ∷ `[11:0]`)에 대한 오류 검사로 쓴다 — 예: ITU-T G.704 의
> CRC-4, 생성 다항식 $G(x) = x^4 + x + 1$. EH 의 오류 검사는 별도 방식.

### 8.1 성립한다 — 그리고 관용구에도 앉는다

- **하드웨어**: 28비트 XOR 트리 하나. 디코드 진입 1사이클 안에 조합으로
  선다. 상수 시간성 무충돌.
- **처분**: malformation 이 정확히 맞는다 — §1.6 의 정의(「바이너리가 틀린
  것」)에 부합하고, loud + 접수 거절. **새 fault 부류가 필요 없다.**
- **관용구**: 이 기계의 무결성 관용구는 「선언과 실물의 자기모순」 검산이다
  (bh_len↔END↔슬롯 상한 삼중 · EH 자기 종류 검산 — `DecodeWalk.scala:244`
  `selfBad` 실물 · 플래그↔EH 대응). CRC 는 그 검산의 **비트-수준 일반화**로
  읽을 수 있다 — 헤더가 자기 자신의 잉여 선언을 나르는 형태.
- **잡는 것 중 가장 값진 것**: opcode 가 *배정된 다른 opcode* 로 뒤집히는
  1비트 오류. 오늘 이것은 구조 검사를 전부 통과하고 **조용히 다른 연산을
  한다** (예: ADD↔SUB). 플래그 1→0 뒤집힘도 같은 부류다(EH 있는데 플래그
  없음은 적법이라 조용히 의미가 바뀐다). word 0 은 *조향* 워드라 이 훼손
  부류가 데이터 훼손보다 질이 나쁘다.

### 8.2 검출력 — 정직하게 (G(x) = x⁴+x+1, 32b 부호어)

$x^4+x+1$ 은 기약·원시 다항식(주기 15)이고 $(x+1)$ 을 인수로 갖지 않는다.

| 오류 부류 | 판정 |
|---|---|
| 1비트 전부 | **검출** |
| 버스트 ≤ 4 | **검출** |
| 2비트 | **불완전** — 부호어 32b > 주기 15 라, 거리 15·30 인 **19쌍/496 미검출** |
| 홀수 가중 전부 | **보장 없음** — $(x+1)$ 비인수 |
| 랜덤 훼손 | 93.75% ($1-2^{-4}$) |

### 8.3 대가 셋 — 첫째가 무겁다

1. **방금 산 것을 도로 판다.** §2 의 알맹이가 「기존 바이너리는 확장 니블
   자리에 이미 0 을 갖고 있어 한 비트도 안 바뀐다」였다. CRC 를 넣으면
   `[15:12]` 가 일반적으로 비0 이 되므로 **기존 바이너리 전량 재인코딩 +
   truth table 벡터 재캡처**가 되살아난다. pre-stable 이라 가능하지만,
   한다면 반드시 **12b 확장과 같은 파도에서** — GUARD-MAP 4건·TLA·SVA 가
   어차피 움직이니 재검증을 두 번 하지 않는다.
   (「0 = 무검사」 탈출구로 재인코딩을 피하는 갈래는 **기각** — 바이너리가
   끌 수 있는 검사는 검사가 아니고, 니블이 0 으로 훼손되면 검사가 꺼진다.)
2. **word 0 의 마지막 예비 4비트 소진.** 이후 기본 헤더에 새 필드 자리가
   0 이 된다. 예약을 그대로 두는 것이 이 저장소에서 가장 싼 결정이고,
   CRC 로 태우면 되돌림이 없다.
3. **커버리지 비대칭.** 최대 13워드 중 1워드. EH 훼손(즉치 비트 뒤집힘,
   LBID 뒤집힘)은 그대로 조용하다 — 제안 자신이 「EH 는 별도」로 인정한
   축이나, 명령이 길수록 보호 비율이 7.7% 까지 떨어진다는 사실은 적어야 한다.

### 8.4 결정적 선행 — §5.1 이 이 위협을 다루지 않는다

정본 §5.1 위협 모델 실측: 다루는 것 = 테넌트 간 누출 · 주소 관측 추론 ·
타이밍 채널. **「다루지 않는 것: 물리적 공격, 공급망, 호스트 측 취약점」.**
전송 훼손·비트 오류는 어느 쪽에도 이름이 없다.

그리고 위협 잔여가 실제로 얇다:

| 훼손 원천 | 기존 방벽 | CRC-4 의 추가 값 |
|---|---|---|
| 호스트 SW 버그 | 없음 | **0** — 같은 SW 가 CRC 도 계산한다 (자기 일관 쓰레기) |
| PCIe 전송 | 링크 LCRC(32b) | 근사 0 |
| 호스트 DRAM | ECC (호스트 의존) | 작음 |
| torn write | sub-word 쓰기 거절 + loud (E.1/E.7 기존) | **niche 실재** — 참조 fetch 중 호스트 수정 |
| on-die SEU | 없음 | 상징적 — FPGA 의 진짜 축은 config 메모리(별개 설비) |

⇒ **정본 자신의 규율(「무엇을 막으려 하는가」를 먼저 적는다)에 따라, §5.1 에
위협을 이름 붙이는 개정이 선행이다.** 위협 모델에 없는 위협을 막는 기능은
근거 부재로 선다.

### 8.5 대안 하나 — 전체 명령 CRC 를 CHKSUM EH 로

위협을 이름 붙이기로 한다면, 헤더 4비트보다 **EH 카탈로그 빈칸(`0xA`–`0xE`)에
CHKSUM EH** 를 두는 갈래가 비교 대상이다: 명령 전체(헤더+EH)를 덮고(커버리지
비대칭 소멸 — 「EH 는 별도」 문제도 함께 답), CRC-8/16 로 검출력도 오르며,
opt-in 이라 기존 바이너리 무변경이 유지된다. 대가: EH 슬롯 1 (기본 형상 4 중
— Di 가 3 을 쓰므로 공존 가능) · opt-in 무결성은 약한 무결성이라는 반론.

③ 붙이지 않는다면 이 절이 「검토했고 위협 모델 밖이라 보류」의 기록으로 남는다.

> **#23 과 #24 사이**에 수행한다. 채택되는 것은 §10 파도에 W-항으로
> 추가된다. #26 의 핵심 부담은 「명명의 의무」다 — 이름 붙인 위협은 방어
> 의무 또는 명시적 잔여 수용을 낳으므로, 좁게 긋지 않으면 보호 없는 다른
> 표면(페이로드·태그·EH 데이터·MMIO 경로) 전부가 「명명된 위협, 방어 없음」
> 상태가 된다.


### 8.7 후속 질문 — EH 가 아예 없는 명령에도 CHKSUM EH 가 필요한가 (2026-08-28)

> **질문**: CHKSUM EH 를 채택할 때, (CHKSUM 이 아닌) EH 가 아예 없는
> 경우에도 CHKSUM EH 가 필요할까?

**답: 필요하지 않다 — 그러나 「보호가 불필요해서」가 아니라 「그 도구가
그 자리에 구조적으로 부적합해서」다. 그리고 이 부적합이 §8.5 의 미결
(둘 다는 이중 지불인가 상보인가)을 답한다: 상보다.**

#### 실측 — EH 없는 명령은 하나뿐이고, 그 하나가 최악 부류다

`required = []` 인 opcode 는 ISA 전수에서 **`0x00 NOP` 하나**다. 그런데
NOP 는 훼손 시 가장 나쁜 부류다 — 1비트 뒤집힘 여덟 방향(0x01·0x02·0x04·
0x08·0x10·0x20·0x40·0x80) 중 **배정된 opcode 로 가는 것들**(0x10 ADD 등)은
「아무것도 안 하기로 한 자리에서 조용히 실연산」이 되고, 역방향(실연산→NOP)
은 「일이 조용히 사라지는」 것이다. 양방향 다 구조 검사를 전부 통과한다.
그리고 #24 의 `Ctrl` 류가 이 부류(제어성·무피연산자 명령)를 늘릴 수 있다.

#### CHKSUM EH 가 그 자리에 부적합한 이유 둘

1. **상대 비용 100%.** 1워드 명령에 CHKSUM EH 1워드를 달면 크기가 2배다.
   13워드 명령의 ~8% 와 대비된다 — 부담이 가장 큰 자리가 정확히 보호
   가치 밀도(전 비트가 조향 비트)도 가장 큰 자리라는 역설.
2. **발견 가능성 순환 — 이것이 구조적 결격이다.** CHKSUM EH 를 찾으려면
   사슬을 걸어야 하는데(next_hdr · bh_len · EH kind/len), **그 비트들이
   바로 보호 대상이다.** next_hdr 가 END 로 뒤집히면 워커가 CHKSUM 을
   영영 만나지 않고 검사는 조용히 사라진다 — §8.3 이 헤더 CRC 의
   「0 = 무검사」 탈출구를 기각한 것과 같은 결의 **구조판**이다. EH 없는
   명령에 CHKSUM 을 다는 것은 *없던 사슬 의존을 보호 목적으로 만들어
   넣는* 것이다. 헤더 `[15:12]` CRC-4 는 **고정 위치**라 이 순환이 없다.

#### 함의 — §8.5 미결의 해소: 이중 지불이 아니라 상보다

| 명령 형태 | 헤더 CRC-4 | CHKSUM EH |
|---|---|---|
| EH 0 (1워드 — NOP·미래 Ctrl 부류) | **0비트 비용·고정 위치·순환 없음** | 크기 2배 + 발견 순환 |
| EH 1~2 (2~3워드) | 헤더만 (1/2~1/3) | ~50~33% 비용 |
| EH 3~4 (≤13워드) | 1/13 커버리지 | **~8% 비용·전체 커버** |

두 기전은 명령 길이 스펙트럼의 **반대쪽 끝에서 각자 최적**이다. CHKSUM 만
채택하면 조향 밀도가 가장 높은 명령이 가장 보호 안 되는 역설이 남고, 헤더
CRC 만 채택하면 긴 명령의 EH 데이터가 조용한 채 남는다.

#### 채택 형태 권고 (#26 결정 패키지에 합류)

**CHKSUM EH 를 채택하더라도 EH 없는 명령에는 요구하지 않는다** — 의무화해도
실익 대비 비용이 최악이고 발견 순환이 검출력을 깎는다. 그 부류의 보호가
필요하다는 판정이 서면 그 자리의 도구는 헤더 CRC-4 다. ⇒ #26 의 조합 갈래
(헤더 CRC + CHKSUM 둘 다)는 이중 지불이 아니라 **길이 스펙트럼 분담**으로
평가해야 한다.


### 8.8 후속 제안 — CHKSUM EH 를 EH 개수 집계에서 제외 (2026-08-28)

> **제안**: CHKSUM EH 는 전체 EH 개수 집계에 포함시키지 않는다 —
> 한 번에 CHKSUM EH 가 여러 개 붙을 일은 없으므로.

**찬성. 다만 「집계」가 하나가 아니라 셋이고, 셋의 처분이 갈린다** —
갈라 적지 않으면 구현이 섞는다:

| 회계 | 처분 | 근거 |
|---|---|---|
| EH 슬롯 상한 (기본 형상 4) | **제외** — 제안의 알맹이 | 아래 |
| `bh_len` (명령 워드 수) | **포함 필수** | 물리 길이다 — 빼면 fetch·순회가 명령 끝을 모른다 |
| wire 다섯째 바이트 (EH 길이 벡터) | **자연 제외** | #27 원칙상 CRC 는 wire 에 아예 없다 — 두 제안이 저절로 정합한다 |

#### 이 제안의 실질 — 「전용 슬롯」이고, 그것이 둘을 산다

하드웨어 관점에서 「집계 제외」 = **워커 슬롯 4 + CHKSUM 전용 1**이다.
형상 파라미터를 5 로 올리는 것과 물리적으로 같지만, **전용**이라는 점이
다른 것을 산다:

1. **슬롯 압력 소멸** — §8.5 의 대가 「EH 슬롯 1」이 삭제된다. Di·Lf64di·C
   전부 3슬롯이라 넷째가 정확히 상한과 만나던 문제가 사라진다.
2. **단조 opt-in — 이것이 더 크다.** 전용이 아니면 이미 4 EH 를 쓰는 명령에
   CHKSUM 을 달려면 **기능 EH 하나를 버려야** 한다 — 무결성 채택이 표현력과
   경쟁하고, 채택이 비단조가 된다. 전용 슬롯이면 **어느 명령에든 기존
   인코딩을 건드리지 않고 CHKSUM 을 얹을 수 있다.**

#### 결합 권고 — 위치 고정(첫 EH)을 함께 정하면 §8.7 의 발견 순환도 죽는다

집계 밖으로 낸 김에 **자리도 사슬 밖 규칙으로 고정**한다: 「CHKSUM 은
존재한다면 반드시 기본 헤더 직후 첫 워드이고, 수신측은 next_hdr 를 타지
않고 **word1 `[11:8]` 자기-종류 니블을 고정 오프셋에서 직접 검사**해
존재를 판정한다.」 그러면 CHKSUM 을 찾는 데 사슬(보호 대상인 next_hdr ·
bh_len)을 걸을 필요가 없다 — §8.7 이 지적한 발견 가능성 순환이 소멸한다.

정직한 잔여: **opt-in 인 한 존재 신호 훼손이 검사를 끄는 벡터는 남는다**
(word1 종류 니블 1개 훼손 = 검사 소등). 그것은 §8.3 이 이름한 opt-in 의
본질 한계이고, 그것이 없는 형태는 always-on 헤더 CRC-4 뿐이다 — §8.7 의
상보성 표가 그대로 선다.

#### 대가·부수 계약 — 정직하게

- **「회계 밖 EH」라는 첫 예외 부류가 생긴다.** 오늘 전 EH(NOP_PAD 포함)는
  슬롯 상한에 계상된다 — CHKSUM 이 첫 예외다. 부류를 여는 결정임을 §1.3.1
  개정 문면(「기능 EH 최대 4 + CHKSUM 전용 슬롯 1, 회계 밖」)에 명시해야 한다.
- **반복 규약 행 추가** — CHKSUM ≤ 1, 반복 = malformation (§4.2.3 전수 표).
  「여러 개 붙을 일 없다」는 전제를 규범으로 못박는 것.
- **워커 실장** — 고정 순회가 4+1 이 된다 (상수 시간성 유지, 슬롯 하나 증가).
- **#27 접면 신설** — wire 에는 CHKSUM 이 없으므로, ingress 가 in-flight
  구성 시 **붙일지 여부를 아는 신호**가 필요하다 (envelope 예약 플래그
  후보 vs ingress 정책 고정). #27 의 Q 목록에 추가.

⇒ 이 제안은 #26 이 CHKSUM 갈래를 채택하는 경우의 **형태를 확정**하는
것이다 — 채택 여부 자체(§5.1 경계 결정)는 여전히 #26 몫이다.


### 8.9 후속 제안 — CHKSUM EH 를 **CH (Castagnoli Header)** 로 재정의 (2026-08-28)

> **제안**: CHKSUM EH 를 아예 **CH** 로 재정의한다 — 단일 워드(32b) 고정
> 길이이고, **그 32비트 전부를 CRC-32C(Castagnoli) 출력으로 채운다.**

**명확한 개선이다.** EH 골격을 벗는 것이 낭비 하나와 구조 문제 셋을 동시에
없앤다.

#### 같은 비용, 검출 2배 — 그리고 다항식 선택이 정량적으로 옳다

CHKSUM *EH* 는 1워드 중 하위 16b 가 공통 헤더(다음 종류·자기 종류·워드 수)
라 **CRC 에 16비트만** 남았다. CH 는 32비트 전부가 CRC 다 — **같은 1워드에
검출 비트 2배.**

그리고 CRC-32C 가 이 길이대에 정확히 맞는다(Koopman 표 기준 — 외부 지식,
확신 중간-높음, #26 패키지에서 원전 핀 권장): **HD=6 이 ~5,243비트까지** —
명령 최대 416b(+CH=448b)가 넉넉히 안이라 **≤5비트 오류 전부 검출**, ≤177b
(≤5워드) 구간은 HD=8. IEEE CRC-32 는 HD=6 이 268b 까지라 416b 에서 열세 —
**Castagnoli 지정이 취향이 아니라 측정이다.** 하드웨어 선례도 도처에 있다
(SSE4.2 `crc32` · iSCSI · ext4).

#### 구조 문제 셋이 「구성적으로」 사라진다

| §8.8 에서 대가였던 것 | CH 에서 |
|---|---|
| 「회계 밖 EH」 첫 예외 부류 신설 | **불요** — CH 는 EH 가 아니므로 EH 회계에 애초에 없다. 예외가 아니라 구성이다 |
| 반복 규약 행 (CHKSUM ≤1) | **불요** — 존재가 플래그 1비트면 두 번 세울 수 없다. 「검사를 늘리는 대신 인코딩을 좁힌다」(E.1.1) 그대로 |
| EH 종류 코드점 소비 (0xA–0xE 중 1) | **불요** — 코드점을 안 먹는다. 빈칸 다섯이 그대로 남는다 |

위치는 §8.8 권고 승계 — **기본 헤더 직후 word1 고정.** wire 정합도 유지
(#27 원칙상 CRC 는 wire 에 없고, CH 는 순수 CRC 이므로 통째로 wire 밖 —
ingress 재계산·재부착).

#### 존재 신호 — 갈래 둘, 그리고 결정 공간의 붕괴

CH 는 전 비트가 CRC 라 **자기 식별 구조가 없다.** 존재를 아는 방법 둘:

- **(i) always-on** — 모든 명령이 word1 = CH 를 나른다. 존재 비트 불요 ·
  소등 벡터 없음 · `[15:12]` 온존. 대가: **전 명령 +1워드**(NOP 2배, 최대
  13→14워드) + **기존 바이너리 전량 재인코딩·truth table 전량 재캡처**
  (bh_len 이 전부 바뀐다).
- **(ii) opt-in** — 기본 헤더에 존재 플래그 1비트(후보: `[15]`). 대가:
  소등 벡터 잔존(플래그 1→0 훼손 = 검사 소등 — opt-in 본질 한계. 역방향
  0→1 은 word1 을 CH 로 오독 → CRC 불일치 → **loud**, 그쪽은 안전) ·
  `[15:12]` 1비트 소비.

**⇒ 어느 갈래든 헤더 `[15:12]` CRC-4 는 사실상 배제된다.**
(i) 이면 CH 가 헤더를 HD=6 으로 덮어 CRC-4 가 잉여이고, (ii) 면 비트
예산이 막는다 — F_CH(1) + CRC-4(4) = 5 > 4. **#26 의 질문이 「두 기전의
경계별 조합」에서 「CH: always-on / opt-in / 안 함」 셋으로 단순해진다.**
§8.7 의 상보성 표는 CH 아래서 이렇게 갱신된다 — 짧은 명령의 0비트-비용
보호(헤더 CRC-4 의 niche)는 사라지고, 그 자리는 (i)의 「전 명령 +1워드」
또는 (ii)의 「NOP 노출 수용」 중 하나가 된다.

#### 남는 것

- 상수 시간성: CRC 누적을 고정 순회에 실으면 된다(워드당 갱신 + 판정점
  비교) — 순회가 이미 고정 횟수다.
- 명칭: 「Header」이되 자리는 기본 헤더 *다음*이다 — 「둘째 헤더」로 읽는
  용어 정리 한 줄이 명세에 필요하다. C 확장의 CCTL/CSTRM 과의 약어 근접은
  실무상 무해.
- 이 절(§8.7–8.9)은 진행 중인 #26 워크플로가 못 본 입력이다 — 결정 패키지
  도착 시 **기전 축은 이 절이 대체**하고(CHKSUM EH 평가는 CH 평가로),
  경계·의무 행렬 축은 그대로 쓴다.


### 8.10 후속 질문 — CRC-4 가 배제되면 `[15:12]` 를 다른 용도로? (2026-08-28)

> **질문**: 기본 헤더 `[15:12]` 의 역할에서 CRC-4 가 배제되면, 그 영역을
> 다른 용도로 배정할 수 있겠는가?

**네 — 조건부로 열린다. 다만 갈래별로 폭이 다르고, 「배정할 수 있다」와
「배정한다」 사이에 정본 규율이 서 있으며, wire 결합 함정이 하나 있다.**

#### 갈래별 잔여 (#26 의 CH 결정과 한 몸이다)

| #26 결과 | `[15:12]` 의 상태 |
|---|---|
| CH always-on | **4비트 전부 자유** (존재 비트 불요) |
| CH opt-in | F_CH 가 1비트(후보 `[15]`) — **3비트 자유** |
| CH 안 함 | CRC-4 후보 지위로 **회귀** — 이 절의 전제가 사라진다 |

#### 「배정할 수 있다」 ≠ 「배정한다」 — 그리고 비워 두는 것이 이미 용도다

정본 규율 둘이 그대로 선다: **「예약 필드는 '언젠가 쓸 여유'로 읽지 말 것 —
예약 필드는 덫이다」** · 배정의 정당화는 「자리가 남았다」가 아니라 **「필요가
먼저 확인됐고 이 자리가 유일 정합」**(ACCTGT `[23:16]` 승격의 형판).

지금 실재하는 claimant 는 **F_CH 하나뿐**이다(opt-in 갈래 한정). 그 밖의
후보들은 전부 투기다 — EH 개수 필드(END·bh_len·슬롯 상한 삼중 위에 네째
선언 = 과잉) · opcode 16b 확장(4096칸에 소비자 없음) · 버전 니블(전형적 덫).

그리고 **비워 두는 것이 이미 한 용도다**: flags `[19:16]` 가 4/4 만석이고,
확장 니블을 `[11:8]` 에 둔 근거가 정확히 「`[15:12]` 가 flags 에 인접해
미래 플래그가 연속 구간으로 자란다」였다(§4). **플래그 성장 여지가
`[15:12]` 의 기본값 용도다** — 소비하는 순간 그 여지가 사라진다.

#### ⚠️ wire 결합 함정 — 「wire 미탑재」는 CRC 전제 위의 지위였다

#27 의 4바이트 0-낭비 헤더(28 + envelope 4 = 32b)는 **`[15:12]` 가 CRC 라서
wire 에 안 실린다**는 전제 위에 있다. 비-CRC 용도로 재배정하면 1:1 비트
재배치가 그 비트들을 **날라야 하고**, 헤더가 32+n 비트가 되어 바이트 정렬이
깨진다.

탈출구가 하나 있다 — **envelope 예약 2비트에 얹기.** F_CH 는 원래 ingress
가 「붙일지 여부를 아는 신호」(§8.8 접면)로 wire 에 있어야 하므로, envelope
예약 1비트에 사상하면 0-낭비가 유지된다. ⇒ **wire 호환 여유는 F_CH 뒤에
envelope 예약 1비트, 즉 in-flight 1비트가 실질 전부**다. 그 이상의 배정은
wire 헤더 성장을 함께 산다.

#### 권고 → **채택됨** (2026-08-28 사용자 승인)

`[15:12]` 의 처분은 **#26 과 한 몸으로** 정한다 — CH 갈래를 고를 때 위
표의 잔여가 자동으로 정해진다. 그리고 **어느 갈래에서든 지금 새 배정은
하지 않는다** — 실재 claimant 가 F_CH 하나뿐이고, 남는 비트의 기본값
용도는 「플래그 성장 여지」라는 이름의 예약 유지다. 훗날 배정이 오면
ACCTGT 형판(빈 전건 + 유일 정합)을 통과해야 한다.

> 이로써 #26 결정 패키지에 실릴 것이 확정됐다: **「CH: always-on /
> opt-in / 안 함」 셋 중 하나를 고르면 `[15:12]` 잔여(4b 자유 / 3b 자유 /
> CRC-4 회귀)가 자동으로 따라오고, 어느 경우든 즉시 배정은 없다.**


### 8.11 후속 지적 — opt-in 은 한 방식이 아니다: F_CH vs **EH-조건부** (2026-08-28)

> **지적**: opt-in 에 한 가지 방식만 있는 것이 아니다 — `F_CH` 플래그 방식
> 외에 **「EH 가 하나라도 있으면 ON, 하나도 없으면 OFF」** 방식이 있다.

**맞다 — 그리고 이 EH-조건부 방식은 검토 결과 여러 축에서 F_CH 를
지배한다.** 정확히는 opt-in 이라기보다 **결정론적 규칙**이다(작성자 선택이
없다) — 그래서 선택지 분류가 셋에서 넷으로 바뀐다.

#### 기전 — 존재 신호가 이미 있는 비트에서 유도된다

기본 헤더 `next_hdr [23:20]` 이 이미 존재를 말한다: `0x0`(END) = EH 없음 →
CH 없음, 1워드 명령. 비-END = EH 있음 → **word1 = CH**, 사슬은 word2 부터.
새 비트 0개.

#### F_CH 대비 지배 축 셋

1. **`[15:12]` 가 통째로 남는다** — always-on 급 (4b 자유).
2. **소등 벡터가 구조적으로 약하다.** F_CH 는 단독 1비트(1→0)가 존재
   신호인데, EH-조건부의 존재 신호(next_hdr)는 **이미 bh_len↔END 삼중
   검산에 얽혀 있다** — next_hdr 를 END 로 뒤집으면 bh_len 이 1 이
   아니라서 기존 검산이 운다. 조용한 소등에는 협조 훼손(next_hdr→END +
   bh_len→1 + flags 정합 + 잔여가 적법 1워드 인코딩) 이 필요하다 —
   단독 비트 소등이 없다.
   *(부수 정정: §8.9 의 「F_CH 1→0 = 소등」도 과대평가였다 — 플래그가
   꺼지면 word1(=CRC 값)이 첫 EH 로 오독되는데 그 `[11:8]` 니블이 대개
   미지 종류라 malformation 으로 우는 경우가 많다. **CH 워드 자체가 사슬
   독으로 작용**한다. 다만 「대개 loud」이지 보장이 아니다 — 일부 CRC
   값은 적법 사슬로 파싱될 수 있다.)*
3. **#27 접면이 소멸한다.** F_CH 는 envelope 예약 1비트를 먹어야 했는데
   (§8.10), EH-조건부에서는 ingress 가 **wire 로 온 next_hdr 에서 존재를
   유도**한다 — envelope 신호 불요, 예약 2비트 온존, 0-낭비 유지.

그리고 정본 미학에 더 맞다 — **「검사를 늘리는 대신 인코딩을 좁힌다」**:
존재 비트라는 자유도 자체가 없으므로 **현실과 어긋날 수 있는 비트가 없다.**

#### 정직한 대가 둘

- **비용이 사실상 always-on 이다.** 실측으로 EH 없는 명령은 NOP 하나뿐
  (`required=[]` 전수) — EH-조건부의 커버리지·재인코딩·재캡처 비용은
  always-on 에서 NOP 만 뺀 것과 같다. F_CH 의 「선택분만 +1워드」 절약은
  사라진다.
- **노출 잔여가 정확히 §8.7 의 최악 부류다.** 덮이지 않는 유일한 명령이
  EH 없는 것들(NOP · 미래 Ctrl 류)인데, 그것들이 전 비트 조향 워드다.
  always-on 과의 유일한 실질 차이가 이 노출 수용 여부다.

#### 갱신된 #26 선택지 — 넷

| 갈래 | 존재 신호 | `[15:12]` | 소등 벡터 | 커버리지 | 비용 |
|---|---|---|---|---|---|
| **always-on** | 불요 | 4b 자유 | 없음 | 전 명령 | 전 명령 +1w · 전량 재캡처 |
| **EH-조건부** | next_hdr≠END (유도) | 4b 자유 | 단독 비트 없음 — 협조 훼손 필요 + 삼중 검산에 얽힘 | EH 있는 전 명령 | ≈ always-on − NOP |
| **opt-in F_CH** | `[15]` 플래그 | 3b 자유 | F_CH 1→0 (사슬 독으로 대개 loud, 보장 없음) | 선택 명령 | 선택분만 +1w |
| **안 함** | — | CRC-4 회귀 | — | 없음 | 0 |

⇒ **always-on 과 EH-조건부의 실질 차이는 「NOP 류의 노출 수용 vs 2배
크기」 하나로 좁혀지고**, F_CH 는 「선택적 적용으로 평균 크기를 아끼는」
용도가 실재할 때만 살아남는다. 결정은 #26 패키지에서.

## 9. 후속 질문 — EH 마다 CRC-4? (2026-08-28, 평가)

> **질문**: EH 들에도 비어 있는 니블이 하나라도 남아 있다면 마찬가지로
> 각각 CRC-4 로 에러 체크가 가능한가?

### 9.1 빈 자리 실측 — 있긴 한데, 정확히 지킬 게 없는 곳에 있다

EH 비트 배치는 측정 트랙(§1.3.2 「EH 의 비트 배치」)에 전수가 있다. 첫 워드
하위 16비트는 전 EH 공통 헤더(다음 종류 4 · 자기 종류 4 · 워드 수 8)로 꽉
차 있고, 본문(`[31:16]` + 후속 워드)의 여유는 종류마다 갈린다:

| EH | 빈 비트 | 비고 |
|---|---|---|
| PORT · IMM16 · MEM · SUBSCRIPT · PRECISION | **0** | **데이터 밀도가 가장 높은 다섯이 전부 꽉 찼다** |
| OPREF | 4b (`[23:20]`) | §1.4.6 폐지-예약 (「반드시 0」) |
| ACCTGT | 8b (`[23:16]`) | ⚠️ **이미 claim 됐다** — Di 명세 §1.1 이 조각열 선언 총개수로 승격 (B.5 유일 정합 후보) |
| IMM32 · IMM64 | w0 `[31:16]` 16b | 측정 트랙에 **미기재** — 어셈블러 방출 관측이 선행 |
| NOP_PAD | 16b | 본문 없음 — **보호할 데이터도 없다** |

### 9.2 판정 — 가능한 곳이 헤더 경우보다 더 어긋나 있다

- **커버리지 역설**: 즉치·목적지·오프셋·첨자를 나르는 다섯(지킬 값이 가장
  많은 EH)에 빈 비트가 **0** 이고, 여유가 있는 곳은 폐지-예약(OPREF 4b),
  이미 팔린 자리(ACCTGT), 본문 없는 패딩이다. **훼손은 빈 니블이 있는
  종류를 골라서 일어나지 않는다** — 종류별로 있다/없다가 갈리는 보호는
  보호 여부가 우연에 걸린 것이다.
- **유일하게 좋은 짧은 부호 하나는 실재한다**: OPREF 본문 12b(LBID 8 +
  src_kind 4)에 `[23:20]` CRC-4 를 걸면 부호어 16b ≤ 주기 15+4 근처라
  1비트 전부 + 2비트 거의 전부(거리 15 인 1쌍만 미검출)를 잡는다 —
  **LBID 1비트 뒤집힘 = 조용히 다른 뱅크를 읽는 오류**를 정확히 덮는다.
  다만 그 자리는 §1.4.6 폐지-예약이라 claim 정당화(「예약은 덫」)가 따로 든다.
- **구조 훼손은 이미 잡힌다** — 자기 종류 검산(selfBad) · 워드 수 · 반복
  규약 · 예약-0 · END 삼중. 조용히 남는 것은 **데이터 값 훼손**인데, 그것이
  많은 EH 일수록 빈 니블이 없다 (위 표).

### 9.3 권고 — §8.6 과 같은 결론이 더 강하게 선다

**보류.** 위협 명명(§8.4 — §5.1 개정)이 선행이라는 순서는 동일하고, 명명된
뒤에도 **CHKSUM EH(§8.5)가 이 축을 더 강하게 지배한다** — 니블 유무라는
우연과 무관하게 명령 전체(헤더 + 전 EH)를 한 기전·한 판정으로 덮고, CRC-8/16
으로 검출력도 오른다. per-EH 니블 CRC 는 종류별 회로 N 개 · 종류별 재인코딩 ·
종류별 규칙을 만들면서 커버리지는 부분에 그친다.

예외적으로 살릴 가치가 있는 것 하나: **OPREF `[23:20]` CRC-4** (위 9.2 둘째
항 — LBID 보호는 짧은 부호가 실제로 좋은 자리다). 위협이 명명되면 CHKSUM EH
와 별개로 검토할 후보로 남긴다.

### 9.4 OPREF `[23:20]` CRC-4 — **정식 채택됨** (2026-08-28)

사용자가 **정식 채택**했다. 실장은 인코딩 개정 파도(§10)에 실린다.

#### 왜 이 하나는 다른 CRC 제안들과 성립 구조가 다른가

- **닫는 것이 「전송 훼손」이 아니라 「조용한 오독」이다.** ISA-8 의 잔여가
  정확히 이것이다 — LBID 가 *사상표에 없는* 값으로 깨지면 route fault(loud)
  지만, *사상된 다른* 값으로 깨지면 **어떤 검사도 울리지 않고 다른 뱅크를
  읽는다.** 구조 검산(선언-실물 자기모순)이 원리적으로 닿지 못하는 부류다 —
  깨진 LBID 도 완벽히 적법한 선언이기 때문이다. §5.5 loud-fault-never-silent
  의 *정신*이 원하는 자리이되, §5.5 가 명령하는 것은 아니다(관측 가능한
  이상을 삼키지 말라는 규범이지 잉여를 더하라는 규범이 아니다) — **명령하는
  것은 이 신설 규범 자신이어야 한다.** 그래서 §5.1 전면 개정이 아니라
  **§1.4.6 국소 검산 규범**이 옳은 거처다.
- **판정기가 아직 없어서, 지금이 정확히 싼 시점이다** (실측
  `rtl/README.md:669`): OPREF `[23:20]`·ACCTGT `[23:16]` 의 예약 판정은
  「본문 해석과 함께 2차 파도 몫」으로 **미구축**이다. `==0` 판정기를
  지었다가 CRC 로 바꾸는 것이 아니라 **처음부터 CRC 판정기로 한 번만
  짓는다** — ACCTGT 쪽도 같은 파도에서 총개수 판정으로 직행하는 것과
  대칭이다. 판정점은 D14 정합 요건 그대로 oExecValid 이전 합류.
- **어셈블러 방출도 실측상 몇 줄이다**: 현행 조립식
  `upper = ((noc_route & 0xFF) << 8) | (src_kind & 0xF)`
  (`wavetensor_asm.py:1987`) — `[7:4]` 는 애초에 조립식에 없어 0 이다.
  CRC 니블을 OR 하는 것이 전부다. EINSUM 이 합성하는 OPREF 도 같은 경로라
  자동으로 얻는다.

#### 확정 문면 (초안)

- **메시지 = 본문 12b** (LBID 8 ∥ src_kind 4), 부호어 16b = 메시지 ∥ CRC 4.
  논리 비트 순서는 명세가 못박는다(고정 길이라 init 은 검출력 중립 — 0).
  하위 16b 공통 헤더는 대상이 아니다 — 그 축은 기존 검산이 이미 덮는다
  (다음-종류 훼손은 *다음* EH 의 selfBad 가, 워드 수는 wordsBad·END 삼중이).
- **다항식 `x⁴+x+1` (ITU-T G.704) 유지** — 16b 부호어에서 근사-최적임을
  확인했다: 1비트 전부 · 버스트≤4 전부 · **2비트는 거리 15 인 1쌍/120 만
  미검출**. `(x+1)` 포함 대안(예: `x⁴+x³+x²+1`)은 홀수-가중 전부를 얻는
  대신 2비트 스팬이 7 로 줄어 미검출 2비트가 11쌍으로 는다 — 열세.
- **처분 = malformation + loud, 판정은 디코드 경계** (§1.6.1 판정 위치 규범
  그대로). OPREF 는 명령당 ≤2 회 — 각 인스턴스가 자기 CRC 를 나른다.

#### 대가 — 정직하게

- OPREF 를 나르는 **기존 바이너리가 전부 바뀐다** (`[23:20]` 0 → CRC).
  어셈블러 재생성은 기계적이나 truth table 의 OPREF 포함 벡터는 재캡처다 —
  pre-stable 정규 이벤트이고, 인코딩 개정 파도에 함께 실으면 재검증이
  한 번이다.
- **다중비트 잔여 6.25%** — CRC 통과 훼손은 여전히 조용한 오독이다.
- **인코더 버그는 원리상 못 잡는다** — 잘못된 LBID 의 올바른 CRC.
- 형식층: 2차 파도(이미 빚진 자리)에 GUARD-MAP 항 하나 + 기대값 함수가 더해진다.

#### CHKSUM EH 와의 관계

대체가 아니다 — CHKSUM EH 는 위협 명명(§8.4) 후의 **일반 기전**으로 남고,
OPREF CRC-4 는 위협 명명 없이도 서는 **국소 검산**(조용한 오독 닫기)이다.
두 정당화의 축이 다르므로 공존한다.
