## #2 예산 I (정적 선언량) — **#1 과 한 몸** (재정식화 강제)

- **재정식화**: 「자리 후보 ACCTGT `[23:16]` *또는* LBID 길이」는 대안
  관계가 아니다 — `[23:16]` 은 `Di` §1.1 base 개정 + #25 W-파도가 이미
  **조각열 선언 총개수 `T` 의 자리로 청구**했다 (`b-gaps.typ` 「선언 자리」
  행 — 「유일한 정합 후보」). **예산 I 의 실체 = 그 `T`(선언측) ≤ LBID
  길이(임대 상한측)의 비교** — 두 자리는 비교의 양변이다. 이 정정이 #1 과의
  「한 몸」 판정을 오히려 단단하게 한다.
- **「충돌 없음-정면」은 과속이다 — 처분 분류가 미결이었다 (→ 확정:
  §13-1).** §2.4.1 4항의
  능력 부재는 「선언이 구현의 용량을 넘는 것」= 고정 능력 명제인데
  (`budget_axis.md` §2 — 같은 바이너리가 같은 기계에서 언제나 같은 답),
  LBID 「길이」가 호스트 임대 상한이면 반례가 선다: 같은 바이너리(T=8
  선언)가 길이=4 표 아래서 거절, 길이=16 아래서 수락. §1.6.2 3분류 배타성
  아래 **능력 부재 / malformation(호스트 자기모순 — D4 `SD_LEN` 선례) /
  기입 시점 거절(C 부류) 중 분류 결정 하나**가 필요하다 — 「확장 문장
  하나」가 아니다. **→ 분류 결정 확정 (2026-08-28): malformation — 호스트
  자기모순, D4 `SD_LEN` 선례 (§13-1).**
- **귀속 정정**: 「둘은 같은 것의 두 얼굴」은 `budget_axis.md` §6.2 배너
  문면이다 — 신규 판정으로 옮겨 적으면 이중 계수다. §11-1 이 남긴 것은
  그 동일성의 **사용자 확인**뿐이다.

## #3 정렬 네트워크 (data-oblivious compare-exchange) — **경량 메모, 지금** (판정 정정 2건 반영)

- **ISA 표면 = D-09 + `0x79 FMINMAX` 쌍이다** (「D-09 가 사실상 전부」는
  반증). `0x79` 는 이미 있는 fp MIN/MAX 표면이고 (JSON:
  `fminmax_op_codes = {MINIMUMNUM, MAXIMUMNUM}`), D-09 행 스스로 「0x79 와
  함께 정하지 않으면 두 MIN/MAX 가 다른 NaN 규칙을 갖는다」고 결합을
  경고하며, `Lf64di` §9-8 은 `0x79` 의 **ACCTGT 없는 2조각 출력**이 W4
  파도의 재행 대상임을 기록한다.
- **NaN·전순서 축을 정면으로 정해야 한다** — data-oblivious 정렬은 전순서
  비교가 전제. 가내 선례 = `0x07B` 의 키 정규화 (±0 통일 · NaN 마스크,
  `Di` §3).
- **코드점 실측**: `0x26` 은 비어 있지 않다 — JSON `0x26 SPLAT (v1.1)`.
  D-09 문면 「0x26..0x2F 여유」는 낡았고 실제 빈칸은 `0x27..0x2F` 다.
  그리고 **base 배정(`0x0##`)과 #24 확장 배정(`0x4##`)은 다른 절차**다 —
  「D-09 를 함께 닫는다」를 적을 때 이 구분을 명시할 것.
- **출력 형태 갈래 4** (compare-exchange 의 (min,max) 두 값):
  1. **두 발화** — min 발화 + max 발화, 각각 ISA-9 ②.
  2. **팩킹** — ≤32b 에서 한 beat 에 min‖max. 대가 = 소비측 레인 선택
     부담 (`ALGDi` payload `[31:0]‖[63:32]` 관례가 선례).
  3. **조각열 T=2 + ACCTGT** (≤32b 에도) — `di_calculus_extension.md`
     §3.1 갈래 2 · `di_design_v1.md` 에 비용(문맥 풀 압력)까지 기록된
     실재 갈래.
  4. **64b: 조각열 T=2 승계** — (min,max) 128b 출력은 열린 매듭이
     아니라 **착지한 형태가 있다**: `Lf64di` §2.2 가 명문으로 「`Di`
     미결 5(출력 beat 형태)는 이 절이 닫는다」 — dual_f64 128b = 조각열
     T=2 + ACCTGT `[23:16]`=2, ISA-9 ③, 문맥 풀 기각 근거와의 대면 완료
     (원장 4 — nCtxs=4 실측). 「여기서 풀지 말 것」이 아니라 **승계**다.
- **ISA-9 ② 위반 확정 재현**: 「한 발화가 단일 beat 둘」 형태는 해설이
  정확히 이름한다 — 단일 beat N 개 = (ii) N 회 반복 = 위반.

## #4 예산 II (런타임 양) — **base 개정 재분류 유지** (근거 재구성)

- 판정은 **근거 ⑴ 하나로 선다**: 유일 통과 재충전 = E.5 새 kind — ABI
  경계다.
- 종전 근거 ⑵ 「장치 주도 반복 = 예산의 존재 이유」는 **독립이 아니라
  조건부**다 (그래픽 §5.4 갈래에서만 성립) — `budget_axis.md` §0.2 가
  정확히 반대로 세웠다: 증폭·장치 주도 기전 **없이도** 다중 조각 wave 가
  가변량을 만들고, 그것이 예산 II 의 동기다.
- **셋째 근거 (보강)**: 예산 II 는 E.11 판별 기준 균열(「진행 중인 일」 vs
  「관측면 0 ⟹ 새 일 없음」 — `budget_axis.md` §8)·소진 처분·관측면 전부
  **드레인/MMIO/ABI 표면**이라 어느 조각도 opcode 로 표현되지 않는다.

## #5 FP8 dtype — **재조준** (낡은 전제 제거)

- **낡음**: `Di` 제3의 갈래가 dtype 코드점 0 으로 착지하며 `Lf64di` 는
  dtype>0x7 완화를 **더 이상 사지 않는다** — `Lf64di` 는 dtype `0x5`
  claim 이고, `Lf64min` §2 손-핀 개정 표는 `fp_block._doc` 의 **0x5
  조항만** 고친다 (dtype>0x7 조항 무변경 — 두 조항은 같은 문장 안의 별개
  항, JSON 실측).
- ⇒ **FP8 은 dtype>0x7 완화의 단독 첫 수요다.** 「지금 병기」의 대상은
  존재하지 않게 된 「Lf64di 완화 결정문」이 아니라, **`Lf64min` 착지 시의
  `fp_block._doc` 개정 행(같은 손-핀 실물의 이웃 조항)에 붙는 각주**다:
  「dtype>0x7 조항의 유일 소비자 후보 = FP8 2칸」.
- **갈래 신설**: **FP8 storage/CVT-only** (v1.8 이 f16 을 storage/CVT 로
  먼저 실은 선례 — `wt64v1_spec.md` §23.2) vs compute dtype — 전자가 더
  싸고 먼저 올 수 있다.

## #6 복소수 (CADD/CSUB 등) — **기각 유지** (수치 정밀 정정)

CADD/CSUB 는 두 레인 독립 덧셈이라 **DADD 몸체 공유 가능성**이 있다
(DSUB 선례) — 「대수 하나당 +4 즉시 초과」는 +2~3 으로 줄 수 있다.
**P>16 초과 결론은 불변** — 기각 유지.

## #9 멀티캐스트/팬아웃 — **기각 유지** (근거 교체 강제)

- **「결과 뱅크 읽기는 비소멸 … 팬아웃은 소비 축에서 공짜」를 싣지 않는다.**
  ⑴ `ResultBank.tla` 는 읽기 액션이 없을 뿐이다 — 모델 머리가 스코프를
  FAB-3/FAB-4(기입 자격·소유 구간)로 한정한다. 읽기를 모델링하지 않은
  것이지 비소멸을 증명한 것이 아니다 — **침묵으로부터의 추론**이다.
  ⑵ 정본에는 「재조립이 완료되고 **결과가 소비된 뒤**의 같은 태그 재사용은
  적법」이라는 소비 사건이 실재하고, 미완 구간 읽기의 처분은 B.5 미결이다 —
  읽기 의미론 자체가 미결이다.
  ⑶ **fp 축에서 거짓**: fp 셋은 `forbid_opref` 라 결과 뱅크를 읽을 수
  없다 — `di_calculus_extension.md` (다)가 「걱정의 **절반**」만 해소된다고
  적고 「진짜 관문은 fp 연산의 결과 뱅크 읽기 금지」라 명명한 자리다
  (`Di` 원장 13). 「소비 축에서 공짜」는 정수/ALU 소비자 한정 명제다.
- **귀속 정정**: 착지한 `Di` 의 단항 팬아웃 닫힘은 **step 내부 재사용
  하나**다 (`Di` §4) — 비소멸 읽기는 그 닫힘의 부품이 아니다.
- **기각의 더 강한 근거로 교체**: 멀티캐스트는 해설이 아니라 **ISA-9 규범
  본문의 완화 절이 이름으로 든다** — 「멀티캐스트를 포함해 … 명시적 개정이
  선행한다」 (01-isa-asm, 토큰 비증식 규범 본문).

## 11. einsum 축 — 배제 유지, 근거 교체

- **틀린 근거를 싣지 않는다**: 배너는 「전부 착지 완료」가 아니라 **「지위가
  절마다 다르다」**이고, §4 는 판정 연기 → C 계획 이월이다.
- HW-side 3종(SPLAT/SIG_BMM/SIG_TRACE_IIJ)은 base **v1.1 로 이관·착지**
