## 0. 계약의 형태 — 무엇에 대한 전단사인가

### 0.1 기준선의 구성 요소 (커밋 4a8da34 실물)

| # | 요소 | 실물 | 관측원 |
|---|------|------|--------|
| (i) | 명령 실워드열 | word 0 (기본 헤더 32b) + [word 1 = CH, EH ≥ 1 일 때] + EH 워드들. 총 `bh_len` 워드. 워드 $i$ 가 비트 $32i$ (리틀엔디언 워드 배치, §1.3.3) | 정본 §1.3 · `asm/wavetensor_asm.py` `_encode_instruction` |
| (ii) | 태그 | **명명 필드 8종 80b** — wave 32 · 에포크 4 · poison 1 · trace 1 · 예약 10 · LNID 16 · 정밀도 8 · 차원 8. **80b 팩킹 순서는 장치 내부 표현이며 ABI 가 아니다** (§1.4.4) | 정본 §1.4.4 · E.5.1 |
| (iii) | 페이로드 | 64b beat × n | 정본 §4.3 · asm `wave_fragments` |
| (iv) | 조각 머리 | 순번 · 선언 총개수 · 마지막 표시(1b). 순번·총개수의 **폭은 정본이 핀하지 않았다** (E.10 4항 — RTL 단계에서 SlotCap 과 함께) | 정본 E.10 |
| (v) | beat 별 사이드밴드 태그 | 각 조각의 사이드밴드가 태그를 **통째로** 나른다 (재조립 키) | 정본 E.10 5항 |

주의 둘. 어셈블러의 448b 정수는 **컨테이너**다 — `bh_len` 뒤의 0-필러
워드는 포맷의 일부가 아니다 (「순회하되 효과가 없어야 한다」의 대상일 뿐).
그리고 (ii)·(iv)는 **비트열이 아니라 필드 튜플로만 관측 가능하다** — 팩킹
순서가 장치 내부이므로, 이 두 요소에 대한 wire 사상의 지시 대상은
「in-flight 의 비트 자리」가 아니라 **정본이 명명한 필드**다.

### 0.2 전단사의 정확한 진술

wire 패킷은 두 부류의 비트로 이루어진다.

1. **본문부** — in-flight 비트(§0.3 재구성류 제외)와 1:1 재배치 대응.
   비트를 잃지도 더하지도 않는 전단사이며, §2 사상표가 그 전체다.
2. **envelope 신설부** — in-flight 대응이 없는 wire 전용 비트: 플래그
   니블 4b(§4·§5) + EH 길이 벡터 8b(셋째 선언, §7 V4) + 말미 패딩(§6).
   **전부 검사 대상이다** — 무시되는 비트를 두지 않는다 (§5.7 결).

### 0.3 wire 가 나르지 않는 것 — 재구성류 전수

「CRC 만 제외」의 실무적 외연이다. 공통 성질: **값이 다른 비트에서 (계산·
상수·불변식으로) 강제되므로 ingress 가 손실 없이 재구성한다.** CRC 두 종
외의 다섯 항은 사용자 문면(「CRC "만"」)의 엄밀한 확장이었고, ~~사용자 확인
대상이다~~ **→ 확정 (2026-08-29): 승인 — 「CRC 만 제외」의 외연은 아래 7항
전부다** (원장 L1). 승인 근거 둘: 일곱 항의 공통 성질이 위 한 문장으로
동일하다는 것, 그리고 전단사 무손상이 왕복기로 기계 증명됐다는 것(사례
22/22 · 부정 10/10 · 전수 비트 회계 — 커밋 `a9e7f5c` 기록. 그 왕복기는
워크플로 일회성 하네스이고 저장소에 없다, §10).

> **수 세기 주의.** 아래 표는 **7항**이다. 「CRC 두 종 밖」으로 세면
> **다섯**(기본 헤더 `[15:12]` 포함), 「사용자 확정 3항 밖」으로 세면
> **넷**(`[15:12]` 제외) — 기준선이 다를 뿐 같은 표이고, 원장 L1 은
> 뒤쪽 셈(넷)으로 적혀 있다.

| 항 | 재구성 방법 | 근거 |
|----|------------|------|
| W5 OPREF `[23:20]` CRC-4 | 본문 12b 에서 재계산 | 사용자 확정 |
| W8 CH word 1 (32b 전부) | 전 워드에서 재계산 | 사용자 확정 |
| 기본 헤더 `[15:12]` | 상수 0 | 사용자 확정 |
| 컨테이너 필러 (워드 `bh_len`..13) | 상수 0 — 포맷의 일부가 아님 | §0.1 · **L1 확정** |
| beat 별 태그 사본 (80b × n) | 불변식 「조각은 같은 태그를 공유한다」(§4.3) — 패킷 태그의 복제 | **L1 확정** |
| 조각 머리 (순번·총개수·마지막) | §2.3 재구성 규칙 — 완결 파도 단위 패킷 불변식에서 강제 | **L1 · L7 확정** |

### 0.4 채널 전제

- WebRTC data channel 은 **reliable + ordered** 로 협상한다
  (`maxRetransmits`/`maxPacketLifeTime` 미설정, `ordered: true`).
  §2.3 페이로드 재구성과 §6 패딩 산술이 이 전제 위에 선다.
- **1 SCTP 메시지 = 1 패킷.** 패킷에 총길이 필드가 없는 이유다 — 메시지
  경계가 패킷 경계다. 자기구획(self-delimiting) 재설계는 EXTF 후속(§4).
- wire 구간 무결성·기밀성은 DTLS 가 덮는다 — in-flight 검산(CRC-4·CH)은
  ingress 재계산으로 자기 구간을 새로 덮는다 (계층별 검사 배치, 제안 기록 ②①).

## 1. 패킷 구조 (요약)

```
byte 0        [7:6] RDE 모드   [5] EXTF(명명 예약)   [4] 예약   [3:0] ⟷ bh[11:8]
byte 1        ⟷ bh[31:24]  (opcode 하위 8b)
byte 2        ⟷ bh[23:16]  (next_hdr 4b ∥ flags 4b)
byte 3        ⟷ bh[7:0]    (bh_len — CH 포함 값 그대로)
byte 4        EH 길이 벡터  [7:6] EH1 · [5:4] EH2 · [3:2] EH3 · [1:0] EH4
byte 5..14    태그 80b (10바이트 — §2.1 T 행들, E.5.1 합동)
byte 15..     EH 구역 — 비트팩 (OPREF 첫 워드만 28b, 나머지 워드 32b)
이어서        페이로드 구역 — 64b beat × n, 순번 오름차순
말미          패딩 0..7b (현행 유도값 {0,4}) — 값 0, 엄격 검사
```

최소 패킷 = 15바이트 (EH 0 · 페이로드 0). 15바이트 미만은 거절.

## 2. 전 비트 자리 사상표 (핵심 산출물 ①)

**표기.** wire 비트 지수 $p$ = 패킷 시작부터 0-기반, 바이트 $B$ 의 비트
$b$ (7 = MSB) 에 대해 $p = 8B + (7-b)$ — **바이트 안 MSB-first** (네트워크
관례). in-flight 명령 워드 $m$ 의 비트 $j$ 는 `I[m][j]`, in-flight 절대
비트 지수는 $32m + j$. 태그·조각 머리는 필드 이름으로 지시한다 (§0.1).
사상 행이 「A ↔ B」이면 A 의 첫(최상위) 비트가 B 의 `[hi]` 다.

### 2.1 고정부 (p = 0..119, byte 0..14)

| p | wire 필드 | in-flight 대응 | 비고 |
|---|-----------|----------------|------|
| 0–1 | RDE`[1:0]` | **없음 (envelope 신설)** | §5. p0 = RDE`[1]` |
| 2 | EXTF | **없음 (envelope 신설)** | §4. 반드시 0 |
| 3 | RSV0 | **없음 (envelope 신설)** | 반드시 0 |

태그 10바이트는 **E.5.1 세-워드 직렬화의 워드 오름차순 · 워드 내 상위
필드 먼저** 순서와 합동이고, E.5.1 이 여백으로 둔 TAG2`[31:16]` 예약만
나르지 않는다 (그 16b 는 워드 표면의 여백이지 태그 비트가 아니다).
§1.4.4 「태그를 나르는 호스트 표면은 워드 정렬된 명명 필드로 나른다 —
80비트를 통짜 비트열로 싣지 않는다」를 wire 가 그대로 상속한 것이며,
**80b 팩킹 순서(장치 내부)는 wire 의 지시 대상이 아니다.**

### 2.2 EH 구역 (p = 120 .. 120 + 32W − 4c − 1)

$K$ = EH 개수, $wc_k$ = EH$k$ 워드 수, $W = \sum wc_k$, $c$ = OPREF 개수.
EH$k$ 의 in-flight 첫 워드 지수 $m_k = 2 + \sum_{j<k} wc_j$ (word 1 = CH).
EH$k$ 의 wire 시작 오프셋 $q_k = 120 + \sum_{j<k}(32\,wc_j - 4\,[\text{EH}j{=}\text{OPREF}])$.

**wire 는 EH 를 사슬 순서 그대로, 각 EH 의 워드를 워드 오름차순 그대로
(예외: IMM64, 아래), 각 워드를 `[31]`→`[0]` MSB-first 로 낸다.** 파스
조향은 사슬 선언이 한다 — EH$k$ 의 종류는 앞선 next_hdr (EH1 은 byte 2 의
`bh.next_hdr`)가 **먼저** 알려 주므로, 28b/32b 분기가 파스 전에 결정된다
(§1.3.3 「사슬을 잇는 것은 여기다」의 wire 재사용 — 헤더의 「영역이 먼저
온다」와 같은 결이되, 워드 내부 재배치 없이 성립한다).

**(a) 첫 워드 — OPREF 이 아닌 모든 종류 (32b).** 슬라이스 내 오프셋
$u = 0..31$: wire $q_k + u$ ↔ `I[m_k][31−u]`.

**(b) 첫 워드 — OPREF (28b, CRC 니블 부재).**

| u (wire, $q_k$+u) | in-flight | 내용 |
|----|-----------|------|
| 0–7 | `I[m][31:24]` | LBID |
| — | `I[m][23:20]` | **CRC-4 — wire 부재.** ingress 재계산 (R2) |
| 8–11 | `I[m][19:16]` | src_kind |
| 12–15 | `I[m][15:12]` | next_hdr |
| 16–19 | `I[m][11:8]` | 자기 종류 (= 0x7) |
| 20–27 | `I[m][7:0]` | 워드 수 (= 1) |

**(c) 후속 워드 (w = 1..wc−1, 32b MSB-first).** wire
$q_k + 32w - 4[\text{OPREF}] + u$ ↔ `I[m_k + w][31−u]`. **단 하나의 예외 —
IMM64 (종류 0x4, wc = 3): wire 는 `I[m+2]` 를 `I[m+1]` 보다 먼저 낸다.**

**(d) 바이트 순서 총칙 — 필드 단위 big-endian.** 워드는 운반 단위이지
필드가 아니다. 한 필드가 여러 워드에 걸치면 (현행 카탈로그에서 유일:
IMM64 의 64b 즉치, in-flight w1 = 하위 32 · w2 = 상위 32) wire 는 **필드의
MSB 부터** 낸다 — 즉 IMM64 본문은 wire 에서 `v[63:56] … v[7:0]` 의 정직한
8바이트 BE 필드다. 워드 오름차순을 고수하면 64b 값이 wire 에서
middle-endian 이 되고, 그것이 과업이 지목한 「w1=하위/w2=상위 뒤집힘
사고」의 상설 지뢰다. 이 역전은 (c) 예외 한 줄로 사상표에 남는다.

**(e) 종류별 첫-워드 본문의 비트 자리 (참조 — (a)/(b)의 전개).**
어셈블러 실물(`_encode_eh`) 기준. wire 는 이 자리들을 그대로 나른다.

| 종류 | 코드 | wc | 본문 자리 (in-flight) |
|------|-----|----|----------------------|
| PORT | 0x1 | 1 | w0`[31:16]` = dest_node_id (LNID, 축자) |
| IMM16 | 0x2 | 1 | w0`[31:16]` = 즉치 |
| IMM32 | 0x3 | 2 | w1 = 즉치 32b |
| IMM64 | 0x4 | 3 | w1 = v`[31:0]` · w2 = v`[63:32]` — **wire 는 w2 먼저 (d)** |
| MEM | 0x5 | 2 | w0`[31:20]` = stride(12) · w0`[19:16]` = addr_mode(4) · w1 = 오프셋 32b |
| SUBSCRIPT | 0x6 | 2 | w0`[31:16]` = o축 · w1`[31:16]` = a축 · w1`[15:0]` = b축 (축 $i$ 가 니블 $4i$) |
| OPREF | 0x7 | 1 | (b) 표 — LBID 8 · src_kind 4. CRC 부재 |

카탈로그 밖 종류(0x0 제외 0xA–0xE 및 미배정)는 **wire 층에서 거절**한다
(V6) — 28b/32b 분기와 보폭을 알 수 없으므로 파스가 성립하지 않고, 버전
스큐가 조용한 오프레임 대신 크게 실패한다 (원장 L8).

### 2.3 페이로드 구역 (p = r₀ .. r₀ + 64n − 1, r₀ = 120 + 32W − 4c)

beat $t$ ($t = 1..n$, wire 등장 순서): wire $r_0 + 64(t-1) + u$ ↔
$D_t[63-u]$ — beat 64b 는 **하나의 필드**로 BE. $n$ 은 잔여 길이에서
유도된다 (V7) — 페이로드 개수 필드는 없다.

**beat 는 필드이고 파도는 필드가 아니다.** 넓은 파도(wide payload)의 lane
배치는 opcode 별 계약(`lanes_to_frags` 핀)이지 wire 필드가 아니므로, wire
는 beat 순서를 in-flight 방출 순서(§0.1 (iii), idx 오름차순) 그대로 두고
beat 내부만 BE 로 뒤집는다 — IMM64 와 처분이 갈리는 이유는 IMM64 의 64b
가 **하나의 in-flight 필드**이기 때문이다 (2.2 (d)).

**조각 머리 — wire 부재, 전량 재구성 (R5).** 패킷은 **완결 파도 하나**를
순번 오름차순으로 싣는다는 불변식 아래, 순번 $= t$ · 선언 총개수 $= n$ ·
마지막 표시 $= (t = n)$ · beat 태그 = 패킷 태그(byte 5..14)로 강제된다.
**이 전제 — 「패킷 = 완결된 파도 하나」 + reliable/ordered 채널(§0.4) — 는
확정이다 (2026-08-29, 원장 L7).** in-flight 조각 머리의 폭이 정본에 핀돼
있지 않으므로(E.10 4항) 이것은 비트 사상이 아니라 **필드 사상**이며, 부분
파도·비순서 스트리밍이 필요해지는 날은 EXTF 후속으로 명시 운반 형태(순번
8 · 총개수 8 · 마지막 1)를 연다 (§4).

## 3. Q1 — Store-and-Execute 접면: 「점프」의 사상은 명령 링 투입이다 (②)

### 3.1 사상

이 기계에 PC 는 없다 (§2.3 — 「PC 도 fetch 도 재발행도 장치 주도 재투입
기구도 없다」). 제안 원문의 「쓰기 후 즉시 PC 를 해당 위치로 점프」는
envelope 층(수신 호스트 A)의 의미론이며, 가속기에 대한 사상은 다음
하나다:

> **RDE Store-and-Execute (10) = DVMA 기입을 완결한 뒤, 기입한 이미지의
> 명령 본문 시작 주소** (E.5.4 의 `SD_BODY` 가 뜻하는 그것 — 기입 시작
> 주소가 아니라 이미지 안에서 word 0 이 놓인 주소이며, 이미지 배치별
> 오프셋은 §5 가 핀한다) **를 `SD_BODY_LO/HI` 로, 패킷 태그(byte 5..14)를
> `SD_TAG0–2` 로 갖는 명령 디스크립터(E.5.4)를 명령 큐(SQ)에 쓰고 tail 을
> 전진시키는 것.**

「해당 위치로 점프」가 정확히 「그 위치를 본문 주소로 갖는 SD 의 정규
투입」이 된다 — E.5.4 가 본문을 **참조로** 나르기로 이미 정해 두었기
때문에, 이 사상은 새 기구가 아니라 기존 표면의 재사용이다. 장치는 wire
의 존재를 모른다: HIU 매체 추상(3장 — 어떤 full-duplex 매체든) 아래에서
장치가 보는 것은 여전히 명령 큐 하나이고, envelope 종점(A 측 daemon /
ingress)은 **호스트 역할로** 큐에 쓴다. 발화 원천은 하나로 남는다 —
wire 는 큐의 **둘째 기입자**를 더할 뿐 **둘째 발화 원천**을 더하지 않는다.

### 3.2 §2.3 위에 선 다섯의 보존 논증

§2.3 해설이 열거한 다섯 (02-fabric-alu.typ)에 대해 하나씩:

1. **드레인에 기계 모드가 불필요** — 투입을 멈추는 가장 싼 방법이 「주지
   않는 것」임은 불변이다. 다만 멈추는 주체에 envelope 종점이 합류하므로
   **드레인·lease 전환 중 RDE 00/10 투입 보류가 envelope 계약**이 된다
   (3.7.2 「드레인 후 교체」· `remote_accelerator_access.md` 의 lease 종료
   시 drain/TLB flush 항과 접합). 기계 쪽 문면은 안 바뀐다.
2. **E.11 관측면 = 드레인 완주의 증거** — 모든 발화가 여전히 큐를
   지나므로 관측면의 완전성이 유지된다. wire 가 큐를 우회하는 발화를
   하나라도 만들면 이 증거가 그 자리에서 죽는다 — 그래서 우회 금지는
   권고가 아니라 이 포맷의 정의다 (RDE 10 의 「실행」에 다른 이행은 없다).
3. **FAB-6 진행성 연쇄의 호스트 앵커** — 연쇄의 끝은 여전히 호스트 큐
   소비다. envelope 는 큐 앞단이므로 앵커 위치가 움직이지 않는다.
4. **토큰 압력 유계 (자가 증폭 경로 부재)** — wire 패킷 1개는 SD 투입
   최대 1건을 낳고, **장치는 wire 패킷을 생성하지 않는다** (완료 방향
   wire 표면은 이 문서 범위 밖 — L5). 증폭 계수 ≤ 1 이 구조로 성립한다.
5. **호스트는 자기가 낸 태그를 전부 안다** — 태그 저작이 원격 M 으로
   옮겨가는 것이 이 축의 유일한 실질 변형이다. ⑤ 를 보존하는 길은 둘
   이었다: **A 측 호스트 역할이 wire 로 들어온 태그를 원장에 기록**하거나
   (ingress 태그 원장), 에포크 한 세대 안의 태그 유일성을 M 에 ABI 의무로
   위임하거나. **→ 확정 (2026-08-29, 원장 L6): ingress 태그 원장을
   채택하고 M 에의 ABI 위임은 기각한다.** 근거: 위임은 M 의 성실성에
   기대지만 원장은 A 측에서 실제로 검증 가능해 ⑤ 를 **문면이 아니라
   기전으로** 보존한다. B.5 「개시 wave 태그의 원천」과 같은 부류라 **같은
   서명으로 닫되**, 집행(원장의 자료구조·수명·에포크 회수 규약)은 **다음
   호스트-ABI 뭉치**(#19 계보 후속 회의)에 편성한다. 이 의무를 적지 않으면
   ⑤ 만 조용히 깨진다.

### 3.3 DVMA 계보 정합

- 기입 경로: RDE 01/10 의 store 는 **장치-내 변환·페이지 소유권 표**
  아래의 가상 주소 기입이다 (3장 DVMA — 변환은 장치 안에서 완결, 호스트
  IOMMU 무전제; E 페이지 소유권 표). envelope 는 그 규약을 우회하는 문이
  아니다 — E.5.4 3항(「디스크립터는 그 규약을 우회하는 문이 아니다」)의
  wire 판.
- 목적지 주소: 사용자 확정 5바이트 헤더에 주소 필드가 없으므로, ~~**채널
  결속 DVMA 창 + 세션 커서**를 제안한다~~ **→ 확정 (2026-08-29, 원장 L2):
  채널 결속 DVMA 창 + 세션 커서를 채택한다** — 순차 기입이고, 커서는
  envelope 세션 상태다(패킷이 아니라 채널이 자리를 안다). **패킷별 주소
  지정은 v1 에서 닫혔고 EXTF 후속**이다 (§4).
- lease 접면: mTLS·lease·heartbeat 는 `remote_accelerator_access.md` 의
  control-plane 몫이고, 이 포맷은 그 lease 가 이미 성립한 뒤의
  user-plane 이다. lease 전환 시 context_switch·TLB flush·drain 의무는
  그 메모의 항을 그대로 상속한다.

### 3.4 신뢰 경계

M→A wire 는 **호스트 소프트웨어끼리의 경계**다. 장치의 신뢰 경계는
움직이지 않는다 — 장치가 받는 것은 여전히 SD 표면이고, 그 표면의 기존
검사(예약 엄격 0 · poison 엄격 0 · malformation 판정)가 wire 유래 명령에
그대로 선다. wire 층은 프레이밍을 판정하고 **의미는 판정하지 않는다** (§7).

## 4. Q3 — 예약 플래그 비트의 명명 (③)

byte 0`[5]` (p = 2) 를 **EXTF — 「확장 프레이밍 후속(extended framing
follows)」** 으로 명명한다. **지금 정의하지 않는다** — §5.7 엄격 예약의
결: 자리에 이름만 붙이고, 뜻은 필요가 먼저 확인된 뒤의 명시적 개정이
claim 한다 (§1.3.1 배정 절차 그대로). 오늘의 계약은 하나다: **반드시 0
이고, 비0 은 거절 + envelope loud.**

이름이 가리키는 성장 축 (claim 후보의 예시이지 정의가 아니다): EH > 4
형상(길이 벡터 4칸의 초과 — §1.3.1 「이 상한은 형상 파라미터이지 ISA
상수가 아니다」를 wire 가 도로 굳히지 않기 위한 자리) · 패킷별 DVMA 주소
(L2) · 부분/비순서 파도 스트리밍 (L7) · **명령 없는 데이터 전용 패킷
(L4)** · **자기구획(self-delimiting) 프레이밍 재설계 (§0.4)** · wc > 3
종류 (L9).

**2026-08-29 확정과의 관계.** 이 목록의 L2·L4·L7 은 더는 미결이 아니다 —
셋 다 **v1 에서 닫는 쪽으로 확정**됐고(채널 결속 창 · `00` = DIRECT ·
완결 파도 단위 패킷), 그 결과 셋의 반대 수요가 갈 곳이 정확히 여기다.
확정이 성장 축을 지운 것이 아니라 **어디로 가야 하는지를 못박았다.**
오늘의 계약은 그래도 하나다 — EXTF 는 반드시 0 이다.

byte 0`[4]` (RSV0) 는 **이름 없는 엄격 예약**으로 남긴다 — 반드시 0.

## 5. Q5 — RDE 2비트 값 공간 (⑤)

| 값 | 이름 | 의미 | 처분 |

| `00` | DIRECT | **비-RDE 직접 제시** — ingress 사설 스테이징에 본문을 놓고 SD 를 투입한다. DVMA 계약 흔적을 남기지 않는다 | 정상 · **확정 (L4)** |
| `01` | RDE-S | **DVMA Store** — 채널 결속 창(L2)의 커서 위치에 [태그+명령+페이로드] 이미지를 기입만 한다. SD 투입 없음 | 정상 · **확정 (L2·L3)** |
| `10` | RDE-SX | **DVMA Store-and-Execute** — `01` 의 기입 + 그 이미지의 본문 시작(기저 + `0x0C`, 아래 배치 표)을 `SD_BODY` 로 갖는 SD 투입 (§3.1) | 정상 · **확정 (L2·L3)** |
| `11` | — | 미지 | **거절 + envelope loud** (§5.7 엄격 관례 — 미지 값 처분). 이름 없는 예약. claim 은 명시적 개정 |

- 제안 원문의 「Store XOR Store-and-Execute」는 `01`/`10` 이 서로 다른
  부호점이라는 사실로 **구조로** 성립한다 — 두 모드가 동시에 서는 인코딩
  자체가 없다.
- 제안 원문의 「`00` = 순수 데이터?」 물음표의 처분 — **확정 (2026-08-29,
  원장 L4): `00` 은 비-RDE 직접 제시다.** 명령 없는 데이터 전용 패킷은
  v1 에서 표현 불가 — 모든 패킷은 명령 정확히 1개를 싣는다 (bytes 0–3
  상시 존재). 물음표는 「데이터 전용 부호점을 하나 산다」가 아니라 「그
  수요는 v1 밖이다」로 닫혔고, 데이터 전용은 **EXTF 후속**이다 (§4).
- `01` 의 저장 이미지 배치는 ~~**SD-형 이미지**를 제안한다~~ **→ 확정
  (2026-08-29, 원장 L3): SD-형 이미지 — 태그 3워드 선두, `SD_BODY` =
  이미지 기저 + `0x0C`.** 근거는 둘째 코덱을 만들지 않는 것이다 (E.5.1
  「둘째 직렬화를 다르게 만들면 호스트 쪽에 태그 코덱이 두 벌 생긴다」).
  배치와 오프셋을 못박는다:

  | 이미지 상대 | 내용 |
  |------------|------|
  | `+0x00`‥`+0x0B` | TAG0‥TAG2 — E.5.1 세-워드 직렬화 |
  | `+0x0C`.. | 명령 본문 word 0‥bh_len−1 (CH·CRC 재계산 완료본) |
  | 본문 끝.. | 페이로드 beat 들 (있으면) |

  **RDE 10 의 `SD_BODY` = 이미지 기저 + `0x0C`** — 기입 시작 주소 그대로가
  아니다. E.5.4 의 `SD_LEN = bh_len` 걷기는 본문 주소에서 시작하므로,
  기저를 그대로 주면 장치가 TAG0–2 세 워드를 명령 word 0–2 로 읽는다.

  **기각된 갈래 (2026-08-29) — 본문-선두 이미지** (본문을 `+0x00` 에 놓고
  태그를 뒤에). 이 갈래는 `SD_BODY` 오프셋 0 을 얻는 대신 E.5.1 이 세운
  **완료 쪽과의 상대 오프셋 재사용**을 잃는다. 오프셋 상수 하나를 아끼려고
  두 방향의 이미지 규약을 갈라놓는 거래라 기각한다 — 이 절이 SD-형을 고른
  이유(코덱 한 벌)와 같은 이유다.

## 6. 패딩 규칙 (⑥)

- **길이**: $P = (8 - (T \bmod 8)) \bmod 8$, $T$ = 비패딩 총 비트 수
  $= 120 + 32W - 4c + 64n$. $120 \equiv 32W \equiv 64n \equiv 0 \pmod 8$
  이므로 **$P = (4c) \bmod 8$ — 현행 카탈로그에서 $P \in \{0, 4\}$**
  (OPREF 홀수 개일 때만 4) #유도. 규칙 자체는 일반형(0..7)으로 둔다 —
  CRC 니블을 나르는 종류가 늘면 $c$ 의 정의가 넓어진다.
- **값**: 0.
- **검사**: **엄격.** 비0 패딩은 거절 + envelope loud. 근거는 §5.7 —
  무시되는 비트는 검사받지 않고 통과하는 비트이며, wire 말미의 자유
  비트는 정확히 은닉 채널의 자리다.
- 패딩은 **패킷 말미 한 곳**뿐이다. EH 구역과 페이로드 구역 사이를 바이트
  재정렬하지 않는다 — 정렬 지점이 둘이면 규칙이 둘이고, 낭비도 는다
  (헤더가 세운 「낭비 0비트」의 연장).

## 7. ingress 절차 (⑦) — 파스 · 검산 · 재계산 · 투입

### 파스 (P)

- **P1** 길이 ≥ 15B 확인, byte 0..14 고정부 해석.
- **P2** 사슬 조향 걷기: 종류 선언은 앞선 next_hdr (EH1 은 byte 2)에서
  얻고, OPREF 면 28b · 아니면 32b + 후속 워드들을 소비한다. IMM64 는
  wire 역전(2.2 (c) 예외)을 알고 소비한다. 걷는 도중 입력이 소진되면
  V8 절단이다.
- **P3** 잔여 비트에서 $n = \lfloor \text{잔여}/64 \rfloor$, 패딩 분리.

### 검산 (V) — 전건 실패 = 거절 + envelope loud (장치 fault 아님)

- **V1** 길이 ≥ 15B.
- **V2** byte 0`[5:4]` = 0 (EXTF·RSV0) · RDE ≠ `11`.
- **V3** LEN 벡터는 비0 접두열이다 — `00` 뒤에 비0 이 오면 거절.
  $K$ = 비0 칸 수, $W = \sum$LEN.
- **V4** **삼중 선언 교차 검산 (wire 연장)**:
  (next_hdr = END) ⟺ (K = 0) ⟺ (bh_len = 1), 그리고
  **bh_len = 1 + (K > 0 ? 1 : 0) + W** — bh_len 은 CH 를 포함한 값
  그대로 wire 를 탔고, CH 는 wire 에 없어도 회계에는 있다.
- **V5** EH$k$ 마다: 사슬이 지목한 종류 = 자기 종류 필드 `[11:8]` ·
  카탈로그 보폭(2.2 (e)) = LEN$_k$ = 자기 워드 수 필드 `[7:0]`.
  (in-flight 두 겹 + wire 벡터 = **셋째 선언**의 대조 — §4.2 관용구의
  wire 연장.)
- **V6** 카탈로그 밖 종류 → 거절 (버전 스큐 fail-loud, L8).
- **V7** 잔여 $\bmod\ 64 = P$ (§6 유도값과 일치) · 패딩 비트 전부 0.
- **V8** **EH 구역 내부 절단** — P2 가 선언량(LEN 벡터·사슬이 지목한 $W$
  워드, OPREF 28b 감산 반영)을 소진하기 전에 입력이 끝나면 거절.
  V1(15B 미만)과 V7(EH 구역 이후 잔여 산술)이 덮지 않는 자리의 명시
  항이다 — 「전건 실패 = 거절」 총칙의 해석에 맡기지 않는다 (무시되는
  비트를 두지 않는 전수 열거의 결, §0.2).

### 재계산·재구성 (R)

- **R1** `I[0]` 재조립: byte 0`[3:0]`→`[11:8]`, byte 1→`[31:24]`,
  byte 2→`[23:16]`, byte 3→`[7:0]`, **`[15:12]` := 0**.
- **R2** EH 워드 재조립. OPREF: 본문 12b 의 논리 비트열
  LBID`[7]`‥`[0]` ∥ src_kind`[3]`‥`[0]` (MSB-first) 에 대해
  $G(x) = x^4 + x + 1$, 비반사·초기값 0·최종 XOR 없음으로 CRC-4 를
  재계산해 `[23:20]` 에 삽입 (§1.4.6 그대로 — 물리 슬라이스 순서가
  아니라 **논리 순서**다).
- **R3** IMM64 워드 순서 복원 (wire w2-먼저 → in-flight w1 = 하위).
- **R4** K > 0 이면 CH: 메시지 = word 0 ∥ word 2‥(bh_len−1) 를 **워드
  오름차순, 각 워드 리틀엔디언 4바이트**로 이은 바이트열 (§1.3.4 그대로).
  CRC-32C (0x1EDC6F41, 반사·init `0xFFFFFFFF`·XOR `0xFFFFFFFF`) → word 1.
  ⚠️ **wire 바이트열 위에서 계산하면 틀린다** — wire 는 BE 재배치본이다.
  재구성된 in-flight 워드 위에서만 계산한다. (자기시험 기지값: §1.3.4 —
  "123456789" → `0xE3069283` 등.)
- **R5** beat $t$ 마다 조각 머리 재구성: 순번 $t$ · 총개수 $n$ · 마지막
  $(t = n)$ · beat 태그 = 패킷 태그.
- **R6** (448b 컨테이너 구현이면) 워드 bh_len..13 := 0.

### 투입 (X)

- **X1** RDE `00`: 본문을 ingress 스테이징에 놓고 SD (kind 0x02, 태그
  워드, 본문 참조, SD_LEN = bh_len) 작성 → SQ tail 전진. 태그를 **ingress
  태그 원장에 기록** (§3.2 ⑤ — 2026-08-29 확정, 원장 L6. 원장의 구체
  규약은 다음 호스트-ABI 뭉치 몫이고, 여기서는 **기록한다**는 의무만
  선다).
- **X2** RDE `01`: 채널 결속 창 커서에 SD-형 이미지 기입 (§5 배치 표 —
  태그 3워드 ∥ 본문 ∥ 페이로드; L3). 투입 없음.
- **X3** RDE `10`: X2 + **이미지 기저 + `0x0C`(본문 시작, §5)** 를
  `SD_BODY` 로 X1 의 투입. 페이로드 beat 는 재구성된 조각 머리·태그와
  함께 입력 파도 경로로 제시.

### 검사 경계 — 이중 판정은 의도다

wire 거절(V1–V8)은 **envelope 층 오류**다 — 장치 FAULT_STATUS 를 세우지
않고, 송신자(M)에게 크게 알린다. 장치는 재구성물을 **디코드 경계에서
다시 판정**한다 (하드웨어는 어셈블러도 envelope 도 신뢰하지 않는다 —
§1.7.3 restrictive-first). 역으로 **태그 필드 정책(poison·예약 10b 의
엄격 0)은 wire 파스가 검사하지 않는다** — 그 판정점은 SD 표면 하나다
(E.5.4). 같은 부류로 **마지막 EH 의 next_hdr ≠ END 도 wire 는 거절하지
않는다** — V4·V5 는 사슬을 LEN 벡터·bh_len 과 회계 대조할 뿐이고, 종료
표식의 정오는 in-flight 걷기 의미론이라 판정점이 디코드 경계다 (걷기가
bh_len 을 넘으면 malformation — E.5.4 6항 · §1.3 「조용한 절단 금지」.
왕복기 gap probe 로 투명 운반 실증). 검사가 두 곳이면 드리프트한다
(§1.4.4 의 축).

> **확정 (2026-08-29) — 현행 유지. wire 층 V 항 신설은 기각한다.**
> 「마지막 EH 의 next_hdr ≠ END」를 wire 가 잡게 하자는 갈래(V9 신설)는
> 서지 않는다: 이 판정은 프레이밍이 아니라 **의미**이고, wire 는
> 프레이밍을 판정하고 의미는 판정하지 않는다(§3.4 · 이 절의 경계). wire
> 가 의미를 판정하기 시작하면 **두 층이 서로 다른 답을 낼 창**이 열리고,
> 그 창은 정확히 이 절이 닫으려던 것이다. 그러므로 처분은 **투명 운반 +
> 디코드 경계 단일 판정** — wire 는 그 니블을 있는 그대로 나르고, 정오는
> 장치가 한 번만 판정한다.

## 10. 검토 경로

**착지 자리 — 확정 (2026-08-29).** 승격 시 정본에 앉을 자리는 ~~(제안)
부록 신설 또는~~ **3장 HIU 의 원격 표면 절**이다. **부록 신설은 기각** —
이 포맷은 기계의 인코딩이 아니라 **호스트 표면**이라 1장이 아니고, 같은
이유로 부록에 격리해도 안 된다: DVMA(3장)·매체 추상(「어떤 full-duplex
