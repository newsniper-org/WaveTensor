## 0. 요약과 권고

**문제**: nearest/bilinear 텍스처 샘플링(타일 축 — `graphics_tiling_axis.md`
의 소비자)을 이 기계에서 어떻게 표현하는가.

**거처 판정 (확정)**: 텍스처의 거처는 **결과 뱅크의 LBID 구간**(조각열로
채워진 연속 슬롯 구간)이다. MEM 상주 갈래(C)는 삼중으로 사망했다 (§1).

**권고 (조건부)**:

1. **A0(무확장 — 호스트 gather + `0x7A`)를 기준선으로 세우고, 좌표/텍셀
   재전달 경제를 실측한 뒤에만** A1/A1′ 중 하나를 채택한다. bilinear 는
   기존 opcode 로 발화 1회에 표현된다(§2 A0) — 신규 원시연산의 근거는
   표현력이 아니라 **경제**이고, 그 경제는 아직 재지 않았다(§9 원장 1).
   표현력 논증이 성립하는 자리는 A2(장치 생산 좌표)뿐이며 이월분이다.
2. **A1′(2-opcode + PRECISION 치수·폭)를 A1 과 나란히 산정한다** —
   「텍셀 폭을 태그가 나른다」는 A1 의 약점이 통째로 사라지는 갈래를 산정
   없이 접을 수 없다.
3. **이 제안의 실제 관문은 §8(구간 메타데이터 — C2 갈래 결정)이다.**
   그 결정 없이 G9 연결 문장은 서지 않는다. **→ 확정 (2026-08-28): 갈래
   ⑵ 방향 채택, 발효는 명세 승격 시점 (§10 항 1).**

## 1. 거처 판정 — 살아남은 것과 죽은 것

### 1.1 갈래 C (MEM 상주) — 사망 확정, 삼중

1. **§4.2.3 종류별 반복 규칙** — MEM 은 명령당 하나다. 샘플당 텍셀 4개
   읽기가 인코딩되지 않는다.
2. **MEM 본문은 정적 주소다** — 좌표 의존(동적) 주소의 **인코딩 자체가
   부재**하고, 그것을 열면 §4.4.4 의 전제(컴파일러의 겹침 증명)가 무너진다.
   (정정 반영: 「§4.4.4 와 정면 충돌」이 아니라 이 형태가 정확하다 —
   결론 불변.)
3. **§1.4.2 커플링 함정** — 메모리 경로 출력은 계수의 정의역 밖이라
   비증식이 문면으로만 남는다 (「메모리로 쓰면 되잖아」 함정).

### 1.2 살아남은 판정 (검토 재현 확인)

- **§2.3 무접촉** — 발화의 유일한 원천(호스트 명령 큐) 유지. 출력은 조각열
  하나(ISA-9 ③), 다섯 조건의 구성적 만족 성립. T=1 조각열은 `Di` §1.1
  인코딩상 적법, ACCTGT 무플래그도 §1.3.1 비대칭으로 적법.
- ~~**읽기 축은 무규범 지대다**~~ → **낡았다. 뒤집는다 (2026-08-30).**
  정본 환류 W5 가 §2.4.1 에 **5항**을 세웠고 그 항의 주어가 정확히
  `src_kind=1` OPREF 의 LBID — 이 제안의 텍스처 읽기 기전 그 자체다
  (`02-fabric-alu.typ:373-380` 「읽기측도 같은 구간을 본다」). 5항이 주는 것
  넷: 구간 시작 = LBID · 길이 = 그 구간을 채운 조각열의 **선언 총개수** ·
  **폭의 선언자는 생산자 하나** · **미완 구간 읽기는 loud fault**.
  **⇒ 이 정정은 논거를 약화시키지 않고 강화한다** — 「무규범 지대에 새
  의미론을 짓는다」가 **「선 규범의 첫 실수요다」**가 된다. 데이터 의존 읽기
  선례 0건은 그대로 유효 (`0x68`/`0x6A` 태그 매칭은 신원 CAM 이지 페이로드
  색인이 아니다, `0x75` seed ROM 은 비아키텍처).
- **🆕 그 승계와 함께 오는 전건 하나** — 5항이 세운 loud fault 의 **관측면이
  미배정**이다 (`02-fabric-alu.typ:401-416` 「이 신호가 자기 비트를 갖는지 기존 축에 접히는지는 *아직 규정되지 않았다*」).
  `FAULT_STATUS` 열아홉 축이 전부 쓰기측이라 읽기측 원천이 없고, B.5 「장치
  전역 fault 비트맵의 비트 배정」에 새 입력으로 올랐다. 정본 §5.6 3항이
  「폴딩 여부는 신호마다 명시적으로 규정한다」를 요구하므로 **이 확장이 그
  신호를 쓰면서 비트를 말하지 않으면 그 규범을 어긴다.** 비트 번호는
  드라이버와 공유되는 순간 ABI 이므로 **호스트 ABI 합의 부류**다 — §7 전제
  원장에 신설한다.
- **LBID 8b 벽 비저촉** — 텍스처는 LBID **하나**(구간)로 이름한다.
  타일-당-LBID 명명이 아니므로 256 벽(`graphics_tiling_axis.md` §4.5)을
  밟지 않는다.
- **빈 조각 결손(그래픽 메모 §4.4) 무관** — 샘플링은 채움 완료 후 읽기다.
- **§5.1 잔여 수용 1항 불증가** — 본 제안의 모든 갈래가 PORT 필수(EH ≥ 1).
  EH 없는 명령이 늘지 않는다 (`Ctrl` 제안의 따름정리와 같은 형태).
- **0x4## 영역 배정** — #24 신규 확장의 자리(1024칸, 처음부터 열림). 영역은
  배정 절차의 규범이지 하드웨어 판정이 아니다.

## 2. 갈래 전수

### A0 — 무확장 기준선 (신규 opcode 0) — **신설, 반드시 그린다**

A1 의 좌표는 파도 페이로드 = **호스트 저작**이고 텍스처도 호스트가 채웠으며
기계는 결정론적이다(§2.5). 즉 **호스트는 자기가 낼 모든 샘플의 텍셀 4개를
명령 조립 시점에 안다.** 그러면:

> 샘플당 호스트가 가중치 4개(u,v 를 아니까)와 텍셀 4개를 계산해 잔여
> 28레인 zero-pad(`Di` §2 패딩 규약 그대로)로 `0x7A FDOT32_CR` 한 발화에
> 싣는다 — **기존 opcode 하나로, 발화 1회에, PACK_FINAL 값 계약까지
> 공짜로** bilinear 가 된다.

이것은 `Di` 계보의 표준 lowering 기구(리만 「격자는 데이터다」) 그 자체다.
⇒ **「lowering 만으로 불가 ⇒ 별도 원시연산」 논증은 A1 형태에서
반증된다.** A1 의 존재 이유는 경제뿐이다: 샘플당 페이로드 약 1,024b
(`0x7A` 캡처) 대 64b(좌표) — 약 16×. **미측정** (§9 원장 1).

### A1 — 좌표-파도 신규 opcode 하나 + IMM16

- 파도 페이로드 = 호스트 저작 **좌표열**(샘플당 64b). 장치가 텍스처
  구간에서 텍셀 4개를 모아 필터한다.
- EH 4슬롯 (여유 0): PORT + OPREF(`src_kind=1`, 텍스처 구간 LBID) +
  ACCTGT(출력 조각열) + IMM16(필터·치수).
- **워드 회계: 기본헤더 1 + CH 1 + EH 4 = 6워드.** CH 는 EH 가 아니라
  word1 이고 존재는 EH-조건부다(#26 결정, `opcode_width_expansion.md`
  §8.6·§8.9; §5.1 은 부호어를 448비트로 잰다). 종전 「4슬롯/5워드」는
  CH 누락 오계였다.
- **자인 약점**: 텍셀 폭은 imm16 에 자리가 없어 **태그 정밀도 필드가
  나른다.** A1′ 가 이것을 없앤다.

### A1′ — 필터를 opcode 로 + 치수·폭을 PRECISION 으로 — **산정 선행 의무**

- 배정안: `0x410 TXSMPN`(nearest) · `0x411 TXSMPB`(bilinear). 1024칸
  영역에서 opcode 2개는 넉넉하다. (`Ctrl-min` 이 `0x400–0x405` 를
  청구하므로 겹침을 피해 `0x41#` 를 청구한다 — 최종 번호는 배정 절차 몫.)
- PRECISION EH 재사용: `dim_override` 8b = log2W ‖ log2H,
  `precision_mode` = 텍셀 폭. **IMM16 불요, 4슬롯 유지**(PORT + OPREF +
  ACCTGT + PRECISION), **태그-폭 우회가 통째로 사라진다.**
- 대가: `dim_override` 의미 재사용 규범 한 줄.

### A2 — 장치 생산 좌표 (뱅크 상주) — 이월

좌표가 장치 생산(뱅크 상주)이면 호스트가 텍셀을 미리 모을 수 없다 —
**표현력 논증이 참인 유일한 자리다.** A1 대비표의 상한도 정정된다: A1 도
인코딩상 T ≤ 255 이고 16 은 기본 형상의 능력일 뿐이다(§3). 이번 제안
범위 밖으로 이월하되, **필요성 논증의 거처가 여기라는 사실**을 잃지 말 것.

### 디스크립터-in-구간 — 그린다, 판정 유보

첫 조각 = 치수·폭 서술자. A2 의 IMM16 상실을 데이터 층에서 되사는 갈래다.
단 §5.7 이 인코딩만 덮는다는 르베그 기각 논거(60b 덫)와 정면으로 대면해야
한다 — 여기서는 그리기만 하고 판정하지 않는다.

### B — TEXGATHER (gather 전용 중간 원시연산) — 기각 방향 유지

기각 근거의 수치는 교체한다: 종전 「~10배」는 FSCALAR 사슬 기준이었다 —
**A0 의 `0x7A` 형은 발화 1회**이므로 그 수치는 무효다. 남는 기각 근거는
A0 대비 이득 부재 + 중간 결과 왕복이다.

## 3. 인코딩·판정 규범 (A1/A1′ 공통)

- **legality: T ∈ 1..255** (ACCTGT `[23:16]`). 포획 형상의 상한
  (참조 형상 FRAG_MAX=16 — `0x7A` desc 는 실측이지 ISA 상수가 아니다)
  초과는 **능력 부재**다 (§2.4.1 4항 「선언이 구현의 용량을 넘는 것」
  선례 그대로). 「T=1..16 균일」 legality 문면은 합법 값 범위를 형상
  파라미터의 함수로 만들어 ISA-7/INV-T1 을 정면 위반하므로 **싣지 않는다.**
- **imm16 (A1)**: `[필터 4b | log2W 4b | log2H 4b | 예약 4b — 반드시 0]`.
  넷째 니블의 예약-반드시-0 행은 §5.7 · `ALGDi` `[7:0]` 선례를 따른다.
- **W·H(+halo) ≤ 구간 길이(텍셀 단위) 검산 필수** — 없으면 선언 공간
  (log2 니블로 2¹⁵×2¹⁵ 까지)이 실현 가능 공간의 약 10⁶ 배로 열린다 (§4).
- **T=C(입력 좌표 파도의 조각 수) 불일치 · 치수 검산의 판정 소재지 =
  MU 발사 사다리(실질 error_flag)** — C 는 입력 파도 포획 완료에야 안다.
  디코드 경계에 못 선다. `ALGDi` §4.2 2항의 자기 패치(「이 한 줄이 없으면
  『디코드 경계 malformation』이 거짓 문면이 된다」)를 축자로 승계한다.
- **사이클 규범**: 사이클은 (opcode, dtype, 서브옵, **선언 형상값 T**)의
  함수까지 허용 — 데이터 **값**의 함수는 불허(§5.3 상수 시간성).
  전건은 `Di` §1.4 정의역 확장이다 (§7 항 3).

## 4. 정직한 한계 — 255 조각 용량 벽 (첫 줄)

**이 확장의 실효 텍스처는 구간당 f16 ≤ 1,020 · f32 ≤ 510 텍셀이다.**

- 구간 = 조각열 하나, 선언 총개수 ≤ 255, 조각 64b. ⇒ **32×32 f16 타일 =
  256 조각 — halo 없이도 안 들어간다.**
- halo 1 포함 실용 최대: f16 ≈ 29×29 (31×31 = 241 조각) · f32 ≈ 20×20
  (22×22 = 242 조각 — 재계산 반영; 검토 초안의 21×21 은 23×23 = 265 조각으로
  255 를 넘는다).
- 다중 구간 텍스처는 `Di` §1.2 의 1-조각열 독법 아래 **표현 불가**다.
- 이 벽이 치수 인코딩 폭을 규정한다 — log2 니블의 선언 공간과 실현 공간의
  격차가 §3 의 검산 의무를 만든다.

## 5. 값 계약

**두 형태를 갈라 적는다** — 「PACK_FINAL 부류로 고정」과 「평가열 계약 +
golden-정의적」은 다른 계약이고, 흐리면 golden 저자가 어느 쪽을 골라도
「따랐다」고 말할 수 있다.

1. **가중치 산출 = 평가열 계약.** floor/frac 추출은 정확하다. 단
   `1−fu` 는 Sterbenz 구간 밖에서 부정확하다 — 「주소 산술 전체가 비트
   정의 가능」의 「전체」에서 **가중치 반올림은 뺀다.**
2. **4항 내적 = exact-sum-round-once.** f16/bf16 텍셀 × f32 가중치 곱은
   광폭에서 정확하다.

**텍셀 dtype legality 는 전수 열거하되 opcode 별로 가른다** (restrictive-first
— `0x7A` 「EXACTLY 2 legal rows」 선례도 opcode 단위 열거다). **사용자 확정
(2026-08-28)** — WebGPU/Vulkan 이 f32 의 표집과 필터링을 가른 구조(§11)를
그대로 승계한다:

- **TXSMPN(nearest) 합법 행: f16 · bf16 · f32.** nearest 는 곱이 없어 값
  계약 비용이 0 — 남는 것은 용량 산술뿐이다(f32 스칼라 ≤ 510 텍셀). f32
  **표집**은 WebGPU(`unfilterable-float`)·Vulkan(`SAMPLED_IMAGE_BIT`)의
  **의무** 표면이라 이 행이 그 의무를 정면으로 덮는다.
- **TXSMPB(bilinear) 합법 행: f16 · bf16.** 둘 다 f32 무손실 임베딩이라
  exact-sum-round-once 계약이 공짜로 선다(위 값 계약 2항).
- **TXSMPB 의 f32 = 가격표 핀 예약 행 — 지금 싣지 않는다.** 가격:
  f32×f32 곱(유효자릿수 48b)은 f64 에서 정확(48 ≤ 53)하므로 **광폭 누산
  또는 `Lf64min` f64 경로 재사용 + 계약 문면 한 줄**로 계약이 복원된다.
  이 행은 WebGPU `float32-filterable` / Vulkan `R32_SFLOAT` 의 선택
  `FILTER_LINEAR` 에 **1:1 사상**된다 — 두 API 모두 f32 필터링을 opt-in
  으로 정의했으므로, 미실장 동안 런타임이 그 기능을 미노출하면 100%
  적합이다. 행 추가는 단조 확장이라 후행 개정이 싸다.
- **int 텍셀 + bilinear + qNaN 처분은 정의 불가 조합** — 비합법 행으로
  명시한다 (빠뜨림이 아니라 금지임을 문면으로).
- **bf16 은 두 API 표면에 존재하지 않는다** — ML 몫으로 유지하되 API 지원
  논거로 세지 않는다.

## 6. 순서 · 점유 처분

### 6.1 순서 — 게이트 없음 (자기모순 제거)

「발화는 텍스처 구간의 토큰 완료로만 게이트」와 「미완 구간 읽기는 loud
fault」는 **동시에 기전일 수 없다** — 게이트가 있으면 fault 의 전건이
공집합이고, fault 가 기전이면 게이트가 없다. 그리고 「재조립 완료」는
§4.4.4 과잉 게이팅 금지가 닫아 둔 게이트 입력 어휘(명시적 순서 토큰의
완료)에 없다. **채택 형태 (정합한 값싼 형태 하나)**:

> **게이트 없음 · 순서는 호스트 몫**(채움 완료 디스크립터 확인 → 샘플 파도
> 투입 — 타일 패스당 호스트 동기점 하나, §9 원장 5) · **조기/미완 구간
> 읽기 = loud fault** (전건의 거처는 §8).

**표기 정정 (2026-08-30): 「loud fault」는 이제 *제안*이 아니라 *승계*다.**
정본 §2.4.1 5항이 축자로 「미완 구간을 읽는 것은 loud fault 다」를 세웠다
(`02-fabric-alu.typ:373-380` 「미완 구간을 읽는 것은 loud fault」). 정본은
**처분만** 주었지 게이트 부재를 주지 않았으므로 「게이트 없음 · 순서는 호스트
몫」은 여전히 이 확장이 정할 몫이다.

### 6.2 점유 처분 — busy-reject 는 규범이 아니다

§2.2 는 공유 유닛 점유 중 처분을 **「이 재구현에서 그 처분은 *대기*다」**
로 확정했고(보류 자원 · no_overtake 가드), 해설이 거절을 명시 기각한다
(「정책 없는 거절은 기아(FAB-6)로 이어진다」). `0x70`/`0x7A` 의
busy-reject 는 **참조 구현의 실측 행동**이지 재구현 규범이 아니다. 갈래:

- **⑴ 대기 승계** — 깊이 0(항상 배압)도 적법하다(§2.2 3항). **권고 →
  확정 (2026-08-28, §10 항 3).**
- ⑵ §2.2 에 「다사이클 팔 예외」 개정을 등재 (§7 항 2) — 기각됐다.

어느 쪽이든 **「정본 개정 사항이 아니다」는 문장은 이 축에서 거짓이다** —
⑵ 는 개정이고, ⑴ 도 처분 문장을 이 확장 명세가 명시해야 한다.

### 6.3 유닛 거처 — 이름과 명세를 가르지 말 것

「전용 샘플러 팔」이라 이름하고 MU-hosted 로 명세하면 비용 구조가 숨는다:

- **MU-hosted**: `0x70`/`0x73`/`0x7A` 와 busy 를 나눈다 — 텍스처 패스가
  행렬 연산을 직렬화한다.
- **전용 4번째 유닛**: 병합점 신설(FAB-1/FAB-9 의무 · dispatch 분류기).

어느 쪽도 산정이 없다 (§9 원장 4). 결정은 산정 후로 미룬다.

## 8. G9 — 구간 메타데이터: 이 제안의 실제 관문

### 8.1 C1 — 완료 표식의 수명 — **정본 B.5 에 행으로 등재됐다 (2026-08-30)**

> 이 구멍을 적을 때는 정본에 받을 자리가 없어 「`Di` §1.2 상속분」으로만
> 적었는데, 지금은 **B.5 「완료 표식의 수명 — 위 처분의 전건이 문맥과 함께
> 사라진다」 행**(*미결 — 정본 자답 가능*)이 서 있고 정본 §2.4.1 해설이 같은
> 내용을 적는다. 그 행이 축자로 「결과 뱅크 구간을 문맥 소멸 뒤에도 오래
> 읽는 소비자가 처음 착지하는 순간 이 자리가 드러난다」고 적는다 — **이
> 제안을 이름 없이 가리킨 것이다.**
>
> ⇒ 표기를 바꾼다: 「이 확장이 발견한 구멍」이 아니라 **「정본에 등재된 행의
> 첫 실수요」**다. 확장이 구멍을 발명한 것이 아니라 드러냈다는 서술이
> 정확하고, 그것이 승격 논거다.
>
> **🆕 그리고 정본이 값싼 대안을 스스로 제시했다** — 같은 행이 「@sec:extpayload
> 4.3 5항의 비우기 시점을 계약으로 좁히는 것만으로도 전건의 수명이 선다」고
> 적는다. 그 갈래는 사상표를 건드리지 않으므로 **저작자 축 신설도 원자성
> 규범 예외도 사지 않는다** — 신설 규범 **둘** 대 **한 문장**이다. C2 ⑵ 의
> 2026-08-28 확정은 *이 대안이 정본에 서기 전에* 내려졌다 (§8.2 참조).
> **어느 쪽이 싼지 판정은 안 선다** — 비우기 시점을 좁히면 재조립 문맥 자원
> 회계가 움직이는데 그 값은 재지 않았다.

(원 서술 — `Di` §1.2 상속분의 구멍)

§4.3 5항·소거 규범은 인도/소거 시 **재조립 상태 전부 비움**을 요구한다.
그러면 문맥이 닫힌 뒤 — 텍스처가 정확히 그 상태로 **오래 읽히는데** —
「이 구간은 완성됐다」를 판정할 런타임 상태가 없다. §6.1 의 「미완 구간
읽기 loud fault」의 전건이 문맥 소멸과 함께 증발한다. **`Txtsmp` 는 이
구멍을 최초로 장기 노출시키는 소비자다.**

### 8.2 C2 — 「길이」의 이중성: 경계 검사가 읽는 길이는 어느 것인가

G9 갈래①의 길이 = **임대 용량**(사상표 `[15:8]`/`[7:0]`), `Di` §1.2 의
길이 = **채운 조각열의 선언 총개수** — `b-gaps.typ` 그 행 자신이 「둘은
다른 값」이라 못박은 그 둘이다. 안전이 요구하는 검사는 **색인 < 채운
길이**다. 용량을 검사하면 반례가 선다:

> 용량 128 임대 · 81 조각 채움에서 색인 100 은 **무언으로 미기입 슬롯을
> 읽는다** — 조용한 쓰레기, fault 0.

갈래 둘 — **사용자 결정**:

- **⑴ 검사 = 채움 총개수.** 안전하다. 단 `Txtsmp` 는 용량-길이의
  소비자가 **아니게 되고**, G9 주장은 쓰기측 채움 검사로 약화된다.
- **⑵ 인도 시점에 실길이 · 완료 비트(· 요소 폭)를 사상표 엔트리에
  기입.** C1 도 함께 닫고 G9 연결(「타일 축이 LBID 「길이」 미결의 결손된
  소비자다」)이 **문면 그대로 실물**이 된다. 대가 = §7 항 4 의 저작자 축
  신설 규범.

**판정**: 「B.5 두 미결의 전건을 동시에 여는 실물」 문장은 ⑵ 를 고를
때만 선다. **이 결정이 이 제안의 실제 관문이다. → 확정 (2026-08-28):
⑵ 방향 채택, 발효는 명세 승격 시점 (§10 항 1).**

## 9. 미측정 원장 — 재지 않은 것 전수

   `0x07B` 상주(16) 위에 얹을 때도 선다. **프로그램 수를 재지 않은 채
   「정확히」를 말하지 말 것.**
3. 발화 수 / 샘플 스루풋.
4. MU-hosted 직렬화 비용 vs 전용 팔 병합점 비용 (§6.3).
5. 타일 패스당 호스트 동기점 1 의 비용 (§6.1).
6. A1′ 산정 (PRECISION 재사용 형태의 인코딩·검증 비용).
7. **포맷 파도(§11) 재전달 경제** — rgba8unorm 4채널에서 A0 는 샘플당
   내적 4발화(채널당 1). 「4× 악화」는 유도 산술이지 실측이 아니다.
8. **ASTC 디코더 산정** — 면적·사이클·모드 커버리지 (§11.4). 산정 전
   in-fabric 채택 없음.

## 11. WebGPU/Vulkan 적합성 전략 — 포맷 파도 · 이월 원장 (사용자 확정 2026-08-28)

> 검토 1회 통과 후의 추가분이다. 계기: 「f32 행은 이미 필요한데?」(사용자,
> 2026-08-28). 재판정 결과 f32 는 opcode 별로 갈라지고(§5 확정), 진짜
> 격차는 채널 축임이 드러났다.

### 11.1 두 API 의 실제 요구 — f32 를 가른 것은 API 자신이다

| 표면 | WebGPU | Vulkan |
|---|---|---|
| f32 표집(nearest/fetch) | **의무** (`unfilterable-float`) | **의무** (`SAMPLED_IMAGE_BIT`) |
| f32 bilinear | **선택** (`float32-filterable` opt-in) | **선택** (`R32_SFLOAT` 의 `FILTER_LINEAR` 비의무) |
| rgba8unorm(+sRGB) bilinear | **의무** | **의무** |
| f16 bilinear | 의무 | 의무 |
| rgb10a2 · rg11b10 bilinear | 의무 | 의무(rg11b10 계열) |
| bf16 텍스처 | 없음 | 없음 |

**적합성(conformance)은 런타임 속성이지 ISA 속성이 아니다** — A0 기준선이
있는 한 의무 표면 전체를 호스트 측에서 적합하게 구현할 수 있다. ISA 행은
적합성을 막지 않고 **포맷별 경제만** 바꾼다. 설계 질문은 「무엇이 안
되나」가 아니라 「어느 포맷의 가속이 값을 내나」다.

### 11.2 포맷 파도 (후속 제안, 신설 확정) — 의무-filterable 의 본체

**대상: rgba8unorm(+sRGB) 4채널 · rgb10a2 · rg11b10.** 근거 셋:

1. 두 API 의 의무-filterable 본체가 여기다 (§11.1) — f32 가 아니다.
2. **A0 경제가 가장 나쁜 지점이다** — 채널당 내적 1발화, RGBA = 샘플당
   4발화 (§9 원장 7).
3. sRGB 는 **필터링 전에 탭마다** 디코드해야 한다(두 API 모두 선형 공간
   필터링 규정) — gather 경로 안에 있어야 하므로 호스트 후처리로 밀 수
   없는 유일한 층이다.

설계 재료 (파도 몫): unorm 정규화 = correctly-rounded x/255 — 256-엔트리
핀 ROM 이면 정확 (곱셈 근사 불가 — 1/255 의 f32 근사 곱은 전 x 에 대해
correctly-rounded 가 아니다). sRGB 디코드 = 256-엔트리 핀 LUT (rsqrt LUT ·
seed ROM 의 핀 규율 승계). 가내 선례: DEQUANT(int→float)·GAMMA_MUL_W 레인
기계. 형태 갈래 둘 — SoA(채널 평면 4구간, 샘플당 4발화) vs packed(레인
언팩 후 4채널 병렬 필터). 용량 산술: RGBA8 = 32b/텍셀 → 2텍셀/beat →
≤ 510 텍셀 ≈ 22×22 (halo 시 20×20) — f16 스칼라와 같은 급.

### 11.3 이월 원장 — API 의무인데 ISA 비용 0 이거나 나중인 것

- **주소 모드(wrap/clamp/mirror/border)**: A1 은 좌표가 호스트 저작이라
  전부 호스트 몫 — **ISA 비용 0 으로 적합.** 장치 생산 좌표(A2)로 갈 때만
  장치 몫이 된다 (A2 이월과 한 몸).
- **mip/trilinear/aniso**: 필터 = 가중합 = 내적. trilinear 8탭은 `0x7A`
  32레인에 한 발화로 들어가는 산술이고, 전용 명령 쪽도 탭 수 일반화이지
  새 의미론이 아니다.
- **depth/PCF(비교 샘플러)**: 탭별 비교 후 평균 — CCMP(`Ctrl-min`) + 내적
  합성 후보. 이월.

### 11.4 압축 포맷 — **방향 = ASTC (사용자 확정 2026-08-28)**

- **용량 산술 (유도)**: ASTC 블록 = 128b 고정 = 2 beat → 구간당 127 블록.
  4×4 = 2,032 텍셀(≈45×45) · 8×8 = 8,128(≈90×90) · 12×12 =
  18,288(≈135×135). RGBA8(≈22×22) 대비 선형 치수 **2×~6×** —
  **압축이 §4 용량 벽을 깨는 유일 갈래**라는 판정의 실물이다.
- **ASTC 선정 근거**: Khronos 로열티-프리 · LDR+HDR 프로파일 · 0.89~8bpp
  최광역 · Vulkan 모바일 프로파일(Android Baseline)의 의무 계열 · WebGPU
  `texture-compression-astc` 와 정렬. BC 원본(데스크톱 생태계)은 업로드 시
  호스트 트랜스코드 폴백 — 적합성 훼손 없음.
- **정직한 대가**: 세 계열 중 디코더가 가장 무겁다(모드 다수 · BISE ·
  파티션 · dual-plane). in-fabric 디코더는 산정 전 채택 없음 (§9 원장 8).
- **순서**: **포맷 파도(§11.2)가 전건이다** — ASTC LDR 디코드 출력이
  unorm8(+sRGB)/fp16 이라 채널·정규화·sRGB 층 위에서만 의미가 있다.
