# `Ctrl` — 값-평면 비교·선택 확장 제안 (`Ctrl-min`)

> ### 지위 (2026-08-28) — 제안 메모, 명세 아님
>
> **비정본이다.** #24 파이프라인(제안·검토 3단)의 산출이며, `docs/extensions/`
> 명세의 **전 단계**다 (`Di` 계보: 메모 → 명세). 정본은
> `docs/wt64v1-architecture-guide/` 하나이고 이 문서의 어떤 문장도 계약이
> 아니다.
>
> 적대 검토 1회를 통과한 **수정 반영본**이다 — 검토가 강제한 다섯
> (갈래 (a)/(a′) 분리 · 발화 수 6/9 정정 · `Di` §1.4 문구 교체 · 부수 이득
> 한정 · 누락 갈래 2건 등재)을 전부 반영했고, 검토가 반증한 문장은 싣지
> 않았다.
>
> opcode 는 12b 표기. 니모닉 `CCMP*` 는 **작업명**이다 — 어셈블러 표면은
> 사용자 몫. 인용은 가급적 절 이름과 규범 라벨로 적는다.

---

## 0. 요약 — `Ctrl-min`

**채택 갈래 (c) — 값-평면 비교.** 발화를 고르는 기구(steer)는 전 갈래
기각하고, **값을 고르는 원료(비교 마스크)** 만 신설한다:

| 항 | 내용 |
|---|---|
| 신규 opcode | **CCMP 6종, `0x400–0x405`** (배정안) |
| 인코딩 행 | ADD 행 축자 — required `[port]` · forbidden `[mem, subscript]` · `allow_imm_xor_opref` · `rtl_alu_binary` |
| 결과 | **마스크 원형** — 참 = 전비트 1 · 거짓 = 전비트 0 (64b 단일 beat, ISA-9 ②) |
| select | lowering — CCMP 1 + 3발화 = **4발화** (lowering-only 는 9발화, §3) |
| 규칙 | **「Ctrl 류는 EH ≥ 1」** — §5.1 보안 결정 입력의 답 (§5) |
| 전건 | **W1**(opcode 12b — `0x400` 은 #25 전에 인코딩 자체가 없다) · **W3**(미배정 = malformation) |

경계선 정식화 (§2.3 축): **「고르는 것이 값이면 밖(적법), 발화이면
안(위반)」.** 발화의 유일한 원천은 호스트 명령 큐다 — 술어가 발화 여부를
정하는 순간 §2.3 의 근거 구조를 침식한다 (문면 무저촉이어도).

## 1. 현행 실측 (ISA JSON — 검토 재확인 완료)

- opcode **68종** (「약 70종」이 아니다 — 수를 옮겨 적을 때 세라).
- **정수 비교 0건 · SIMD 레인 비교 0건.**
- 있는 것: AND/OR/XOR `0x14–0x16` · NOT/NAND/NOR/XNOR `0x50–0x53` ·
  NEG `0x1B` · SAR `0x19`(imm16 필수 — `SAR(x,63)` 1발화 적법) ·
  STEER `0x02`(desc 축자 「pass-through with new tag」) · MERGE `0x03`
  (STEER 의 alias).
- `0x60–0x65` 는 add/sub/mul 만 — fp 셋에 비교 없음. FMINMAX `0x79` notes:
  offset-key 비교기 · 「signed-int compare tree is NEVER reused for FP」.
- EH 없는 명령의 현행 전수 = **NOP 하나** (JSON 실측: `required []` 는
  NOP 뿐, WADV 도 PORT 필수) — §5.1 잔여 수용 1항 문면과 일치.

## 2. `Ctrl-min` 명세안

### 2.1 CCMP 6종 (배정안 `0x400–0x405`)

| opcode | 작업명 | 술어 |
|---|---|---|
| `0x400` | CCMPEQ | a == b |
| `0x401` | CCMPNE | a != b |
| `0x402` | CCMPLTS | a < b (signed) |
| `0x403` | CCMPLES | a <= b (signed) |
| `0x404` | CCMPLTU | a < b (unsigned) |
| `0x405` | CCMPLEU | a <= b (unsigned) |

- **GT/GE 는 의사 니모닉** — 피연산자 교환으로 어셈블러 표면에서만 제공
  (`hl_only_mnemonics` 선례: LAYERNORM 등). 코드점 0.
- 인코딩 행은 **ADD 행 축자** (§0 표). B 피연산자는 imm XOR opref —
  ADD 와 같은 규율.
- **마스크 원형**: 결과는 전비트 1 / 전비트 0. AND/XOR select lowering
  (§3)과 직결되는 유일한 원형이다.

### 2.2 분할·상수 시간 판정

- **ISA-9 ②** — 결과 슬롯 한 칸에 착지하는 단일 beat 하나.
- **상수 시간성**: CCMP 는 `Di` §1.4 정의역 (opcode, dtype, 서브옵) **안**에
  있고, 조합 단일 beat 라서 **자명하게 만족**한다. (「step 프로그램이
  아니므로 정의역 판정 대상 자체가 아니다」로 적으면 상수 시간 의무가
  안 붙는 것처럼 읽힌다 — 의무는 붙고, 자명 이행이다. `Di` §1.4 의
  정의역은 전 명령에 걸린다 — dtype 축 선례가 step 아닌 `0x70` 이다.)

## 3. 발화 수 실측 (정정 반영)

**lowering-only** (CCMP 없이, signed 전범위 LT 마스크):

```
d = SUB(a,b)
v = AND(XOR(a,b), XOR(a,d))
m = SAR(XOR(d,v), 63)
```

SUB · XOR · XOR · AND · XOR · SAR = **6발화** (종전 「≈5」는 오계).
이 op 셋에서 6 미만 대안은 없다 (대안 공식 검산: 7발화).

**select** (마스크 m 위에서): `r = XOR(b, AND(XOR(a,b), m))` = 3발화.

| 경로 | 발화 수 |
|---|---|
| lowering-only select | 6 + 3 = **9** |
| CCMP 경로 select | 1 + 3 = **4** |

## 4. 기각 전수 — steer 계열과 그 친족

### 4.1 (a) 동종 이중 steer — **정적 malformation**

두 PORT 팔(또는 두 ACCTGT 팔) 중 술어로 택일하는 형태. §4.2.3 종류별
반복 규칙 — PORT 반복 = malformation, ACCTGT 반복 = malformation. 디코드
경계에서 죽는다.

### 4.2 (a′) 이종 쌍 steer — **정적으로는 적법, 의미 층에서 사망**

술어로 「PORT 배달 / ACCTGT 누산」을 택일하는 형태. **§4.2.3 은 이것을
막지 않는다** — 반복 규칙이 금지하는 것은 *같은 종류*의 반복뿐이고,
**PORT 1회 + ACCTGT 1회는 오늘 이미 다중 조각 wave 의 표준형이다**
(모든 opcode 가 PORT 필수 · 총개수 ≥2 선언 wave 는 ACCTGT 없으면
malformation, §4.3). 기각의 실근거는 넷이다:

1. **출력-전량 정리** — 억제된 PORT 팔 = 영원히 발화하지 않는 소비자.
   발화가 남기는 후속 전송 전량의 분할(ISA-9)이 「전량」에서 깨진다.
2. **§4.3 결속 불변** — ACCTGT 팔이 데이터 의존이면, 결속이 개시 wave
   디코드 시점에 확정된다는 규범과 정면 충돌.
3. **§1.4.1 축자 조립** — 출력 태그는 「dest_node_id 를 *그대로* 받는다」.
   술어가 목적지를 고르는 자리가 없다.
4. **§5.1 타이밍 축** — 값 의존 배달 경로는 관측면이 된다.

⇒ 「이 갈래를 여는 개정의 사정권」을 적을 때, (a′)에서는 **반복 표 두
행이 빠진다** — (a)의 사정권을 (a′)에 옮겨 적지 말 것.

### 4.3 poison 술어화 — 기각 확정

§1.4.4 poison 3항: 흐름 불변 · 논리합 전파 · **명령 방향 반드시 0.**
poison 을 조건 비트로 쓰는 갈래는 세 문장 전부와 충돌한다.

### 4.4 wave/에포크 술어화 — 기각 확정

불투명 식별자 규범 — 등가 비교와 보존 외 해석 전면 금지 (산술 · 비트
슬라이스 · 게이트 입력 전부).

### 4.5 단일 opcode + imm16 서브옵 — 기각 (근거 둘)

- ① 서브옵이 imm16 을 차지하면 즉치 B 피연산자 자리가 없다 (원 기각 사유).
- ② (검토 신규) **§4.2.3 이 IMM16/32/64 를 한 종류로 묶어 반복
  malformation** 으로 정하므로, 「imm16 서브옵 + imm32 로 B 를 싣는」
  탈출로도 죽는다. 더 닫힌 기각이다.

## 5. 「Ctrl 류는 EH ≥ 1」 — §5.1 EH-0 보안 결정 입력 (명시 절)

§5.1 잔여 수용 1항 = **EH 없는 명령** (CH 의 존재가 next_hdr ≠ END 에서
유도되므로 EH 0 명령은 CRC 가 덮지 않는다 — 현행 전수 NOP 하나). 함정
문면: 「*EH 없는 명령으로 설계할지가 이제 보안 결정이다* — 그 확장
(Ctrl 류)의 설계 입력이다.」 이 절이 그 입력의 답이다.

**따름정리 (승격)**: 이 기계의 순서 기전은 명시적 순서 **토큰**이고
(§4.4.4), 토큰 수신자는 PORT 명명이다. ⇒ 출력-전량 원칙을 지키는 Ctrl
명령은 **PORT 필수 = EH ≥ 1 이 따름정리로 성립한다.** 설계 재량이 아니라
구조 귀결이다.

⇒ **CCMP 6종 전부 PORT 필수 — §5.1 잔여 수용 1항의 폭 증가 0.**
NOP-하나 규범이 이 확장 후에도 그대로 참이다.

## 6. 부수 이득 — 한정해서 적는다

타일 축(`graphics_tiling_axis.md`)에의 이득은 **「픽셀 ≥ 64b 형식에
한해」 값-평면 계산 도구 공급**까지다. 과대 주장 금지:

- 그 메모 §4.4 의 실제 결손은 **계약 어휘** 결손이다 — 「이 칸은 안
  덮였다」를 나를 자리 없음 + 총개수 0 의 처분 0건. **CCMP 는 그 어느
  것도 건드리지 않는다.** (「빈 조각 값 채움」·「커버리지 마스크」라는
  낱말은 그 메모에 없다 — 전문 grep 0건.)
- **레인 평면에서 무너진다**: int4/int8 레인 포장 픽셀(레인 16/8개)은
  스칼라 CCMP 로 레인 마스크를 못 만들고, 언팩-비교-리팩은 발화 수가
  레인 수 배가 된다.

## 7. 그린 갈래 — 채택하지 않고 등재한다 (검토 강제 2건)

1. **SIMD 레인 CCMP 변종** — §1 이 실측한 「레인 비교 0건」의 되돌아오는
   자리. 이 ISA 의 레인 기계(`0x60` 블록 · GAMMA_MUL_W · DEQUANT)와 타일
   축을 보면 레인 술어가 가장 개연적인 실수요다. 여기서는 제안도 기각도
   하지 않는다 — **미측정 원장: 「레인 술어 수요 재지 않았다」** (§9).
2. **정수 2-입력 MIN/MAX (융합 비교-선택)** — select 의 지배적 소비자는
   통상 clamp/min/max 다: CCMP+mux 4발화 vs 전용 opcode 1발화. FMINMAX 의
   「정수 트리를 FP 에 재사용 않음」 규약은 **FP 방향 한정**이라 정수
   MINMAX 를 막지 않는다. 코드점 후보 2 (`0x406`/`0x407`). 채택/기각을
   여기서 정하지 않고 미측정 원장에 등재한다 (§9). base 쪽 D-09
   (`0x27..0x2F` 배정 미결)와는 **다른 절차**다 — base 배정(`0x0##`)과
   #24 확장 배정(`0x4##`)을 섞지 말 것 (정렬 후보 메모와 겹침 조정).

---

## 8. B.5 등재 제안 — 「소비 후 도착의 처분」

**정본 0건이다** (전 장·부록 grep — 처분 문장 0. 중복 처분은 조각 순번
축 §4.3 에만 있다). 결과가 소비된 뒤 같은 태그로 도착하는 전송의 처분이
이름을 갖지 않는다. 현행 B.5 에 해당 행 없음 확인 — **등재 검토를
제안한다.** (부정 주장이므로 지위는 전수 grep 수준의 확인이다.)

---

## 9. 미측정 원장

1. **레인 술어 수요** — 재지 않았다 (§7 항 1).
2. **정수 MIN/MAX 수요** (clamp 빈도 실측) — 재지 않았다 (§7 항 2).
3. CCMP 6종의 실 워크로드 발화 절감 (§3 은 공식 계수이지 워크로드 실측이
   아니다).

## 10. 사용자 결정 필요 항목

1. `Ctrl-min` 채택 여부 (권고: 채택 — 전건 W1·W3 착지 후).
2. CCMP 니모닉 표면 확정 (작업명 → 어셈블러 이름).
3. §7 항 2 정수 MIN/MAX — 그릴지 / 기각할지 / 원장 유지할지.
4. §8 B.5 「소비 후 도착의 처분」 행 등재 여부.
5. opcode 배정 번호 확정 (`0x400–0x405` 안 — `Txtsmp` 는 `0x41#` 청구로
   겹침 회피).
