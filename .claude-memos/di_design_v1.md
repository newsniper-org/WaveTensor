# `Di` 확장 — 설계 확정안

정본 좌표는 전수로 직접 열어 확인했다. 파일은 하나도 고치지 않았다. 다섯 축의 검증 보고가 남긴 치명 결함 — Forward AD 의 팬아웃 블로커, 르베그의 5슬롯 초과, 스텐실 경계 모드의 다축 오답, 리만의 부분합 배달 미확정, opcode 축의 dtype 손-핀 위반 — **다섯 전부를 인코딩을 늘리지 않는 방향으로 닫았다.** 그 결과 신설 opcode 는 둘, 신설 EH 는 0, 신설 dtype 은 하나이고, 다섯 축 중 둘은 인코딩 변경 0 으로 착지한다.

# 0. 결론 한 줄

**`Di` 는 새 EH 를 만들지 않고, 새 능력 부재 사건을 만들지 않고, `CAP_STATUS` 축을 하나도 늘리지 않는다.** 전 축의 EH 사슬이 3슬롯 이내이므로 (상한 4 — `01-isa-asm.typ:168-176` · `04-ext-payload.typ:759-764`) **`Di` 는 EH 사슬 길이 능력 부재 축을 한 번도 밟지 않는다.** 스텐실이 그 결손의 「첫 밟는 자」라는 판정은 **철회한다** — 그 판정은 5슬롯 설계에서만 참이었고, 5슬롯 설계는 기각됐다.

# 1. 확정안 — 축별

## 1.1 리만 — `RIEMANNDi`: 새 인코딩 0

**한다.** 리만 적분은 **정규 경로를 `0x7A FDOT32_CR` 하나로 못박고, 새 opcode·새 EH·새 dtype·새 계약을 하나도 만들지 않는다.** 명령 형태는 기존 그대로 — 기본헤더 + `PORT` + `PRECISION` = **2 EH 슬롯 / 3 워드**, A‖B 연접 16조각 단일 파도(1,024b), 결과는 fp32 조각 하나. ISA-9 분할 판정은 **②**(결과 슬롯 한 칸에 착지하는 단일 beat 하나 — `01-isa-asm.typ:335-345`).

정규 경로를 FP 블록으로 고르는 근거는 **EH 예산이 아니라 값 계약**이다. 리만 축 검증이 밝힌 대로 EINSUM 리만은 PRECISION 을 붙여도 4슬롯 이내이므로 예산 논거는 무효다. 실제 근거는 `scripts/golden_fdotcr.py` 가 못박은 「`r == pack_signed(exact Σ aᵢ·bᵢ)` **비트 동일**」 — 이 ISA 에서 **결합 순서가 값에 보이지 않는 유일한 부동소수 축약**이다. §2.5 「결정론은 검증 가능성의 전제」(`02-fabric-alu.typ:405-408`)가 여기서 산술로 성립하고, 결합 순서가 형상의 함수가 되는 갈래가 애초에 열리지 않으므로 INV-T1 축도 열리지 않는다. EINSUM 경로에는 그런 계약이 없다.

**lowering 규약 넷을 확정한다.**

1. **격자는 데이터다.** 표본점·가중치는 전부 파도 페이로드로 오고, 분할 폭 `N` 은 어느 인코딩에도 없다. `N > 32` 는 lowering 이 정적으로 `⌈N/32⌉` 발화로 편다 (§2.3 — 발화의 유일한 원천은 호스트 명령 큐, `02-fabric-alu.typ:162-167`).
2. **가중치 규약과 그 적용 범위.** 공통 배율 `h` 를 분리하고 계수만 싣고 사후 `FS_MUL` 한다 — 균등 격자에서 9.4×–24× 를 번다(리만 축 독립 재현). **적용 범위를 명시한다: 계수가 유한 이진 분수 집합에 드는 격자에 한한다.** 비균등 격자에서는 개선이 **1.00×**(실측)이고 균등 대비 4.4× 손실을 진다 — 이것은 규약이 사지 못하는 대가이고, 「측정한 것」으로 적는다.
3. **패딩 규약.** `N mod 32 ≠ 0` 이면 잔여 레인의 **A·B 양쪽**을 canonical zero 로 기입한다. B 만 0 으로 두는 것은 부적법이다 — A 가 Inf/NaN 이면 계수가 0 이어도 전체가 qNaN 이 된다(실측; ISA 의 `0x7A` desc 도 「NaN/Inf operand … → canonical qNaN + sticky」로 같은 것을 적는다). 이 규약이 없으면 심프슨-31 이 조용히 깨진다.
4. **부분합 접기는 호스트가 한다.** `N > 32` 의 부분합은 결과 슬롯에 착지하고 호스트가 접는다. 근거는 회피가 아니라 사실이다 — **이 ISA 에 fp32 이항 축약 경로가 없다**: `0x71`/`0x72` 는 `legal_dtypes [0,1]` 정수 전용, `0x73` 은 B 가 OPREF 로 오는 스칼라 브로드캐스트(`a*B[63:32]+B[31:0]`), `0x7A` 는 32항 고정. 그리고 **두 생산자를 한 소비자의 A·B 로 정적 라우팅하는 수단이 인코딩에 없다** — PORT EH 본문 16비트는 전량이 `dest_node_id` 이고 페이로드 포트 선택자가 아니다(`01-isa-asm.typ:277-283`), payload_b 는 별개 생산자 경로가 아니라 같은 파도의 확장 페이로드다(`0x78` desc: 「fp32 scale rides ext_payload_b on the wave-COMPLETING fragment beat」). 리만 축이 「트리의 모양은 확정했고 피연산자 배달은 확정하지 않았다」고 적은 자리의 답은 **트리를 못 짓는다**이다.

**대가.** 초판 정의역은 f16/bf16 표본이다. f16 은 65504 에서 Inf 로 넘고 한 레인의 Inf 가 블록 전체를 qNaN 으로 만든다 — 특이점 적분은 bf16 을 쓴다. 이것은 정밀도 축이 아니라 **정의역 축**이고, 방향이 정밀도 축과 반대다. `N > 32` 의 호스트 왕복은 재지 않았다 — **방향만 안다.**

**기각한 대안.** EINSUM 기반 리만(값 계약 부재) · 등차 문턱/분할 폭을 인코딩에 싣기(INV-T1) · FSCALAR 이항 트리(위 4항).

## 1.2 르베그 — `SUPMEASDi` (opcode `0x7B`)

**한다.** 층 케이크 $\int f\,d\mu = \int_0^\infty \mu(\{f>t\})\,dt$ 를 채택하고, 그 유일한 신규 원시연산을 **「초과 개수」 하나**로 좁힌다. `LEBESGUE` 로 부르지 않는다 — 명령이 하는 일은 적분이 아니라 초과 측도 한 겹이다.

| 항목 | 확정 |
|---|---|
| opcode | `0x7B` — **fp 블록 안**(`0x70`–`0x7F`). 미배정 실측 확인(배정 최대 `0x7E`, 블록 내 빈칸은 `0x7B`·`0x7F` 둘) |
| mode ROM 행 | `legal_dtypes [4]` · `legal_acc [1]` · `legal_rnd [0]` — `in_fp_block` 자기 게이트 안이므로 **생성기 변경 0** |
| A 피연산자 | 4 f32 레인 = 128b **2조각 파도** (`0x79 FMINMAX` 형 그대로) |
| B 피연산자 | 문턱 `t`, `src_kind=1` OPREF → `dec_eff_b_value` (`0x73 ACC_ELEMWISE` 형 그대로) |
| EH 사슬 | `PORT` + `PRECISION` + `OPREF` = **3슬롯 / 4워드**, 여유 1 |
| 플래그 | `F_HAS_OPB` + `F_PRECISION_OVR` |
| 출력 | `sext64(int32)` 계수 `0..4` — **단일 beat**, ISA-9 **②** |
| ACCTGT | 요구하지 않는다 (출력이 조각열이 아니므로 §4.3 결속 1항의 전건이 서지 않는다 — `04-ext-payload.typ:268`) |

**5슬롯 초과를 이렇게 닫았다.** 르베그 축 검증의 치명 결함 1(사슬이 5가 되어 모든 적법 인코딩이 능력 부재로 선다)은 실재했다 — `require_precision_eh: true` 인 opcode 는 **15개, 예외 0건**이고 f32 를 고르는 유일한 기구가 PRECISION EH 다. 답은 **A 를 파도 페이로드로, B 를 OPREF 로 두는 것**이다. 두 반쪽 다 선례가 있고(128b/4레인 f32 A = `0x79`, OPREF-B = `0x73`), **ACCTGT 를 필수로 적은 것이 잘못이었다** — 단일 beat 결과에는 §4.3 이 ACCTGT 를 강제하지 않는다. 그리고 이 형태는 **OPREF 읽기 폭을 opcode 가 정한다는 숨은 신규 계약을 만들지 않는다**(결함 2 소멸) — OPREF 는 64비트 `eff_b_value` 하나를 그대로 나른다.

**비교 의미론을 전부 못박는다** — 반례 셋이 실재했으므로 하나도 남기지 않는다.

- **키 정규화**: `key(a) = (a[30:0]==0) ? 0x80000000 : (a[31] ? ~a : a ^ 0x80000000)`. `0x79` 의 오프셋 키는 `−0 < +0` 이 **필요한** 연산의 것이고, 층 케이크의 정본 하한 문턱은 정확히 $t_0 = 0$ 이다. 정규화하지 않으면 $x = [+0,+0,+0,+0]$ 에 대해 $t=-0.0$ 이면 계수 4, $t=+0.0$ 이면 0 이 나온다 — 같은 실수의 두 비트열이 다른 측도를 낸다. 정규화하면 키 순서가 NaN 을 뺀 전 구간에서 IEEE `>` 와 **정확히 일치**한다. 비교기 코어는 `0x79` 와 공유하고 전처리 한 단이 갈린다.
- **비교는 엄격 초과 `>`** 하나다. 서브옵을 두지 않는다 — imm16 은 금지(`0x79` legality 복제).
- **NaN 문턱 → 결과 0. NaN 레인 → 지표 0.** 레인당 `isNaN`(`exp==0xFF && mant!=0`) 검출과 마스크가 **새로 든다.**
- **비정규**: 비교는 비정규를 정확히 다룬다(`0x79` 의 DAZ-EXEMPT 승계).
- **새 데이터패스는 0 이 아니다.** isNaN 검출 ×4 + ±0 키 정규화 ×4 + 1비트 지표 4개의 popcount 트리 — `0x72 ACC_REDUCE` 의 합산 트리는 `legal_dtypes [0,1]` = int4/int8 폭이지 1비트가 아니다. 면적은 작겠으나 **재지 않았다 — 방향만 안다.** 「비교기 재사용 비용 0」은 **철회한다.**

**측도를 정수로 내는 결정이 이 설계에서 가장 값비싼 것을 산다.** 계수 $m_k$ 가 정수이므로 접기가 결합적이고, **`ADD 0x10` 으로 실제로 표현된다** — A 는 앞 단계에서 라우팅된 파도, B 는 `OPREF`(`allow_imm_xor_opref: true`, `forbid_opref: false`). 직렬 사슬이므로 **동시에 살아 있는 LBID 는 상수 개**이고 르베그 축이 지적한 LBID 고갈($K\lceil M/4\rceil$ 개 = 65,536 vs 256)이 소멸한다. `0x71` 의 ISA 노트가 같은 수법을 이름한다 — 「K-loops chain via serial carry-in or VDOT partials + **ADD 0x10 trees**」. 이것이 fp 측도를 기각하는 결정적 근거다: **fp 였다면 접을 수단이 없다**(§1.1 4항).

**적분 조립.** $\int f \approx \Delta t \cdot \sum_k m_k$ — **초판은 균등 문턱 격자**로 못박아 곱셈을 한 번으로 줄인다. 반올림은 `CVT` I2F 한 번 + `FS_MUL` 한 번, 둘 다 RNE. **`0x74` 는 DAZ/FTZ 이므로 $\Delta t$ 가 비정규 영역에 들면 적분이 통째로 0 이 된다** — $\Delta t \ge 2^{-126}$ 이 lowering 의무이고, 구간 폭 $R$ 에 대해 $K \le R \cdot 2^{126}$ 이 $K$ 의 상한이다. 이것을 적지 않으면 「$O(1/K)$」가 거짓말이 된다.

**$K$ 는 어느 인코딩에도 없다.** 문턱은 뱅크 상주 값이고 $K$ 는 lowering 이 정적으로 펴는 발화 수다. INV-T1/T2 축을 아예 열지 않는다 — 이 설계에서 가장 좋은 부분이고 그대로 유지한다.

**기각한 대안.** 히스토그램/scatter(데이터 의존 주소 기입 — `02-fabric-alu.typ:358-360` 「순번이 그 구간 안의 자리를 정한다」와 정면 충돌) · 문턱을 MMIO 구성에 두기(발화 사이 상태) · 정밀도 8비트 mode byte 에 문턱 싣기(f32 문턱 32비트가 4비트 코드점에 안 들어간다 — 「여유가 0」이라는 이전 근거는 **거짓**이었다: `acc`·`rnd` 는 4값 중 1값만 합법이고 여유가 상당하다) · **마스크 생산 + 기존 `0x54 POPCNT` 2발화 갈래**(4레인 마스크가 64비트 워드의 4비트만 쓰고 60비트가 데이터 층의 덫이 된다 — §5.7 의 예약 규율은 인코딩만 덮고 데이터는 못 덮는다. 그리고 발화가 2배이고 중간 마스크가 결과 슬롯을 하나 더 먹는다).

## 1.3 Forward AD — **새 opcode 0. `dual_f32` = dtype `0x6`**

**한다.** Forward AD 를 **새 명령이 아니라 새 데이터 형식**으로 짓는다. `dual_f32` 를 mode byte 의 dtype 코드점 **`0x6`** 에 배정하고, 기존 세 opcode 의 `legal_dtypes` 에 더한다:

| opcode | dual 지원 | 서브옵 |
|---|---|---|
| `0x74 FSCALAR` | 이항 | `FS_ADD`(부재값) · `FS_SUB` · `FS_MUL` · `FS_DIV` — **`FS_FMA` 제외** |
| `0x75 FRSQRT32` | 단항 | — |
| `0x76 FEXP2_32` | 단항 | — |

페이로드 배치: primal `payload_a[31:0]`, 접선 `payload_a[63:32]`. B 도 같다. EH 사슬은 이항이 `PORT`+`IMM16`+`PRECISION` = **3슬롯/4워드**, 단항이 `PORT`+`PRECISION` = **2슬롯/3워드**. ISA-9 판정은 **②** — 이중수는 한 값이고, 64비트 안의 32/32 분할은 계수의 정의역(「결과 슬롯에 착지하는 전송」, `01-isa-asm.typ:343-345`)의 원소가 아니다.

**이 갈래가 D1 블로커를 소멸시킨다.** Forward AD 축 검증의 치명 결함은 실재했다 — `y = FRSQRT32(v)` 의 접선 규칙 $-\tfrac12 y^3 t$ 는 `y` 를 최소 4회 소비하는데, 이 기계에 multicast 는 없고(`01-isa-asm.typ:330` · `04-ext-payload.typ:169`) 유일한 재사용 기구인 `src_kind=1` OPREF 를 `0x74`/`0x75`/`0x76` 이 전부 금지한다. **dtype 갈래에서는 `y` 의 재사용이 step 프로그램 안에서 일어나므로 토큰 전송이 아니고, 따라서 ISA-9 계수에 보이지 않는다.** 단항 미분 규칙이 한 발화 안에서 닫힌다.

**정본이 이 기구를 이미 이름했다.** `02-fabric-alu.typ:392-393` — 「정밀도 가변 — 같은 연산기가 여러 데이터 형식을 처리한다. **명령이 정밀도를 지정하고, 데이터패스가 그에 따라 자릿수와 반올림을 바꾼다**」. 그리고 `02-fabric-alu.typ:450-451` — 「**프로그램 선택자는 명령의 논리 필드(연산·정밀도)이며 이미 형상 무관이다** (INV-T1)」. 이중수는 정확히 「정밀도 필드가 고르는 다른 step 프로그램」이다. 새 축을 여는 것이 아니라 **정본이 이미 판 축의 새 값**이다.

**`0x6` 을 고른 것이 손-핀 불변식을 살린다.** `fp_block._doc` 실측 원문은 「dtype 0x5 = f64/Lf-reserved illegal **everywhere**; **dtype > 0x7 illegal**」이고, 이 못은 「hand-pinned in tests, **generator-independent**」다. `0x8`/`0x9` 를 쓰는 것은 그 불변식의 명시적 완화이고 생성기 밖 테스트를 함께 움직여야 한다. **`0x6`·`0x7` 은 그 못 안쪽에 비어 있다** — 어느 fp 블록 행도 쓰지 않으므로 오늘 ROM 이 전부 거절하고, 특정 행의 `legal_dtypes` 에 더하는 것은 **restrictive-first 의 단조 완화** 그 자체다. ⇒ **손-핀 무변경 · 생성기 무변경 · `in_fp_block` 무변경 · ROM 재굽기 한 번.** opcode 축의 「dtype 8칸이 비었다」는 거짓이었고, 「`0x8` 을 쓴다」는 처분은 불필요한 대가였다.

**`FS_FMA × dual_f32` 는 malformation** 이고 판정은 **디코드 경계**다 — mode byte `dtype == 0x6` 과 `imm16[7:4] == 3` 이 둘 다 인코딩에 있으므로 순회 종료 직후에 선다. 근거: `0x74` desc 가 「**FS_FMA addend C = `payload_a[63:32]`**」로 못박은 자리가 정확히 접선 자리다. 두 계약이 같은 비트를 다투므로 「같은 비트가 어느 계약을 뜻했는지 알 수 없게 된다」(`01-isa-asm.typ:290-296`)의 정확한 사례다. **검사를 늘리는 대신 인코딩을 좁힌다** — legality 행에 한 줄. FMA 는 lowering 이 MUL+ADD 두 발화로 편다(의미 보존, `01-isa-asm.typ:1228-1245` lowering 계약 안). **`FS_DIV` 는 배제하지 않는다** — $(u/v)' = (u'v-uv')/v^2$ 는 한 발화 안에서 닫히고, Forward AD 축 설계안이 나눗셈을 언급조차 하지 않은 것은 결손이었다.

**수치 규약을 FSCALAR 수준으로 못박는다.**
- **곱셈 순서**: $t = \mathrm{RN}(\mathrm{RN}(u'\!\cdot\! v) + \mathrm{RN}(u\!\cdot\! v'))$ — `u'·v` 가 먼저. step 프로그램 문면도 이 순서로 적는다(원안이 §1.5 와 §4 에서 순서를 두 번 다르게 적은 자기모순을 여기서 닫는다). FAB-8 은 비트 일치를 재므로 순서는 계약이다.
- RNE-only · DAZ/FTZ · IEEE specials 는 언제나 DATA(`0x74` 승계).
- **접선 레인의 IEEE 예외는 `0x7E FP_STATUS` sticky 에 올라간다.** `u=+\infty, u'=0, v=1, v'=0` 이면 primal 은 멀쩡한데 접선이 invalid 를 올린다. 이 워드는 레인별이 아니고 atomic read-and-clear 이므로 **primal 만 쓰는 소비자가 접선의 예외로 오염된다.** 접선 레인만 억제하는 갈래는 비대칭 계약을 신설하므로 고르지 않는다 — **오염을 받고 적는다.** 이것이 이 축의 기재해야 할 대가다.
- **곱셈기는 늘지 않는다.** dual MUL 은 곱셈 3회지만 step 이 단일 공유 곱셈기를 3단계에 재사용한다 — `02-fabric-alu.typ:467` 「곱셈기는 하나다」 통과.

**레인 오독 표면은 새로 열리지 않는다.** dtype `0x6` 이 세 행에만 legal 이므로 다른 opcode 는 mode ROM 이 거절한다. 프로그램이 mode byte 를 거짓으로 적으면 오독되지만, 그것은 f16 파도를 bf16 로 읽는 것과 **같은 부류의 기존 표면**이다. 「오독 표면 여섯」도 「오독 표면 0」도 아니다 — **표면 수 불변**이 정확한 표현이다.

**진짜 대가 — 기본 형상 $P$.** dual-MUL · dual-DIV · dual-RSQRT · dual-EXP2 로 step 프로그램이 최대 넷 는다(ADD/SUB 가 레인 폭 재해석으로 되는지는 **재지 않았다**). `02-fabric-alu.typ:459-461` 이 「기본 형상은 $P$ = 전 상주(**10종**)로 두어도 좋다 — **그때 능력 부재 경로는 도달 불가한 채 계약으로만 존재한다**」고 적으므로, $P$=10 을 그대로 두면 **처음으로 그 경로가 도달 가능해진다.** ⇒ **$P$ 를 14 로 올린다.** `02-fabric-alu.typ:459` 의 「10종」이 개정 대상이고, 값은 RTL 측정과 함께 확정한다(§2.5.1 규범 그대로). 이것이 Forward AD 의 유일한 정본 개정이다.

**기각한 대안.** 신규 `FDI` opcode(이항 이중수 전용) — 같은 일을 하면서 opcode 를 먹고 **단항의 팬아웃 블로커를 못 닫는다.** 단항 전용 opcode 신설 — 「연산마다 opcode」로 미끄러진다. `dual_bf16` 초판 배정 — **소비자 0**(bf16 산술 팔이 없다; bf16 은 `0x77` 변환 종점과 `0x7A` 파도 dtype 으로만 존재). 접선을 조각열 2 로(문맥 풀 고갈 축 `b-gaps.typ:1079` 를 값마다 연다) · 접선을 메모리 경로로(§4.2.3 축을 먹고 출력 매체를 규범으로 함께 정해야 한다 — `b-gaps.typ:1059`) · `0x74` 의 `forbid_opref` 완화(ISA 노트가 alu-binary XOR 덫을 이유로 못박은 자리다).

## 1.4 Stencil / FDM — `FDMDi` (opcode `0x80`)

**한다.** 원시연산을 **순수 상관(correlation)** 하나로 좁힌다:

$$\text{out}[j] \;=\; \sum_{i=0}^{L-1} c[i]\cdot x[j+i], \qquad j = 0..T-1$$

중심도, 경계도, 반경도, 축 길이도 없다. 이 정의에는 그 개념들이 아예 등장하지 않는다.

| 항목 | 확정 |
|---|---|
| opcode | `0x80` — fp 블록 **밖**. `require_precision_eh: false` |
| 요소 폭 | **태그가 나른다** (§4.3 결속 키 = wave·에포크·LNID·**정밀도**·차원) — 명령이 다시 선언하지 않는다 |
| A (`x`) | 입력 파도, 최대 `FRAG_MAX` 조각 (`0x7A` 선례) |
| B (`c`) | `src_kind=1` OPREF → **결과 뱅크 구간**. 길이 `L` = 그 구간을 채운 조각열의 **선언 총개수** |
| 출력 | 조각열 `T` 개, ACCTGT 가 결속한 연속 구간. ISA-9 **③** |
| `T` 의 선언자 | **`ACCTGT[23:16]`** (아래 §4 개정 2) — 유일한 선언자, 재선언 없음 |
| EH 사슬 | `PORT` + `OPREF` + `ACCTGT` = **3슬롯 / 4워드**, 여유 1 |
| asm legality | required `[port, opref, acctgt]` · forbidden `[imm16, imm32, imm64, mem, subscript]` · `require_opb_flag: true` · `forbid_mem: true` |
| 사이클 상한 | **선언한다** — `T·L` 상한. 이 ISA 의 다중 사이클 MU-호스트 op 는 전부 상한을 진다(`0x70` int4 90 / int8 48 · `0x7A` ≤10,000) |
| busy-interlock | `0x70`/`0x7A` 와 같은 처분. 비행 중 dispatch 는 **loud** 거절 |

**경계 정책을 명령에서 없앤 것이 이 축의 핵심 결정이다.** Stencil 축 검증의 F1 은 실재했다 — CLAMP/WRAP/ZERO 를 **평탄 지수**에 적용하면 다축에서 전부 틀린 값을 낸다(8×8 타일 y-패스에서 8열 중 7열이 오답). 그 반례에 대한 수리는 두 갈래였고, 축 길이 `N` 을 인코딩에 넣는 갈래는 필드 넷(16b×4)을 요구해 3워드 신규 EH 를 낳는다. **고른 것은 다른 갈래다: 경계 조건은 기계의 것이 아니라 프로그램의 것이다.**

정본이 이미 그렇게 말한다 — §2.4 계약 6항(`02-fabric-alu.typ:308-313`)은 범위 밖 색인의 읽기를 「**비소유 관측**」으로 처분하지 패딩 의미론을 주지 않는다. Stencil 축이 「정본에 패딩 의미론이 없다」를 옳게 적발했고, 그 옳은 처분은 **패딩 의미론을 신설하는 것이 아니라 요구하지 않는 형태를 고르는 것**이다. 모든 선형 경계 조건(Dirichlet · Neumann · 주기)은 **halo 값의 선택**으로 표현되고, halo 를 실물로 만드는 것은 lowering 의 일이며 lowering 은 축 좌표를 안다. ⇒ **표현력 손실 0, 신규 계약 0, F1 의 반례 전부 소멸.**

같은 방식으로 **중심 오프셋도 없앤다** — 비대칭 커널은 계수 벡터에 0 을 넣어 표현되므로 인코딩 0 비트, 검사 0 건, 표현력 손실 0. `L` 의 홀짝 판정도 필요 없다. **반경 `r` 도 없다** — `L` 이 계수 구간의 선언 총개수로 온다.

⇒ **IMM16 이 필요 없어진다.** opcode 축이 제안한 16비트 제어 워드(커널 길이 6b + 중심 6b + 경계 4b)는 통째로 사라지고, 그와 함께 「경계 정책 몇 개인가」·「`c ≥ L` 의 처분」·「`L=0` 의 처분」·「범위 초과가 malformation 인가 능력 부재인가」 네 갈래가 **전부 물음 자체를 잃는다.** 「검사를 늘리는 대신 인코딩을 좁힌다」의 가장 강한 형태다.

**남는 대가는 정직하게 적는다.**
- **구간은 조각 단위 연속이다. stride 를 인코딩하지 않는다.** 비연속 축 패스는 `0x23 PERM` 으로 전치한 뒤 도는 형태이고, 축당 PERM 2회가 든다. rank 3 타일에서는 슬라이스당 한 발화 — `O(\text{타일 변})` 발화다. **「27점 3D 상자 = 발화 3」은 거짓이다.** 그 비용은 §2.3 아래 호스트 명령 큐에 그대로 실린다.
- **한 발화의 `x` 는 파도 하나에 든다** — `FRAG_MAX` 조각이 상한이고, 그 축은 `CAP_STATUS[0]`(재조립 슬롯)로 **이미 관측 가능**하다.
- **`T + L - 1 > N` 이면 조각열이 완성되지 않는다** — §4.3 규범 3항의 순번 누락, **loud fault**. 새 처분이 아니라 기존 기구다.
- 계수 구간을 채우는 것은 별도 발화 하나다(계수 파도 → ACCTGT 로 구간에 착지). 루프 불변이므로 한 번.

**`0x80` 을 고르고 `require_precision_eh` 를 false 로 둔 근거.** opcode 축의 검증이 실물로 보인 대로, `scripts/gen_isa_tables.py:240-248` 의 mode ROM 색인은 `((code & 0xF) << 8) | …` 로 **opcode 하위 니블뿐**이고 조회는 `in_fp_block = (cb_opcode[7:4] == 4'h7)` 로 게이트된다. `0x80` 에 mode byte 를 요구하면 `0x80 & 0xF = 0x0` 이 **`0x70 VFMA_ACC` 의 ROM 행에 얹히고**, `in_fp_block` 이 걸러 그 행은 RTL 에서 한 번도 조회되지 않는다 — 어셈블러는 엄격해지고 RTL 은 아무 mode byte 나 받는 **공허 PASS**다. 그리고 `0x6B` 식 손-못박기(`asm-stricter-than-RTL`)를 하나 더 낳는다. ⇒ **요구하지 않는다.** 요소 폭의 선언자를 태그 하나로 유지하는 것은 「재선언은 검산이며 불일치는 malformation」(§4.2.2 6항)을 부르지 않는 유일한 형태이기도 하다. 부수로 `0x80` 은 `truth_table_premigration.json` 도메인(`0x00`–`0x6F`) 밖이므로 **differential recapture 를 강제하지 않는다.**

**기각한 대안.** 신규 EH `0xA` STENCIL 3워드(계약 신설이 크고, 상관 정의 + 구간 읽기로 인코딩 0 에 도달한다) · 오프셋열 인코딩(27점에서 6슬롯/13워드, 비용 $\Theta(k\!\cdot\!D\!\cdot\!\log r)$) · SUBSCRIPT 재사용(라벨 코드지 수치 필드가 아니다) · MEM stride(§4.2.3 「메모리 접근은 명령당 하나」) · 메모리 출력(`01-isa-asm.typ:370-385` 함정) · `0x80`–`0x8F` 블록 예약(소비자 0) · `CAP_STATUS[2]` 신설(`b-gaps.typ:1129` — 「비트 수가 아니라 **순서**다. 열거를 먼저 세우고 폭을 확정한다」).

## 1.5 공통 기반 — 읽기측 구간 + 총개수 선언 자리

`FDMDi` 가 요구하고 나머지 셋이 함께 쓰는 것이 둘이다. 둘 다 **정본이 이미 반쯤 쓴 것의 완성**이다.

**(가) 읽기측 구간 의미론 — §2.4.1 의 대칭.** 정본은 쓰기측 구간을 확정했다: 「조각열 하나는 연속한 슬롯 구간을 차지하며, 조각의 순번이 그 구간 안의 자리를 정한다. 구간의 시작은 LBID 가 지목하고, **길이는 조각열이 나르는 선언 총개수다**」(`02-fabric-alu.typ:358-360`). **읽기측에 같은 문장이 없다.** 확정: `src_kind=1` OPREF 의 LBID 는 **구간 시작**이고 길이는 그 구간을 채운 조각열의 선언 총개수다. **폭의 선언자는 생산자 하나이고 소비자는 그것을 읽는다** — opcode 가 폭을 정하는 갈래는 선언자를 둘로 만들므로 기각한다. 그리고 **미완 구간 읽기는 loud fault** 다 — `b-gaps.typ:1050-1057` 이 이름한 「소비 게이트가 없으므로 「부분 결과가 전체로 오독될 수 없다」가 계약이 아니라 희망으로 선다」를 여기서 닫는다.

**(나) 조각열 선언 총개수의 선언 자리 = `ACCTGT[23:16]`.** `b-gaps.typ:1037-1048` 이 「**유일한 정합 후보**」로 이름한 자리다 — 「그 자리가 태그→구간 결속의 원천과 같은 EH 이고 「같은 사슬에 두 번이면 malformation」이 선언 유일성을 겸한다」. **`Di` 가 그 행의 첫 소비자다.** 오늘 `01-isa-asm.typ:1007` 은 그 8비트를 「예약, 반드시 0」으로 적으므로 **§1.4.7 개정**이 필요하다. 대가는 0 이다 — ACCTGT 는 오늘 `eh_codes` 에 없어 소비자가 0 이고, **예약을 활성 필드로 승격하는 것은 §5.7 이 이름한 덫을 하나 없애는 것**이다. 값 공간 `1..255` 는 인스턴스 개수와 무관하므로 INV-T1 통과이고, 이것이 `e-defined.typ:1415-1421` 이 RTL 로 미룬 조각 머리 폭 상수 `W` 의 **첫 소비자**다 — **`W ≥ 8` 을 요구한다.** 소비자가 생긴 뒤 폭을 정하는 것이 그 항이 요구한 순서다.

# 2. 축 사이 모순 해소

## 2.1 「상수를 명령에 어떻게 싣는가」 — 넷이 한 답을 낸다

과업이 지목한 대로 문턱 집합 · 분할 폭 · 스텐실 계수 · AD seed 는 **같은 부류의 문제**다. 원안 넷은 서로 다른 답을 냈다(뱅크 · 데이터 · 미결 · 페이로드). 하나로 접는다.

> **규약 — 상수는 데이터다. 명령은 상수를 나르지 않는다.**
> 네 상수 족은 전부 **파도 페이로드 또는 결과 뱅크 구간**에 살고 LBID 로 주소된다. 즉치에도, MMIO 구성에도, mode byte 에도 두지 않는다. 인코딩이 나르는 것은 **구조 선택자**뿐이다 — 서브옵 니블, dtype 코드점, 출력 총개수 — 셋 다 형상 무관한 작은 열거다.

| 상수 | 거처 | 명령이 나르는 것 |
|---|---|---|
| 르베그 문턱 $t_k$ | 뱅크 슬롯 (OPREF-B) | 없음 — $K$ 는 lowering 이 편다 |
| 리만 가중치 $w_i$ | 파도 페이로드 (A‖B) | 없음 — $N$ 은 lowering 이 편다 |
| 스텐실 계수 $c_i$ | 뱅크 **구간** (OPREF-B) | 없음 — $L$ 은 구간의 선언 총개수 |
| AD seed (접선 초기값) | 페이로드 `[63:32]` | 없음 — dtype `0x6` 이 해석만 정한다 |

**세 가지가 이 규약에서 따라 나온다.** ① INV-T1/T2 축이 네 축 모두에서 열리지 않는다 — 상수의 **개수**가 어느 인코딩에도 없다. ② §2.3(가변 반복 불가)이 자동으로 만족된다 — 반복 수가 인코딩 상수이거나 lowering 이 정적으로 편 발화 수다. ③ 상수를 바꾸는 데 재컴파일이 필요 없다 — 뱅크 값만 바뀐다.

**대가도 하나로 접힌다:** 상수가 데이터이므로 **재전달 비용**을 진다. 르베그는 `x` 를 $K$ 번 재전달하고, 스텐실은 계수 구간을 한 번 채우며, 리만은 가중치를 파도마다 싣는다. **셋 다 재지 않았다 — 방향만 안다.** 이것이 이 규약의 유일한 미측정 대가이고, 넷이 같은 대가를 지므로 한 번 재면 전부 안다.

## 2.2 opcode·EH 자리가 넷의 요구를 동시에 만족하는가 — 만족한다

| 축 | opcode | EH 슬롯 | 워드 | 신규 EH | 신규 계약 |
|---|---|---|---|---|---|
| 리만 | `0x7A` (기존) | 2 | 3 | 0 | 0 |
| Forward AD | `0x74`/`0x75`/`0x76` (기존) | 2–3 | 3–4 | 0 | 0 |
| 르베그 | **`0x7B`** (신규, fp 블록 안) | 3 | 4 | 0 | 0 |
| Stencil | **`0x80`** (신규, 블록 밖) | 3 | 4 | 0 | 2 (공통 기반) |

- **EH 슬롯 최댓값 3 < 4** ⇒ EH 사슬 길이 능력 부재를 밟지 않는다.
- **워드 최댓값 4 ≪ 13** ⇒ 워드 상한을 밟지 않는다.
- **신규 EH 0** ⇒ `0xA`–`0xE` 다섯 칸이 그대로 남는다. §4.2.3 「전수」 반복 규칙 표에 행을 더할 필요가 없다.
- **fp 블록 잔여**: `0x7F` 한 칸(손대지 않는다). **블록 밖 잔여**: `0x81`–`0xFF`.
- **`0x6` 을 쓴 뒤 dtype 잔여**: `0x7` 한 칸(손-핀 안쪽).

두 신설 opcode 는 **서로 다른 게이트를 탄다** — `0x7B` 는 `in_fp_block` 안이라 mode ROM 이 dtype 을 집행하고, `0x80` 은 밖이라 태그가 정밀도를 진다. 겹치지 않으므로 `gen_isa_tables.py` 의 별칭 함정을 열지 않는다.

## 2.3 원안 다섯이 서로 어긋난 자리 — 처분

| 어긋남 | 처분 |
|---|---|
| 르베그·Stencil 이 「`CAP_STATUS` 결손의 첫 소비자」를 각각 주장 | **둘 다 철회.** 전 축 3슬롯이라 그 축을 밟지 않는다. 그 결손은 `b-gaps.typ:1109-1132` 에 **이미 등재**돼 있고 `Di` 는 첫 소비자가 아니다 |
| 르베그가 ACCTGT 를 필수로, Stencil 도 필수로 적음 | **출력 형태가 가른다** — 단일 beat(르베그)는 불요, 조각열(Stencil)은 필수. §4.3 결속 1항의 전건 그대로 |
| opcode 축이 dtype `0x8`, Forward AD 축이 dtype 니블 포화 주장 | **둘 다 틀렸다.** `0x6`·`0x7` 이 손-핀 안쪽에 비어 있다 |
| 리만·르베그가 부동소수 접기 순서를 다르게 처리 | **르베그는 정수라 문제가 없고, 리만은 `0x7A` 의 값 계약이 순서를 값에서 지운다.** ⇒ `Di` 는 부동소수 접기 순서를 **한 번도 만들지 않는다.** §2.5 결정론이 계약 증가 0 으로 성립한다 |
| Stencil 이 경계를 기계에, lowering 축이 halo 를 프로그램에 | **프로그램으로 확정** (§1.4) |
| opcode 축의 「`0x71`/`0x7A` 가 이미 가중 내적」 | `0x71` 은 정수 전용, `0x7A` 는 32항 고정. **리만의 f32 부재는 `Di` 의 결손이 아니라 ISA 의 결손**이고 별건 B.5 등재 |

| 단계 | 내용 | 비용 | 선행 |
|---|---|---|---|
| **0** | **리만** — lowering 규약 넷(격자=데이터 · 이진분수 적용 범위 · A·B 양측 패딩 · 호스트 접기)을 문서화 | **0** — 인코딩·정본 무변경 | 없음 |

# 6. 남은 미결 — 사용자만 답할 수 있는 것

설계자가 고를 수 있는 것은 전부 §1 에서 골랐다. 아래 넷은 고를 수 없다.

1. **`Di` 가 `WT64v1-C` 인가 `v2.x` 인가.**
   *갈리는 것*: `T_stable` 재정의에 걸린 릴리스 축이며, 이 결정이 신규 opcode 둘의 동결 시점을 정한다.

2. **리만의 정의역을 f16/bf16 32항으로 좁히는 것을 받는가.**
   *갈리는 것*: f32 리만을 지금 사려면 「부동소수 벡터 축약 경로 부재」(B.5 신규 1)를 함께 사야 하고, 그것은 신규 opcode 최소 하나 + step 프로그램 + 결합 순서 값 계약을 요구한다 — `Di` 보다 큰 결정이다.

3. **「Stencil/FDM 을 명령어셋 레벨 직접 지원」이 경계 처리까지 뜻하는가.**
   *갈리는 것*: 이 설계는 상관 원시연산만 ISA 로 올리고 경계 조건을 lowering 의 halo 로 밀었다. 그것이 지시의 이행인지 축소인지는 지시자만 답한다.

4. **니모닉이 수학 이름인가 연산 이름인가** — `LEBESGUEDi`/`RIEMANNDi` 인가 `SUPMEASDi`/`FDOT32_CR` 인가.
   *갈리는 것*: `Di` 접미사는 사용자 지시이고, 이 설계는 명령이 하는 일(초과 측도 한 겹 · 상관 한 번)이 적분 그 자체가 아니라는 이유로 연산 이름을 골랐다. 어셈블러 표면의 이름은 사용자 것이다.

**미결로 올리지 않은 것**(설계자가 골랐으므로): 문턱 집합의 공급자(뱅크 상주) · 분할 폭의 거처(데이터) · 스텐실 계수의 상주(뱅크 구간) · 접선 저장 자리(페이로드 `[63:32]`) · 경계 정책 개수(0 — 인코딩에서 제거) · `CAP_STATUS` 비트 배정(안 한다) · 능력 부재 판정 시점(⑴).

# 7. 밟지 말아야 할 것 — 기각 전수

다음 사람이 같은 것을 다시 제안하지 않도록, 기각한 것과 **왜** 기각했는지를 전부 적는다.

**르베그**
- 히스토그램 · scatter · 정렬 — 데이터 의존 주소 기입. 결과 슬롯 착지는 조각열의 **순번**이 정하지 값이 정하지 않는다(`02:358-360`).
- 문턱 개수 $K$ 를 인코딩에 싣기 — INV-T1/T2.
- 문턱을 MMIO 구성에 두기 — 발화 사이 상태가 생기고 §2.3·상수 시간성 축을 다시 열어야 한다.
- 문턱을 mode byte 에 싣기 — f32 문턱 32비트가 4비트 코드점에 안 들어간다. (「dtype 여유가 0」이라는 이전 근거는 **거짓**이었다 — `acc`·`rnd` 는 4값 중 1값만 합법이라 여유가 상당하다.)
- 측도를 fp 로 내기 — 결합 순서가 값에 보이고, **접을 수단이 이 ISA 에 없다**.
- ACCTGT 를 단일 beat 결과에 강제 — §4.3 결속 1항의 전건이 서지 않는다. 이것이 5슬롯의 원인이었다.
- 마스크 생산 + 기존 `0x54 POPCNT` 2발화 — 4비트 마스크가 64비트 워드의 60비트를 데이터 층의 덫으로 남긴다(§5.7 은 인코딩만 덮는다). 발화 2배, 중간 결과 슬롯 하나 추가.

**리만**
- EINSUM 기반 — 결합 순서에 대한 값 계약이 없다. (「EH 예산 때문에 능력 부재」라는 이전 근거는 **거짓**이었다 — 실측 3–4슬롯.)
- FSCALAR 부분합 트리 — payload_b 는 같은 파도의 확장 페이로드이지 별개 생산자 경로가 아니고, PORT 본문에 A/B 선택자가 없다(`01:277-283`).
- 비균등 격자에서 §2.2 가중치 규약을 적용 — 개선 1.00×(실측). 규약이 사지 못한다.
- B 만 canonical zero 로 패딩 — A 의 Inf/NaN 이 전체를 qNaN 으로 만든다(실측).

**Forward AD**
- 신규 `FDI` opcode(이항 이중수 전용) — 같은 일을 하면서 opcode 를 먹고 **단항의 팬아웃 블로커를 못 닫는다.**
- 단항마다 opcode — 「연산마다 opcode」로 미끄러진다.
- dtype `0x8`/`0x9` — 「dtype > 0x7 illegal」 손-핀 불변식(생성기 밖 테스트)의 완화를 부른다. `0x6` 이 못 안쪽에 비어 있다.
- `dual_bf16` 초판 배정 — **소비자 0.**
- `FS_FMA × dual` — addend C 가 `payload_a[63:32]`, 접선 자리와 다툰다.
- `0x74` 의 `forbid_opref` 완화 — ISA 노트가 alu-binary XOR 덫을 이유로 못박은 자리다.
- 접선을 조각열 2 로 — 문맥 풀 고갈 축(`b-gaps.typ:1079`)을 값마다 연다.
- 접선을 메모리 경로로 — §4.2.3 축을 먹고 출력 매체를 규범으로 함께 정해야 한다(`b-gaps.typ:1059`).
- $P$=10 을 그대로 두고 step 을 늘리기 — 「도달 불가한 채 계약으로만 존재」하던 능력 부재 경로가 조용히 도달 가능해진다.

**Stencil**
- 신규 EH `0xA` (3워드) — 상관 정의 + 구간 읽기로 인코딩 0 에 도달한다. 계약을 늘리지 않고 되는 것을 계약으로 푸는 나쁜 거래.
- 경계 정책을 인코딩·기계 의미론으로 — **평탄 지수 포화·mod 는 축 좌표 경계 조건이 아니다.** 8×8 타일 y-패스에서 8열 중 7열이 오답(실측 반례). halo 로 표현하면 표현력 손실 0.
- 중심 오프셋 `c` 필드 — 계수 벡터의 0 패딩으로 표현된다. 인코딩 0, 검사 0.
- 반경 `r` 필드 — 계수 구간의 선언 총개수가 `L` 을 준다.
- `pitch = 0` 인코딩 — `sum(cᵢ)·x` 는 스칼라 곱이 이미 한다. 소비자 0.
- 오프셋열 · SUBSCRIPT 재사용 · OPREF 다중 · MEM stride · 메모리 출력 — 원안 기각 그대로 유효.
- `require_precision_eh: true` 를 블록 밖 opcode 에 — ROM 별칭 + `in_fp_block` 이 만드는 **공허 PASS**(`gen:240-248`).
- fp mode 가드를 「`require_precision_eh` 인 모든 opcode」로 일반화 — 같은 이유. **부채를 갚는 것이 아니라 별칭을 연다.**
- `0x80`–`0x8F` 블록 예약 · `0x7F` 사용 — 소비자 0 인 자리에 인코딩 짓기.
- `CAP_STATUS[2]` 신설 — `b-gaps.typ:1129` 가 「비트 수가 아니라 **순서**」를 요구한다.

**공통**
- OPREF 읽기 폭을 opcode 가 정하기 — 폭의 선언자를 둘로 만든다. 구간 읽기에서 **선언자는 생산자 하나**다.
- ACCTGT `[23:16]` 을 예약-0 으로 확정 — `b-gaps.typ:1037` 이 **「유일한 정합 후보」**로 이름한 자리다. 봉인하면 조각열을 내는 모든 확장이 자기 출력 형태를 선언할 자리를 잃는다.
- 이미 B.5 에 등재된 항(`CAP_STATUS` 축 · 출력 매체 · 미완 구간 · 선언 자리 · 판정 시점)을 「신규 적발」로 다시 올리기 — 다섯 축 중 넷이 각각 한 번씩 했다. **`Di` 가 할 수 있는 것은 그 행에 첫 소비자를 붙이거나 그 행을 닫는 것뿐이다.**

---

**총평.** 확정안의 형태는 원안 다섯보다 **작다.** 신규 opcode 2(원안 합계 3–4), 신규 EH 0(원안 1), 신규 dtype 1(원안 2), 신규 능력 부재 사건 0(원안 2), 신규 `CAP_STATUS` 비트 0(원안 1–2), 최대 EH 사슬 3슬롯(원안 5–6). 줄어든 자리마다 근거가 하나씩 있고 — 상관 정의가 경계 셋을, 계수 벡터의 0 패딩이 중심 필드를, 구간의 선언 총개수가 커널 길이 필드를, dtype `0x6` 이 신규 opcode 와 손-핀 완화를, 정수 측도가 fp 접기 경로를, 단일 beat 판정이 ACCTGT 두 슬롯을 각각 없앴다 — 그 여섯이 이 회의에서 실제로 한 일이다. 남은 대가 중 재지 않은 것은 **셋뿐**이고 전부 「방향만 안다」로 적었다: 상수 재전달 비용, 르베그의 새 비교 전처리 면적, dual step 프로그램 종수.
