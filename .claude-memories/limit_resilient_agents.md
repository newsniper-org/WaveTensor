워크플로 에이전트 지시문에 늘 넣는다: (1) 모든 sby · TLC · rtl-sim · 변이 배치는 짧아도 `nohup … > log 2>&1 &` — 전경 컨테이너 금지, (2) 역할 디렉터리의 `progress.md` 를 단계마다 갱신(띄운 실행 · 로그 · 결과 · 남은 일), 재개한 에이전트는 그것부터 읽고 끝난 실행은 다시 돌리지 않는다, (3) 기계적 단계는 `effort: 'low'` 고려(반증 · 검토는 유지).

**Why:** 2026-10-12~13 주간 한도로 에이전트가 넷씩 죽기를 반복했고, 전경으로 돌린 컨테이너가 고아로 남았으며(w3hi-masm 등), 재개 때마다 같은 조사를 다시 했다. 사용자: 「한도 소진에 걸리더라도 이미 하고있던 작업들까지는 멈추지 말고 끝까지 진행하도록 할 방법이 있나?」 → 「그렇게 해.」

**How to apply:** 브리프의 규율 절에 위 두 줄을 넣는다. 재개 전에 `podman ps` 로 고아 컨테이너를 정리한다(아직 결과를 쓰는 nohup 실행은 남겨 둔다). 한도 자체는 막을 수 없다 — extra usage/자동 충전은 사용자가 설정한다. [[background-task-oom-kill]] 과 같은 nohup 원칙.
